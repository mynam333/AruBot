# 로컬 짚톡

## 처음 설정

1. OBS의 WebSocket 서버를 켜고, 로컬 프로그램의 OBS 연결 화면에 주소와 비밀번호를 저장합니다.
2. 로컬 프로그램의 **짚톡**에서 **소스 새로고침**을 누르고 사용할 마이크 소스를 선택합니다.
3. 입 다묾·입 열림 이미지를 가져옵니다. 음소거 이미지는 선택 사항이며, 없으면 입 다묾 이미지가 표시됩니다.
4. **짚톡 사용**을 켜고 설정을 저장합니다. 현재 마이크 음량과 출력 미리보기를 확인합니다.
5. **주소 복사**로 얻은 URL을 같은 PC의 OBS 브라우저 소스에 넣습니다. 배경은 투명하며 브라우저 소스 크기에 맞춰 표시됩니다.

기본 화면 맞춤은 이미지 전체가 보이는 **전체 표시**입니다. **화면 채움**은 비율을 유지하면서 넘치는 부분을 자르고, **좌우 반전**은 이미지 방향을 뒤집습니다.

## 음량 반응

- 입 열림 기준: 기본 -38 dB. 잡음에 반응하면 값을 높이고, 작은 목소리를 놓치면 낮춥니다.
- 입 닫힘 여유: 기본 6 dB. 기준 근처에서 이미지가 빠르게 번갈아 나타나는 현상을 줄입니다.
- 입 열림 유지: 기본 160 ms. 음량이 닫힘 기준 아래로 내려간 뒤 기다리는 시간입니다.
- OBS 연결 또는 음량 신호가 끊기면 입 다묾으로 돌아가며 연결을 계속 재시도합니다.
- OBS에서 소스를 음소거하면 음소거 이미지가 우선합니다. 운영체제나 마이크의 물리적 스위치 상태는 OBS가 알려주는 범위에서만 반영됩니다.

## 포인트·후원 반응

**반응 추가**로 이름, ID, 이미지, 기본 표시 시간을 저장한 뒤 테스트할 수 있습니다. **변수 복사**로 얻은 값을 기존 명령어 또는 후원 반응 내용에 넣습니다.

```text
${pngtuber::happy::5}
${pngtuber::happy}
```

첫 번째는 5초 표시, 두 번째는 저장된 기본 시간을 사용합니다. 표시 시간은 0.1~300초입니다. 명령어의 포인트 비용과 후원 조건은 기존 관리 페이지에서 설정합니다. 별도 짚톡 비용은 차감하지 않습니다.

커스텀 이미지는 마이크 반응보다 우선하며, 종료 후 현재 마이크 상태로 복귀합니다. 여러 요청은 **순서대로 재생**하거나 **즉시 교체**할 수 있습니다. 반응은 최대 32개, 대기 요청은 최대 20개입니다. 클라우드 요청은 온라인 로컬 프로그램이 필요하며, 60초 내 전달되지 않으면 실행하지 않습니다.

## 저장과 보호

- 이미지와 설정은 로컬 프로그램의 사용자 데이터 폴더 아래 `pngtuber`에 저장합니다. 마이크 음성은 녹음하거나 서버로 전송하지 않습니다.
- PNG, GIF, WebP, JPEG를 지원합니다. 이미지별 20 MiB, 전체 디코딩 픽셀 1,600만, 애니메이션 240프레임 이하입니다. 가져온 원본 바이트를 유지하므로 투명도와 지원되는 애니메이션이 보존됩니다.
- 출력 서버는 `127.0.0.1`에만 열리며, 주소의 비밀 키가 필요한 읽기 전용 서버입니다. 주소를 다른 사람에게 공개하지 마세요.
- 기본 포트는 17842입니다. 포트를 변경하면 OBS의 브라우저 소스 주소도 갱신해야 합니다.
- 앱과 OBS를 다시 켜면 저장한 설정으로 복구합니다. 마이크 반응은 클라우드 로그인 없이도 동작합니다.

## 개발 검증

`npm run test:pngtuber`는 엔진, 파일 저장, OBS 메시지, 로컬 출력 서버, Electron IPC 연결을 검사합니다. `npm run test:pngtuber:ui`는 실제 브라우저에서 설정 화면을 검사합니다. 자동 테스트와 모의 OBS 검증은 실제 마이크·OBS 및 배포 서버에서의 후원 실행을 대신하지 않습니다.

OBS 연동 규격: [obs-websocket 공식 프로토콜](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md).
