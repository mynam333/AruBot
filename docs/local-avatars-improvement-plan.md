# 방송 아바타 비판 검토 및 개선 기획

작성일: 2026-10-11 KST · 검토 기준: `f2dab8f` 및 현재 작업 트리

상태: **아래 검토를 기준으로 A~F 구현을 반영했다. 변경 내용과 검증 범위는 [v3 적용 기록](local-avatars-v3.md)을 따른다. 이 문서의 성능 목표와 실방송 수용 시나리오는 자동으로 달성된 것으로 간주하지 않는다.**

## 1. 결론

현재 기능은 이미지 등록, 치지직 이벤트 반응, 로컬 물리 연산, OBS 출력, 독립 테스트와 백업까지 연결된 초기 제품이다. 다음 개발의 우선순위는 동작 개수 확대보다 **편집 내용 보존, 테스트의 신뢰성, 예측 가능한 시간·중단 규칙, 방송 중 장애 복구**다.

출력과 테스트가 분리되어 있고, 임의 스크립트를 실행하지 않으며, 설정과 이미지가 로컬에 저장되는 구조는 유지할 가치가 있다. 반면 '테스트에서 보였으니 방송에서도 된다', '시간을 입력했으니 그 시간만큼 움직인다', '백업은 현재 편집에 영향을 주지 않는다'라는 자연스러운 기대는 아직 모든 경우에 충족되지 않는다.

완성도를 기능 수나 주관적 점수로 평가하지 않는다. 아래의 결함 해소, 작업 성공률, 장애 복구, 실제 방송 검증으로 판단한다. Stream Avatars 최신판과의 우열은 이번 검토에서 조사하지 않았으며, 기존 문서의 경쟁 제품 설명을 우월성의 근거로 재사용하지 않는다.

### 검토 범위와 증거 수준

- 로컬 편집 화면, 아바타 엔진, 이미지·백업 저장소, 오버레이, 서버 이벤트 중계, Electron IPC, 릴리스 설정을 읽었다.
- '재현'은 실제 엔진/정규화 함수를 메모리에서 호출해 결과를 확인한 항목이다. 운영 계정이나 저장 파일은 변경하지 않았다.
- '코드 확인'은 실행 경로를 확인했지만 이번 검토에서 실제 Electron/OBS로 다시 재현하지 않은 항목이다.
- '추가 측정'은 부하나 사용자 관찰이 있어야 발생 정도를 판단할 수 있는 위험이다.
- 이전 자동 검사나 브라우저 미리보기 결과를 실제 OBS·치지직 생방송 검증 완료로 간주하지 않는다.

### 유지할 점

- Matter.js와 단일 로컬 엔진이 이동 상태를 결정하는 구조. OBS마다 게임 판정을 따로 만들지 않는다.
- 방송과 편집 테스트의 물리 세계 분리. 실전 리허설도 실제 OBS에 노출하지 않는다.
- 채팅 원문을 HTML로 삽입하지 않는 출력, 루프백 바인딩, 출력 키, 로컬 IPC 제어, 임의 스크립트 금지.
- 이미지 원본 로컬 복사, 파일 해시, 백업 무결성 검사, 기존 정상 설정 복구.
- 달리기·부양의 시간 생략 시 기본 5초. 사용자가 기본 시간을 변경하면 변경값을 사용한다.
- 기본 무료 캐릭터 팩 및 동봉된 출처·라이선스. 새 자체 제작 캐릭터로 대체하지 않는다.

## 3. 제품 동작 원칙

1. **저장, 방송 적용, 테스트 실행은 서로 다른 행위다.** 한 행위가 다른 상태를 암묵적으로 지우지 않는다.
2. **입력한 시간의 의미를 예측할 수 있어야 한다.** '전체 시간'은 실제 전체일 때만 사용한다.
3. **반응이 실행되지 않았으면 원인을 확인할 수 있어야 한다.** 모든 거부를 채팅으로 답하지는 않는다.
4. **방송을 방해하지 않는 실패를 우선한다.** 잘못된 편집, 백업 실패, 새 포트 충돌이 기존 출력까지 중단하지 않는다.
5. **자유도는 관리 가능한 범위로 늘린다.** 임의 코드, 무제한 반복, 무제한 자원 소비를 허용하지 않는다.
6. **시청자는 자신의 참여를 중단할 수 있어야 한다.** 상호작용과 과밀 상황에서도 이를 보장하는 별도 처리 예산을 둔다.
7. **연출은 로컬, 수신은 중계 의존이다.** 인터넷 없이 이미지 편집과 합성 테스트는 가능하지만 새 치지직 채팅 수신까지 가능한 것은 아니다.

## 4. 편집·저장·테스트 상세 설계

### 4.1 편집 내용 보존

`savedConfig`, `draftConfig`, `liveRevision`을 구분한다. 원자적 저장 성공 응답 전에는 미저장 표시를 지우지 않는다. 저장 실패 시 편집을 그대로 유지하며 재시도할 수 있어야 한다.

| 작업 | 요구 동작 |
| --- | --- |
| 저장된 내용 백업 | 저장 버전만 내보낸다. `draftConfig`, 선택 항목, 미저장 표시, 미리보기는 유지한다. |
| 편집 내용까지 백업 | '저장 후 백업'을 별도 선택한다. 저장 실패 시 백업은 시작하지 않는다. |
| 복원 | 파일 검증과 교체 내용 요약 후 확인한다. 현재 편집 보존/취소를 선택할 수 있게 한다. |
| 방송 시작 | 미저장 변경이 있으면 '저장된 설정으로 시작'과 '저장 후 시작'을 선택한다. |
| 규칙 변경 저장 | 실행 중 시퀀스는 시작 당시 설정으로 마무리한다. 새 입력부터 새 버전 사용. |
| 앱 종료/재로딩 | 미저장 설정을 버릴 때 확인한다. 자동 복구 초안은 별도 파일에만 보관하며 방송 자동 적용은 금지한다. |

편집 기록은 최근 50회 또는 2MiB 중 먼저 도달한 범위에서 실행 취소/다시 실행을 제공한다. 이미지 원본을 기록에 복제하지 않고 해시 참조만 보관한다. 초안과 실행 취소 기록이 참조하는 파일은 정리 대상에서 제외한다. 캐릭터 삭제·규칙 복제·순서 이동은 각각 한 번의 실행 취소로 되돌린다.

**완료 기준:** 미저장 캐릭터 이름을 수정하고 백업을 내보낸 뒤에도 수정값과 미저장 표시가 남는다. 디스크 쓰기 실패를 주입해도 이전 방송과 초안이 유지된다.

### 4.2 두 종류의 테스트

| 구분 | 동작 미리보기 | 채팅 리허설 |
| --- | --- | --- |
| 목적 | 이미지·움직임·수치 조정 | 실제 입력 조건과 실행 결과 확인 |
| 설정 | 편집 중 설정 | 저장 설정 또는 편집 설정을 명시적으로 선택 |
| 권한·후원 조건 | 우회 사실을 표시하고 선택 반응을 직접 실행 | 지정한 테스트 사용자 정보 그대로 검사 |
| 입장 | 선택 캐릭터 강제 생성 가능 | 자동 입장/명령 입장/정원/차단 규칙 준수 |
| 쿨다운 | 해당 캐릭터의 이전 동작과 쿨다운 초기화 가능 | 반복 입력 사이에 유지 |
| 대상 | 테스트 대상 드롭다운으로 지정 | 실제 명령 파서로 지정하며 동명이인 상황도 재현 |
| 시간·난수 | 고정 시드와 가상 시간 선택 가능 | 같은 시드로 같은 입력 순서 재생 가능 |
| 출력·저장 | 별도 테스트 화면, 실제 시청자 기록 저장 안 함 | 동일 |

테스트 결과는 '입력 수신 → 규칙 일치 → 권한·대상·쿨다운 검사 → 실행/거부'를 한 줄로 요약하고, 자세한 조건은 펼쳐 본다. 예: `실행 안 됨 · 재사용 대기 2.1초`.

테스트 닉네임은 표시값이고 테스트 사용자 ID는 별도 고정값으로 둔다. 같은 닉네임의 두 사용자를 만들고 특정 대상을 지정할 수 있어야 한다. '선택 반응 테스트'에도 대상 선택과 표시할 말풍선 입력을 제공한다.

**완료 기준:** 운영자 전용 반응은 일반 사용자 리허설에서 거부되고 운영자 리허설에서는 실행된다. 실전 모드에서 연속 명령이 쿨다운에 막히며, 빠른 미리보기에서는 수정 직후 즉시 재실행된다. 두 결과 모두 실제 OBS·프로필에 영향을 주지 않는다.

### 4.3 편집 화면 구조

웹사이트는 변경하지 않는다. 기존 로컬 탭을 유지하되 미리보기·설정 편집·운영 상태의 경계를 분명히 한다.

- 상단: 현재 방송 설정 버전, 실행/정지, 이벤트 연결, 출력 연결 수, 미저장 변경 수.
- 미리보기: '방송 크기'와 '확대 보기' 전환, 선택 캐릭터 추적, 안전 영역 표시. 검사 표시는 OBS 출력에 포함하지 않는다.
- 캐릭터: 검색, 복제, 이미지 재사용, 상태별 미리보기, 없는 상태의 대체 이미지 표시.
- 반응: 검색, 활성 여부·트리거 필터, 복제, 위/아래 이동, 명령 별칭 충돌 표시.
- 테스트: 빠른 미리보기 버튼과 리허설 입력을 구분하고 편집 후 실행 시 자동 스크롤로 입력 맥락을 잃지 않게 한다.
- 참여자: 검색·정렬, 1.5초 전체 DOM 교체 대신 변경 행 갱신. 클릭 중 버튼 위치와 키보드 포커스를 유지한다.
- 숫자 오류는 해당 필드에 표시한다. 저장 단계에서 조용히 다른 값으로 바뀌는 것은 줄이고, 보정이 필요하면 보정값을 보여준다.

도움말 문단을 기본 화면에 길게 배치하지 않는다. 버튼 이름, 필드 단위, 상태 배지와 필요한 툴팁으로 의미를 전달한다. 키보드 접근, 명확한 포커스, 980px 폭과 125% 배율에서 겹침 없는 화면을 수용 기준으로 둔다.

## 5. 동작·시간·대상 규칙

### 5.1 시간은 동작별로 정의한다

신규 기본 반응에서 달리기와 부양은 `기본 시간 5초`, `채팅 시간 허용`, `허용 범위 0.1~120초`다. 명령에 숫자가 없으면 기본값을 사용한다. `5`, `5초`, `5s`를 지원하고, 인자가 있으나 형식이 틀린 경우는 기본값으로 몰래 실행하지 않고 거부 이유를 남긴다. 허용 범위 밖 숫자는 일관되게 제한하고 실제 적용값을 진단 기록에 남긴다.

| 동작 | 시간의 의미와 추가 설정 |
| --- | --- |
| 달리기/걷기/춤/인사/앉기 | 동작 유지 시간. 시작·정지 전환 시간은 그 안에 포함. |
| 부양 | 상승+체류+하강 전체 시간. 기본 상승/하강은 각각 25%, 최대 1.2초로 현재 계약 유지. 고급 설정은 세 구간의 합이 전체와 일치해야 함. |
| 점프 | 높이/강도와 '착지 후 다음 단계'가 핵심. 초 수로 체공을 약속하지 않는다. 별도 '착지 후 대기' 제공. |
| 모이기/따라가기/접촉 | 최대 접근 시간. 도착 또는 접촉하면 성공, 대상 이탈·시간 초과면 지정한 실패 정책 실행. |
| 말풍선 | 표시 시간. 기본적으로 이동을 중단하지 않음. |
| 크기 | '임시 효과'는 유지 시간 후 기존값 복원. '기본 크기 변경'은 저장되는 선택값으로 표시. |
| 대기 | 다음 단계까지 기다리는 시간. '제자리 대기'와 '현재 동작 유지'를 구분. |

채팅 인자는 선택한 한 단계의 `duration`에 연결하는 것을 신규 기본 정책으로 한다. 여러 단계 전체 길이를 조절하는 고급 옵션은 각 단계 비율을 유지하되 최소 시간·점프 착지 조건이 불가능하면 저장하지 못하게 한다. 전체 반응 권장 상한은 120초이며 상한 값은 베타에서 검토한다.

**호환성:** 현재 v2의 `durationFromChat=true`는 모든 단계에 적용된다. 이를 자동으로 한 단계 적용으로 바꾸면 기존 사용자의 연출이 달라진다. v3 전환 시 `legacyAllSteps`로 보존하고 편집기에서 총 길이와 전환 선택을 표시한다. 기존 영구 크기 변경도 임시 효과로 몰래 바꾸지 않는다.

**완료 기준:** '달리기 5초 → 말풍선 2초' 반응에서 달리기 단계만 인자에 연결했다면, `!명령 10`은 10초+2초다. 숫자 생략 시 5초+2초이고, 문서·미리보기·실전이 같다.

### 5.2 충돌과 취소

임의 스크립트 대신 세 종류의 제한된 실행 영역을 둔다: 이동, 포즈, 말풍선/표시 효과. 모든 동작을 병렬 실행하는 범용 편집기는 만들지 않는다. 동일 영역은 한 동작만 소유하고, 이동 중 허용되는 포즈 조합은 정의된 목록으로 제한한다.

| 상황 | 신규 기본 정책 |
| --- | --- |
| 퇴장·차단·방송 중지 | 모든 동작 취소와 대상 참조 해제. |
| 게임 진행 | 게임이 이동 제어권을 보유. 허용된 응원/점프 외 일반 이동은 거부 이유 기록. |
| 본인의 새 이동 명령 | 이전 일반 이동 교체. 부양 중이면 현재 위치에서 전환하고 순간 지면 이동 금지. |
| 모든 채팅에 대한 꾸밈 반응 | 낮은 우선순위. 명시적 이동 명령을 취소하지 않음. |
| 후원·구독 반응 | 규칙별 '현재 동작 후 실행/즉시 교체/겹쳐 표시' 중 허용 가능한 방식 선택. |
| 대상 접촉 | 접근 중에도 대상 위치 갱신. 대상 퇴장 시 즉시 취소. 수평 거리뿐 아니라 높이·참여 동의 검사. |

대기열은 사용자당 최대 3개·전체 최대 256개를 초기 제안값으로 둔다. 동일한 일반 반응은 병합 가능하지만 서로 다른 후원 이벤트를 임의 합치지 않는다. 5초 이상 기다린 꾸밈 반응은 만료시키고 지연 이유를 기록한다. 경제적 보상이나 결제 완료를 이 임시 연출 큐에 의존시키지 않는다.

기존 '항상 교체' 규칙은 마이그레이션에서 유지한다. 새 템플릿부터 위 정책을 적용하고, 기존 규칙 전환 시 바뀌는 중단 동작을 미리 보여준다.

### 5.3 시간과 애니메이션 동기화

- 시뮬레이션에는 단조 증가 시계를 사용하고, 기록 시각용 wall clock과 분리한다.
- 실제 경과 시간을 누적하는 고정 스텝 물리를 유지하되 한 번에 처리할 최대 보충 스텝을 제한한다. 장시간 정체·절전 복귀 시 오래된 단계를 한 프레임에 몰아서 실행하지 않는다.
- 절전 복귀는 `suspended → resyncing → running`으로 구분한다. 게임은 일시정지 후 재개/종료를 운영자가 선택하고, 누락 채팅을 복구했다고 표시하지 않는다.
- 스냅샷에 `sessionId`, `sequence`, `configRevision`, `simulationTime`, 동작 시작 시각을 포함한다. 뒤늦은 프레임·재시작 전 프레임을 구분한다.
- 보행/달리기 시트는 이동 거리와 보폭 설정으로 위상을 계산한다. 속도를 올렸는데 발만 느리게 움직이는 현상을 줄인다.
- 여러 OBS 소스에서 같은 시트 위상을 계산하도록 엔진 기준 시간을 전달한다. 위치 보간과 게임 판정의 권위를 혼동하지 않는다.

정확한 프레임 제어가 필요한 사용자는 스프라이트 모드를 사용한다. 원본 GIF/WebP 모드는 보존하되 일시정지·시점 동기화에 한계가 있음을 표시한다. 모든 파일을 강제 변환하지 않는다. 추후 선택형 시트 변환은 알파·프레임 지연·반복·합성 방식을 보존할 수 있는지 별도 검증한 뒤 제공한다.

## 6. 캐릭터·이미지·방송 화면

### 6.1 이미지 가져오기

가져오기 순서: 파일 검사 → 형식/프레임 확인 → 상태 지정 → 잘라보기/정렬 → 선택 동작 미리보기 → 저장.

- 단일 이미지, 애니메이션 이미지, 스프라이트 시트를 구별한다. 행·열 자동 추정은 제안만 하고 확정하지 않는다.
- 프레임 크기와 원래 종횡비를 저장한다. 셀 너비·높이가 정수로 나누어지지 않으면 경고하고 자르기 기준을 선택한다.
- 상태별 `anchorX/anchorY`, 표시 오프셋, 원본 방향, 크기 보정을 제공한다. 발 기준점은 모든 상태에서 공유하는 것이 기본이다.
- 프레임 범위·FPS·반복/한 번 재생·끝 프레임 유지/대기 복귀를 지원한다. 열·행·FPS의 UI/검증 상한은 동일한 상수에서 가져온다.
- 실제 표시될 대체 상태를 보여준다. 예를 들어 달리기 원본이 없으면 '걷기 이미지 사용'이지 무조건 '기본 이미지'가 아니다.
- 에셋 목록에서 이미 가져온 이미지를 다시 선택할 수 있게 한다. 동일 해시는 재사용하며 상태별로 파일을 복제하지 않는다.
- 사용자가 가져온 팩에는 작성자·원본 링크·라이선스·재배포 가능 여부를 기록할 수 있게 한다. 로컬 사용과 팩 재배포를 같은 권한으로 취급하지 않는다.

### 6.2 자원 예산

기존 64파일/48MiB 제한을 측정 없이 크게 늘리지 않는다. 먼저 사용량 표시를 `캐릭터 / 고유 파일 / 저장 용량 / 예상 디코딩 비용`으로 나눈다. 9개 상태 파일을 가진 캐릭터 7개가 한도에 가까워지는 사실을 사전에 표시한다.

디코딩 비용은 최소한 픽셀 수·프레임 수·활성 에셋 수로 추정하되, 추정치가 실제 GPU 메모리라고 단정하지 않는다. 기본 팩, 소형 GIF, 대형 투명 GIF, 혼합 150명 장면을 실제 OBS에서 측정한 뒤 활성 에셋 예산을 정한다. 파일 보관 한도와 동시에 재생할 수 있는 한도는 별개다.

정리 화면은 사용 중·초안 참조·복구 참조·미사용 파일을 구분한다. 삭제 대상과 확보 용량을 먼저 보여주고, 정리 실패가 저장 설정을 손상시키지 않게 한다.

### 6.3 오버레이 구성

- 가상 장면의 기준 크기와 출력 종횡비를 분리한다. 1920×1080 기본값을 유지하고 1280×720, 울트라와이드, 하단 띠 출력의 안전 영역을 검증한다.
- 바닥·좌우 경계·최대 높이를 연출 안전 영역으로 제한한다. 캐릭터 크기·이름표·말풍선을 포함한 실제 표시 영역이 밖으로 나가지 않게 한다.
- 부양 높이가 허용 공간보다 크면 저장/테스트에서 실제 적용 가능한 높이를 표시한다. 값을 조용히 다르게 적용하지 않는다.
- 게임 현황은 장면 비율 기준 배치로 바꾼다. 방송 크기 미리보기에서 실제 OBS와 같은 위치가 보여야 한다.
- 이름표는 크기, 최대 폭, 표시 정책을 제공한다. 기본 정책은 최근 반응 사용자 우선으로 하되 항상 표시 옵션을 유지한다. 겹침 방지는 화면 내 위치 조정과 표시 개수 제한으로 시작한다.
- 이미지 로드 실패는 기본 이미지로 대체하고 로컬 진단에 파일명을 표시한다. 방송 화면에 인증 키, 경로, 장문의 오류를 노출하지 않는다.

## 7. 시청자 경험·운영 안전

### 7.1 명령 발견과 입력

명령 목록은 규칙 정의에서 생성한다. 기본값·인자 종류·별칭·필요 권한·대상 기능의 활성 여부를 함께 표시한다. 복사는 '저장된 명령'과 '편집 중 명령'을 구분하고 후자는 미적용 표시를 포함한다.

대상과 시간 인자를 별도로 파싱한다. 예: `!따라 @이름 8`. 이름 안 공백을 지원하려면 마지막 시간 토큰과 인용된 이름의 문법을 정하고, 동명이인은 로컬에서 부여한 짧은 참여 번호로 구별한다. 내부 플랫폼 UID를 그대로 노출하지 않는다.

기존 웹 명령 시스템과 동일 별칭을 등록하면 양쪽 연출이 동시에 발생할 수 있다. 서버 규칙을 수정하거나 가로채지 말고, 알려진 명령 메타데이터만 받아 충돌 경고를 제공한다. 연결이 끊겼을 때는 '충돌 확인 안 됨'이라고 표시한다.

실패 안내는 기본적으로 로컬 진단에만 남긴다. 시청자에게 필요한 사용법은 짧은 개인 캐릭터 말풍선으로 제한적으로 보여줄 수 있다. 자동 채팅 답변은 별도 토글·발송 예산·권한 설계 없이 추가하지 않는다.

### 7.2 참여와 제재

- 개인 참여 상태: 참여 중, 자발적 숨김, 운영자 시간제 제외, 운영자 차단. 자발적 숨김은 `!입장`으로 복귀할 수 있다.
- 운영자 퇴장은 일회성 화면 제거로 이름을 명확히 하거나 'N분 제외'를 별도 명령으로 제공한다. 지속 차단과 섞지 않는다.
- 차단은 일반 프로필 90일 정리와 분리한다. 정책·보관 기간·수동 해제·전체 삭제를 명시하고, 영구 보관을 무조건 기본으로 단정하지 않는다.
- 대상 상호작용은 방송 전체 허용과 개인 허용을 모두 확인한다. 따라가기·밀기 등은 개인 거부와 대상별 쿨다운을 지원한다.
- 정원이 차면 일반 채팅으로 기존 참여자를 즉시 밀어내지 않는다. 최근 활동 기반 교체 또는 제한된 대기열 중 운영자가 선택한다. 거부 사유와 인원 수는 로컬에 표시한다.
- 전체 비우기는 현재 참여자만 제거한다. 새 참여까지 막는 '신규 참여 중지'와 화면을 숨기는 '출력 숨김'을 별도 제어로 둔다.

말풍선 기본 비활성화는 유지한다. 활성화 시 최대 길이·개수·표시 시간·차단 목록과 스팸 제한을 적용한다. 현재 결합 문자를 일괄 제거하는 방식은 일부 언어의 정상 글자도 바꿀 수 있으므로, 기존 프로젝트의 잘고 방어와 일관된 '과도한 결합 문자 제한'으로 통합하는 방향을 검토한다. 방송 공개 텍스트를 완벽히 자동 검열할 수 있다고 약속하지 않는다.

### 7.3 현재 게임을 먼저 완성한다

게임 상태를 `모집 → 카운트다운 → 진행 → 결과 → 종료`로 구분한다. 참가 인원, 남은 시간, 참가 닫힘, 결과 표시 시간을 설정할 수 있어야 한다.

- 달리기: 기본은 난수 기반 관전 게임임을 운영 화면에서 명시한다. 채팅으로 승률을 올리는 것처럼 오인시키지 않는다. 채팅 부스트는 별도 규칙으로 추가하며 사용자당 횟수·최대 효과를 동일하게 제한한다.
- 공동 응원: 인원·시간·사용자별 쿨다운으로 가능한 최대 점수를 계산하고 도달 불가능한 목표를 경고한다. 중도 이탈 시 목표 유지/감소 정책을 시작 전에 정한다.
- 게임 종료는 한 번만 처리한다. 중복 종료로 결과가 바뀌거나 승수가 중복 반영되지 않게 한다. 절전/연결 장애로 중단된 게임의 결과는 정상 승리와 구분한다.
- 새 게임 후보는 투표로 모이기, 공동 목표 채우기 순으로 검토한다. 장비 상점·유료 재화·대규모 전투는 현 단계에서 제외한다.

### 7.4 다양성은 완성된 템플릿으로 제공한다

기능을 늘릴 때는 새 버튼 수보다 '선택하고 수치 몇 개만 바꾸면 바로 작동하는 반응'을 늘린다. 아래는 C 단계의 시간·중단 계약을 사용해 F 단계에서 제공할 신규 템플릿 제안이다. 현재 제공되는 완성 템플릿 목록으로 오인하지 않도록 한다.

| 템플릿 | 사용자가 바꾸는 값 | 기본 조합과 주의점 |
| --- | --- | --- |
| 달리고 인사하기 | 달리기 시간·속도, 인사 시간 | 달리기 종료 후 인사. 채팅 숫자는 달리기에만 적용. |
| 떠오르며 말하기 | 전체 부양 시간·높이·문구 | 부양과 말풍선 동시 시작. 종료·취소 시 말풍선 정리 여부 선택. |
| 잠깐 커지기 | 배율·유지 시간 | 임시 크기 효과 후 기존 개인 크기로 복귀. 다른 크기 효과 중첩 금지. |
| 첫 참여 환영 | 인사 이미지·문구 | 방송 세션 첫 참여에 한 번. 단순 재입장마다 반복되는 환영과 별도 트리거로 제공. |
| 다가가 인사하기 | 대상·최대 접근 시간·인사 | 대상 허용과 접근 성공 때만 인사. 대상 퇴장·시간 초과는 안전하게 종료. |
| 후원 감사 | 최소 금액·포즈·문구 | 진행 중 이동은 유지하고 포즈/문구만 표시하는 기본안. 불가능한 포즈 조합은 편집기에서 제한. |

템플릿은 일반 규칙으로 복제한 뒤 독립 편집한다. 템플릿 업데이트가 이미 편집한 사용자 규칙을 덮어쓰지 않도록 원본 템플릿 ID와 복제 버전만 기록한다. 처음부터 복잡한 빈 편집기를 제시하기보다 '템플릿 선택 → 기본값 미리보기 → 필요한 값만 편집' 순서로 진입시킨다.

## 8. 장애·성능·진단

### 8.1 안전한 적용과 복구

포트 변경은 새 리스너 준비 → 설정 저장 → 출력 주소 변경 알림 → 기존 리스너 종료 순서다. 새 리스너와 이전 리스너가 잠시 공존하는 동안 각 요청의 Host/Origin 검사는 해당 리스너의 포트를 기준으로 해야 한다. 어느 단계에서 실패해도 기존 출력이 유지되어야 한다. 이미 변경된 출력 주소는 사용자가 OBS에 반영해야 한다는 점을 표시하고, 앱 재시작 때는 저장된 주소를 그대로 유지한다.

오버레이 재연결은 계속 시도하되 로컬 관리 화면에는 '서버 대기/키 오류/출력 연결 한도/프레임 지연'을 구분한다. 서버 재시작 시 `sessionId` 변경을 감지해 옛 위치 보간·에셋 상태를 초기화한다. 배포 버전과 프로토콜 버전이 맞지 않으면 제한된 빈도로 자동 재로딩하고 반복 실패는 진단한다.

백업 압축과 큰 파일 검사는 worker 또는 비동기 작업 큐로 옮긴다. 작업 진행/취소가 가능해야 하며, 취소 시 임시 파일만 제거한다. 복원은 임시 영역 검증 후 반영하며 부분 실패 시 기존 설정·파일로 돌아갈 수 있어야 한다. 시청자 개인정보가 없는 '연출 팩 백업'과 별도 동의가 필요한 '개인 기록 백업'을 분리한다.

### 8.2 과부하 정책

현재 중계의 80건/초는 모든 전달 경로의 서비스 한도가 아니라 원격 인스턴스 공용 배치 경로의 산술 상한이다. 같은 인스턴스 직접 전달, 실제 DB 왕복, 페이로드 크기에 따라 결과가 달라진다.

개선안은 방송별 작은 큐와 공정한 순환 처리다. 퇴장·운영 제어, 후원/구독, 명시적 명령, 일반 채팅에 각각 한도를 둔다. 높은 우선순위라도 무제한 수용하지 않는다. 일반 채팅 입장 갱신은 사용자별로 병합할 수 있지만 개별 명령·후원 ID는 유지한다. 혼잡 시 폐기 건수·최대 대기 시간을 집계한다.

원격 중계는 끊긴 동안의 채팅을 보장해 재전송하는 구조가 아니다. 단기 장애 후 오래된 연출을 몰아 재생하지 않는 현재 원칙을 유지한다. 금전적 권리나 포인트 지급이 필요한 기능은 별도 영속 시스템이 필요하므로 이 기능에 결합하지 않는다.

스냅샷은 에셋 정의를 매번 포함하는 현재 방식에서 시작해 바이트 수를 측정한다. 필요성이 확인되면 설정 버전 변경 시 카탈로그 전송, 이동 프레임에는 최소 상태만 전송한다. 패킷 유실 복구를 위해 연결 초기와 일정 주기에는 전체 상태를 보낸다. 성능 측정 전 전체 렌더러를 Canvas/WebGL로 교체하지 않는다.

### 8.3 진단 계약

이벤트 결과에 `eventId`, `ruleId`, `configRevision`, 수신 지연, 판정 결과, 이유 코드, 중단 원인을 남긴다. 주요 이유 코드는 `COOLDOWN`, `ROLE_DENIED`, `TARGET_MISSING`, `TARGET_AMBIGUOUS`, `ACTOR_LIMIT`, `DISABLED`, `PAUSED`, `STALE_EVENT`, `RATE_LIMIT`, `GAME_OWNS_MOTION`, `INVALID_ARGUMENT`다.

상태 표시는 세 축이다: 이벤트 수신 연결, 로컬 연출 실행, 출력 연결/프레임 상태. 채팅이 없는 시간만으로 연결 실패라고 판단하지 않는다. 출력 연결 수를 'OBS 감지 완료'로 표현하지 않는다.

진단은 기본적으로 메모리 최근 200건만 보관한다. 원문 채팅은 기본 미보관이고 입력 오류 분석에 필요한 경우에도 길이 제한·선택 수집을 적용한다. 내보내기 시 닉네임·토큰·출력 키·로컬 경로를 제거한다. 사용자 식별 해시는 익명화 보장이 아니라 연결 가능한 가명 식별자로 취급한다.

## 9. 구현 단위와 순서

공수는 팀 규모와 실제 OBS 측정 전에는 날짜로 확정하지 않는다. S는 국소 수정, M은 한 기능 경계 변경, L은 여러 모듈의 계약 변경이다. 단계별로 완료 기준을 통과한 뒤 다음 범위를 늘린다.

| 단계 | 작업 | 공수·선행 조건 | 완료 조건 |
| --- | --- | --- | --- |
| A. 손실·중단 방지 | F01 백업 분리, F02 포트 안전 전환, 저장 실패 초안 보존 | M · 즉시 시작 가능 | 미저장 내보내기, 포트 충돌, 쓰기 실패 회귀 검사 |
| B. 믿을 수 있는 테스트 | 미리보기/리허설 분리, 구조화된 판정 결과, 대상 선택, 명령 목록 버전 표시 | M · A의 상태 구분 | 권한·쿨다운·정원·대상 결과가 같은 엔진 실전 입력과 일치 |
| C. 시간·중단 계약 | 동작별 시간, 인자 연결, 설정 버전 고정, 제한된 실행 영역, 시뮬레이션 시계 | L · B 진단 필요 | 복합 반응·정지/재개·절전·반응 교체 시나리오 통과 |
| D. 이미지 품질·편집 | 프레임 비율/피벗, 제자리 상태 미리보기, 에셋 재사용, 실행 취소, 안전 영역 | L · C 상태 계약 | 상태 전환 시 발 위치 유지, 비정사각 프레임 무변형, 초안 파일 정리 안전 |
| E. 운영·수신 안정화 | 차단 보관, 참여 상태, 방송별 중계 예산, 장애 진단, 비동기 백업 | L · B 이유 코드 | 차단 만료 정책·폭주·재접속·장시간 방송 검증 |
| F. 게임과 연출 확대 | 참가/카운트다운/결과, 목표 설정, 반응 템플릿 | M · C/E | 현재 두 게임의 운영 시나리오가 완결될 것 |

구현은 같은 단계 안에서도 작은 변경으로 나눈다. 예를 들어 F01은 백업 처리 분기와 UI 회귀 검사만으로 독립 배포할 수 있다. 여러 기능을 한 번에 전면 교체하지 않는다.

### 책임 경계

- `schema.cjs`: 버전과 마이그레이션, 필드 의미, 공통 상한. 기존 규칙의 의미 보존.
- `engine.cjs`: 입력 판정, 시간, 동작 소유권, 게임 판정. 이유 코드를 반환하되 UI 문구는 넣지 않는다.
- `service.cjs`: 방송/미리보기/리허설 생명주기, 출력 서버 전환, 스냅샷 버전.
- `storage.cjs`: 설정·초안·차단 정책·에셋 메타데이터와 백업 원자성.
- `overlay.js/css`: 비율·위상·보간·에셋 실패 대체와 재연결. 명령이나 게임 결과는 결정하지 않는다.
- `renderer/avatars.js`: 편집 이력, 필드 검증, 테스트 결과, 운영 상태. 핵심 규칙을 따로 재구현하지 않는다.
- `local-avatar-relay.js`: 채널별 전달·공정 분배·누락 집계. 연출 이미지나 설정 저장은 하지 않는다.

파일 분리는 기능 경계가 실제로 커지는 시점에만 수행한다. 타입 정의와 순수 검증 함수는 먼저 공유하고, 신규 프레임워크나 범용 플러그인 시스템은 요구하지 않는다.

### 배포와 호환성

v2 원본 설정을 보존한 뒤 v3 변환 결과를 검증한다. 더 최신 버전의 설정을 구버전 앱이 조용히 기본값으로 덮어쓰지 않게 한다. 롤백은 백업에서 명시적으로 수행하며, 구버전으로 신규 필드를 저장하면 무엇이 사라지는지 알려준다.

새 이벤트 필드는 기존 서버/클라이언트 조합에서 선택적으로 처리하고 기능 지원 버전을 교환한다. 서버와 로컬 앱 업데이트 순서가 바뀌어도 기존 동작은 유지되어야 한다. 릴리스 파이프라인의 자동 검사 외에 실제 Windows 설치·업데이트·OBS 재접속 검증을 별도 승인 조건으로 둔다. 코드 서명 여부는 릴리스 산출물에서 확인하며 설정 파일만 보고 서명 완료라고 판단하지 않는다.

## 10. 수용 시나리오

자동 검사는 바뀐 계약 중심으로 작성한다. 화면은 사용자 흐름을 바꾸는 경우에만 집중 확인하고, 실제 방송 시험은 아래 묶음으로 수행한다.

| 영역 | 반드시 확인할 사례 |
| --- | --- |
| 편집 보존 | 미저장 백업, 백업 취소/실패, 저장 실패, 종료 후 초안 복구, 실행 취소 후 에셋 정리 |
| 안전한 적용 | 점유 포트로 변경, 설정 저장 중 오류, 방송 중 규칙 한 개 변경, 이미지 검사 중 계속 재생 |
| 기본 시간 | 숫자 생략 5초, 사용자 기본값 7초, 이번 명령만 2초, 빈 설정값, 잘못된 인자, 상한 밖 숫자 |

| 실전 리허설 | 일반/운영자/스트리머 권한, 후원 최소값, 연속 입력, 수동 입장, 정원 초과, 실제 출력 격리 |
| 이미지 | 투명 PNG/GIF/WebP, 비정사각 프레임, 원본 왼쪽 방향, 상태별 여백 차이, 누락/손상 파일 |

### 우선 확정할 제품 선택

아래는 권장 초안이지 사용자 승인이나 구현 완료를 뜻하지 않는다.

- 채팅 시간은 신규 규칙에서 지정한 한 단계만 바꾸고, 부양 시간은 상승/하강을 포함한 전체 시간으로 유지한다.
- 새 명시적 이동은 이전 이동을 교체하지만 일반 채팅의 꾸밈 반응은 이동을 끊지 않는다.
- '퇴장'은 일회성, 'N분 제외'와 '차단'은 별도 기능으로 둔다. 차단 보관 정책은 일반 90일 프로필 정리와 분리한다.
- 에셋 팩 시장·임의 스크립트·장비 상점·유료 재화는 현재 개선 범위에 넣지 않는다.
- 공개 배포 확대 전 A/B를 먼저 완료하고, C/E의 시간·차단·폭주 핵심 계약을 확인한다. 새 게임 확대는 그 이후다.
