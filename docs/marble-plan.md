# 주루마블 구현 명세

## 시각·동작 완성도 개선

중립적인 디자인 평가와 독립적인 CSS 검사로 개선점을 분리했다.
유지할 강점은 외곽 보드, 투명한 중앙, 프로필 말, 가로/세로별 저장 배치다.
작은 말과 상태 글자, 약한 특수 칸 위계, 주사위 크기 맥동, 눌리는 듯한 카드 공개가
핵심 개선 대상이었다. 자동 검사의 미션 색상 띠 지적은 칸의 색을 전달하는
의미 있는 표시이므로 유지한다. 동작 평가 중 기존 애니메이션 자체는 소스 기준이었다.

### 디자인

- 보드: 무광에 가까운 흰 타일, 얇은 색상 띠, 진행 방향, 효과 아이콘을 구분한다.
  황금 칸만 금색 재질을 사용한다. 현재 칸은 굵은 윤곽과 옅은 바탕으로 표시한다.
- 말: 대표 프로필을 더 크게 하고 받침 그림자와 활성 테두리를 보강한다.
  다중 말은 제목 영역을 보존하며, 현재 플레이어의 이름과 사진은 주사위 패널에도 표시한다.
- 패널: 본문·상태·페이지 번호를 키우고 타이머의 준비/진행/임박/완료를 구별한다.
  세로 기본 주사위는 내부 폭을 넓게 사용하고 타이머는 그 아래 우측에 둔다.
  기존 저장 배치는 보존하며 기본 배치 복원 시에만 새 좌표를 적용한다.

### 동작

- 주사위: 고정 카메라, 결정적인 던지기/충돌/감속, 마지막 결과 확인 구간.
  서버가 정한 결과를 표시하며 시각 효과로 결과나 확률을 바꾸지 않는다.
- 말: 짧은 준비 동작, 방향을 가진 도약, 착지 압축, 도착 윤곽 순서.
  이동 이력은 가까운 몇 칸만 잠깐 강조하며 중앙에 경로나 파티클을 만들지 않는다.
- 황금 카드: 앞뒷면을 분리한 원근 회전, 한 번의 얕은 들림과 금박 반사.
  공개 후에는 정지해 읽기 쉽게 하고 긴 미션은 손실 없이 페이지를 순환한다.
- 시간: 모든 주요 동작은 서버 타임라인에서 계산한다. 새로고침/폴링이 효과를
  재시작하지 않으며 일시정지와 재개가 같은 장면에서 이어진다.

### 성능·접근성

- 이미 설치된 Three.js만 사용하며 별도 애니메이션 의존성을 추가하지 않는다.
- 움직이는 동안만 프레임을 갱신하고 숨겨진 탭은 비싼 렌더링을 중지한다.
- 동작 줄이기에서는 공간 이동/회전을 제거하고 결과·상태 정보는 유지한다.
- WebGL 장애 시 정적인 주사위로 대체한다. 색상 외에도 아이콘과 텍스트를 사용한다.
- 추가 질문은 생략했다. 사용자가 고정한 방송 공간 및 기존 기능 유지 조건 안에서
  기획과 구현을 함께 요청했으므로 해당 범위에서 진행한다.

## 방송 화면 최종 방향

사용자 추가 요청에 따라 보드는 화면 가장자리를 따라 둘러싼 직사각형으로 배치한다.
보드 안쪽은 배경, 제목, 장식 패널 없이 완전히 투명하게 비워 버튜버 캐릭터를 위한
공간으로 남긴다. 프로필 사진 말은 해당 칸을 따라 움직이며, 닉네임과 진행 정보는
말·보조 패널·관리 화면에 표시한다.

- 기본 24칸은 가로 화면에서 9열×5행, 세로 화면에서 5열×9행의 테두리를 사용한다.
  칸 수가 바뀌면 화면 비율에 맞게 가로·세로 칸 수를 다시 계산한다.
- 가로 화면: 보드 전체 화면, 주사위·타이머·미션은 우측 안쪽에 모은다.
  중앙과 좌측 안쪽이 주 캐릭터 공간이며, 참가자 목록은 멀티 플레이 때만 보인다.
- 세로 화면: 주사위·타이머는 상단 안쪽, 미션은 하단 안쪽에 둔다.
  중앙의 세로 공간을 캐릭터 영역으로 남기며 참가자 목록은 기본 숨김이다.
- 보조 패널은 계속 개별 이동·크기 변경·표시 여부 저장을 지원한다.
  기존 저장 배치를 자동으로 덮어쓰지 않으며 기본 배치 복원으로 새 구성을 적용한다.
- 긴 미션은 글자를 잘라 버리지 않고 여러 페이지로 나누어 순환한다.
  같은 칸의 여러 프로필 말은 제목 영역을 침범하지 않도록 전용 영역 안에서 배치한다.

## 목표와 범위

**사용자 확정: 기본 콘텐츠와 모든 기본 화면은 싱글 플레이 중심이다.**
기본 말 1개로 즉시 시작하고, 여러 참가자와 온라인 초대는 보조 기능으로 둔다.
기본 칸/카드는 다른 참가자가 없어도 성립한다. 단독 플레이에서 참가자 선택,
목록, 초대가 기본 진행을 가리지 않아야 한다.

**사용자 확정: 말은 스트리머의 대표 프로필 사진, 이름은 대표 닉네임을 사용한다.**
기본 말은 방장 계정과 연결하고 초대 참가자도 본인의 프로필을 사용한다.
연결된 계정의 이름/사진을 다른 참가자가 임의로 위조할 수 없다. 사진 실패 시
이니셜/기본 원형 말로 대체한다. 직접 추가한 오프라인 참가자만 이름을 직접 지정한다.

아루봇 관리 화면에서 준비, 초대, 진행, 설정을 완료하고 같은 서버 상태를
투명 OBS 브라우저 소스와 온라인 참가자 화면에 표시한다. 기존 명령어, 후원,
관리자 권한, 포인트 저장 방식은 유지한다. 배포 전 실제 OBS와 운영 DB 검증은
자동 테스트와 구분한다.

## 사용자 흐름

1. `/marble`에서 기본 24칸과 12장 황금 미션 카드를 확인한다.
2. 기본 대표 프로필 말 하나로 바로 시작한다. 추가 참가자는 필요할 때만 직접 추가하거나
   아루봇 계정을 검색해 초대한다. 최대 8명.
3. 초대받은 사용자는 자신의 주루마블 페이지의 받은 초대에서 수락한다.
   수락 즉시 기존 개인 OBS 주소에 해당 방이 표시된다. 포인트·후원 연동은 별도다.
4. **사용자 확정: 차례 없이 자유 진행한다.** 각 참가자는 자신의 미션을 마치면
   다른 참가자의 상태와 관계없이 자신의 말을 굴린다. 방장은 대신 굴리기, 일시정지,
   미션 완료, 건너뛰기, 타이머 조작, 종료를 할 수 있다.
5. 참가자는 초대를 수락한 방의 자기 말만 굴리기/미션 완료가 가능하다.
   `participantControl`을 끄면 방장만 진행한다. 참가 권한은 봇 관리 권한이 아니다.
6. 게임 종료 후 기록과 참가·OBS 연결은 남고 다시 시작하면 위치와 진행 효과를 초기화한다.
   참가 화면의 `참여 종료`는 본인 말·미션·후원 예약을 제거하고, 표시 중이던 방이면
   OBS를 내 보드로 돌린다. 진행 중에도 본인이 나갈 수 있다. 재참여에는 새 초대가 필요하다.

## 기본 콘텐츠

- 라투디 방송을 기준으로 술·안주 10칸, TMI, 냥체/멍체 2분,
  외국어 금지 3분, 물 타임, 황금 카드, 주사위 전진·후진,
  보너스 주사위, 방어권의 24칸. 냥체/멍체는 시작할 때 하나를 선택한다.
  기존 18번의 금지어 3분은 삭제하고 안주 쉬는 시간(60초)으로 대체한다.
- 황금 카드는 가벼운 버튜버 방송 미션을 수행한 뒤 성공·실패를 판정하는 12장 덱이다.
  손동작·포즈·즉석 광고는 요구하지 않는다. `eventKind: game`의 표시는 시청자 미션이며
  기존 보상/반전/술·안주/특별 규칙 분류와 사용자 즉시 실행형 카드도 유지한다.
- 기본 구성:

  | 카드 | 미션 | 성공 보상 | 실패 벌칙 |
  | --- | --- | --- | --- |
  | 너에게만 애교 | 목소리로 애교 한 문장 | 방어권 1장 | 귀여운 다짐 한 문장 |
  | 오늘의 명대사 | 채팅 추천 대사 한 문장 연기 | 방어권 1장 | 소소한 TMI |
  | 주사위 건배 | 별도 주사위 눈만큼 작은 모금, 물·무알코올 가능 | 방어권 2장 | 방어권 최대 1장 반납 |
  | 진지한 한 문장 | 지정 대사를 웃지 않고 세 번 | 방어권 1장 | 장난스러운 목소리로 한 번 |
  | 칭찬 배달 | 시청자에게 서로 다른 칭찬 세 가지 | 방어권 1장, 안주 한 입 | 자기 칭찬 한 문장 |
  | 냥체 집중 시간 | 60초 동안 냥체 유지 | 방어권 2장 | 30초 멍체 타이머 |
  | 안주 맛 표현왕 | 맛있다 없이 안주 맛 두 가지 표현 | 보너스 굴리기 | 방어권 최대 1장 반납 |
  | 목소리 세 가지 | 같은 인사를 세 가지 목소리로 | 방어권 1장 | 시청자 선택 목소리로 인사 |
  | 추억 한 조각 | 30초 안에 즐거운 방송 추억 | 방어권 1장 | 다음 방송에서 할 일 한 가지 |
  | 주사위 칭찬 릴레이 | 별도 주사위 눈만큼 다른 칭찬 | 방어권 2장 | 30초 동안 말끝에 최고예요 |
  | 오글 대사 도전 | 지정 감사 대사를 끝까지 말하기 | 방어권 1장 | 귀여운 감사 인사 |
  | 오늘의 TMI | 30초 안에 오늘의 소소한 TMI | 방어권 1장, 보너스 굴리기 | 짧은 응원 구호 |

- 진행: 카드 공개 → 필요 시 미션 주사위 → 수행 → 성공/실패 → 결과 확인.
  성공 여부는 방장 또는 직접 조작이 허용된 본인 참가자가 판단한다. 타이머 만료는
  자동 실패가 아니며, 판정 전에는 결과 효과를 적용하지 않는다. 성공/실패는 한 번만 확정한다.
- `challenge`에 미션 주사위 사용 여부와 성공/실패 설명·효과를 각각 저장한다.
  카드 편집에서 모든 문구, 진행 타이머, 결과별 방어권·보너스·주사위 이동 등을 수정한다.
  결과 효과는 각 최대 6개이고, 판정 전 효과는 메시지·타이머만 허용한다.
  미션 덱이 있을 때 카드 칸은 카드 한 장과 메시지·타이머만 조합한다.
- 미션 주사위는 일반 설정이 두 개여도 한 개만 굴린다. 서버 난수, 결과, 시작·종료 시각을
  저장해 기존 3D 주사위 패널에서 재생한다. 말 위치·일반 굴림 이력·라운드·포인트는 바꾸지 않는다.
  본문의 `{dice}`는 결과로 치환되며, 굴리기 전/굴리는 중에는 결과를 숨긴다.
  추가 주사위를 다시 굴리거나 애니메이션이 끝나기 전에 판정하는 요청은 거부한다.
  주사위가 필요한 미션의 타이머는 해당 애니메이션이 끝난 시각부터 시작한다.
- 실패 타이머는 기존 미션 타이머를 대체하고, 보너스/이동 주사위는 결과 확인 후 시작한다.
  판정 전 패스에는 성공 보상·실패 벌칙이 없다. 참가자 방어권 비용 등 기존 패스 규칙은 유지한다.
- 외국어 금지는 외래어도 포함하되 사람 이름·닉네임은 제외한다. 판정은 스트리머가 한다.
- 음주량 경쟁, 빠르게 마시기, 강제 음주를 기본값으로 넣지 않는다.
  음료 선택과 미션 패스는 자유이며 문구는 모두 편집 가능하다.
- 칸 수는 12~40개, 4의 배수. 칸 번호는 이동 순서를 뜻하고 시작 칸은 0번.
- 카드 1~60장, 매 셔플 주기에 중복 없이 뽑는다. 다음 카드 결과는 클라이언트에 노출하지 않는다.
- 칸/카드 공통: 이름, 본문, 색, 효과 목록. 효과는 최대 6개.
- 칸/카드 아이콘은 의미별 컬러 일러스트 16종 중 선택한다. 예전 데이터처럼
  아이콘이 없으면 효과·제목으로 자동 선택하며, 칸 번호에 따라 무관한 그림을 배정하지 않는다.
  미션 그림은 항상 정방향, 이동 화살표는 다음 칸으로 나가는 모서리에 별도로 표시한다.
- 사물에 눈·입·볼터치 같은 얼굴 표현을 넣지 않는다. 일정한 외곽선, 제한된 의미별
  색상, 재질 하이라이트와 명확한 실루엣으로 귀여운 스티커 일러스트를 만든다.
  이동 이벤트는 같은 원근법으로 맞춘 정육면체의 앞·위·옆 3면과 각 면에 투영한
  눈을 사용한다. 전진의 +, 후진의 −, 보너스의 별은 주사위 밖 작은 배지로 분리한다.
  보드 동선은 별도 화살표로 구분한다.
- 황금 카드는 청록색 뒷면과 금박 테두리, 전용 이벤트 헤더·종류 표기로 일반
  흰색 미션 카드와 구분한다. 공개 시 3D 뒤집기, 본문 자동 페이지, 축소 모션을 지원한다.
- 효과: `message`, `timer`(5~600초), `move`(-12~12칸), `goto`(칸 번호),
  `rollForward`/`rollBackward`(주사위 하나를 굴려 전진/후진),
  `skip`(1~3단계 휴식 표시, 완료 시 해제), `extra`(완료 후 1회 보너스 굴리기),
  `shield`(방어권 1~99장 획득, 수량 생략 시 기존처럼 1장),
  `shieldLoss`(1~99장 차감), `shieldClear`(전부 회수), `shieldDouble`(두 배),
  `card`(황금 카드).
- 방어권은 효과 순서대로 적용하고 잔액은 0~99장으로 제한한다. 보상·차감은
  일반 칸/즉시 실행형 카드는 도착 시, 판정형 카드는 판정 트랜잭션에서 한 번만 반영하며
  완료/패스 시 다시 반영하지 않는다.
  `pending.shieldDelta`에 제한 적용 후 실제 증감을 저장한다. 오버레이와 참가 화면은
  명목 수량 대신 실제 +/−/변동 없음을 표시하며 기록에는 전후 잔액을 남긴다.
- 주사위 이동은 이벤트 확인 후 전진/후진 굴리기 버튼으로 실행한다. 일반 주사위 수가
  2개여도 이동 이벤트는 정확히 1개이며 서버 난수·경로·방향을 저장한다. 도착 칸은
  정상 발동하지만 이동 칸을 다시 만나면 다음 명시적 클릭까지 대기한다.
  완료 전 중복 클릭·이전 roll ID를 거부하고, 패스로 이동을 취소할 수 있다.
  이동 굴리기는 추가 포인트를 차감하지 않으며 후원 예약보다 먼저 진행한다.
  전진/후진/보너스 굴리기의 충돌 조합은 설정 저장 시 거부한다.
- 기존 사용자 지정 `move`/`goto`는 고정 이동과 도착 칸 미발동 동작을 유지한다.
  카드 내 카드 효과는 금지한다.
  임의 JS/HTML/URL 실행은 지원하지 않아 순환·스크립트 주입을 막는다.
- 이전 기본값과 내용이 정확히 일치하는 9/18/21번 칸 및 기존 8장/12장 기본 덱만
  대기/종료 상태에서 row lock 안에서 자동 갱신한다. 덱 교체 시 셔플 목록도 비운다.
  진행/일시정지 중에는 다음 대기/종료 상태까지 미루며, 수정한 칸·카드·배치·가격은
  보존한다. 사용자 수정 덱을 새 기본 덱으로 바꾸려면 게임 종료 후 판·카드에서
  황금 카드 기본 구성을 명시적으로 적용하고 저장한다. 사용자 지정 카드 칸이 한 번에
  여러 카드를 뽑거나 즉시 보상을 함께 주는 경우 덱 자동 교체를 보류해 기존 설정을 보존한다.

## 자유 진행과 시각 연출

- 주사위 1개 또는 2개, 결과는 서버의 암호학적 난수로 확정한다.
- 각 참가자별 `roll -> dice animation -> stepwise pawn movement -> mission/card -> complete -> ready`.
- 여러 참가자의 이동/미션/타이머는 독립적이다. `playerStates`에 각각 저장한다.
  `currentPlayerId`는 차례가 아닌 화면 초점이다. 온라인 OBS 응답에서는 주소 주인의
  말로만 초점을 투영하며, 방장의 선택이나 공유 게임 상태를 변경하지 않는다.
  roster는 각 참가자의 진행 상태와 타이머를 함께 표시한다.
- 주사위 약 1.2초, 칸 이동은 약 0.2초/칸. 서버 타임스탬프로 지연 접속도 같은 시점을 재생한다.
- 주사위 결과, 이동 경로, 카드, 효과는 하나의 DB 트랜잭션으로 저장한다.
- 타이머는 애니메이션 종료 시각부터 시작하고 서버 deadline으로 표시한다.
  일시정지/재개/추가 시간/완료를 지원한다. 만료 후에도 미션 완료를 확인한 뒤
  해당 말의 다음 굴리기가 가능하다. 다른 참가자의 진행에는 영향을 주지 않는다.
- 전체 일시정지는 이동과 타이머의 시간축도 멈추고 재개 시 정지 시간만큼 이동시킨다.
- 패스는 현재 미션을 종료한다. 참가자는 보유 방어권을 소모하고 방장은 강제 패스할 수 있다.
- 같은 참가자의 동시 요청은 한 번만 굴린다. 서로 다른 참가자는 독립적으로
  진행한다. 설정 변경은 revision, 말별 조작은 expectedRollId로 충돌을 판정하며
  409 응답은 자동 재실행하지 않는다. 응답 유실 시 같은 requestId로 결과를 확인한다.
- 종료 후 동일 이벤트 재수신은 새 게임에서 다시 실행되지 않는다.

## 채팅·포인트·후원

- 설정: 포인트 명령어 토글, `!주루마블` 기본 트리거, 1회 가격, 후원 토글,
  1회 최소 금액. 금액과 명령어를 주루마블 페이지에서 직접 수정한다.
- 채팅은 `triggerPlayerId`로 선택한 참가자의 말을 굴리는 방송 참여 기능이다.
  미선택이면 첫 참가자이며 화면에 대상 이름을 표시한다. 시청자 본인이
  게임 참가자일 필요는 없다. CHZZK/CIME/YouTube 경로에 동일하게 연결한다.
- 포인트는 대상 참가자가 실행 가능한 상태일 때만 차감하고 주사위 상태 저장과 같은
  PG 트랜잭션을 사용한다. 진행 중/잔액 부족/종료/중복 요청은 추가 차감하지 않는다.
- 후원은 KRW 및 설정 금액 이상일 때 이벤트당 1회. 미션 진행 중에는 최대
  참가자당 20개의 후원 굴리기 예약을 FIFO로 저장한다. 해당 참가자 미션 완료 시 소비한다.
- 일시정지 중 예약은 보관, 종료 시 남은 예약은 화면에서 확인 후 비워진다.
  외부 후원 금액은 봇이 환불하지 않으므로 설정 화면에 이 정책을 명시한다.
- 서버는 이벤트 ID를 중복 방지 키로 쓰고 기존 명령어 남용 제한을 거친다.
- 기존 사용자 명령어/돌림판/출석/예약 명령어와 겹치면 저장을 거부한다.

## 저장과 통신

### 온라인 참가자의 시청자 참여

- 참가자는 참여 화면의 `내 시청자 참여` 탭에서 자신의 포인트 명령어·가격,
  후원 토글·최소 금액을 저장한다. 방장 게임판과 다른 참가자의 설정은 수정하지 못한다.
- 초대 수락은 OBS만 연결하며 유료 시청자 참여는 켜지 않는다. 명시적으로 연결·저장한 방 한 곳만
  자신의 채널 이벤트를 받으며, 자신의 계정에 연결된 말만 굴린다.
  포인트는 이벤트가 들어온 원래 채널에서 차감한다.
- 자신의 게임 설정은 보존한다. 다른 방에 연결되어 있으면 내 관리 화면에 연결 상태와
  설정 바로가기를 표시하고, 초대 철회 이후에도 내 게임으로 연결을 복원할 수 있다.
  연결된 방이 종료되거나 참가 권한이 사라져도 다른 게임에서 임의로 과금하지 않는다.
  유료 연동은 수락한 초대 ID에 묶는다. 참여 종료·철회 후 새 초대를 수락해도 과거
  유료 연동은 재개되지 않는다. 저장된 토글·명령어·금액은 유지하고 명시적으로 재연결한다.
- 참여 설정 버전은 게임 진행 버전과 분리한다. 다른 말의 이동 중에도 저장할 수 있지만,
  다른 창에서 동일 채널의 설정을 바꾸면 초안을 보존하고 충돌을 표시한다.
  단순 명령어 중복 오류는 해당 명령어를 고쳐 즉시 다시 저장할 수 있다.
- 참가자 본인에게만 후원 대기 건수를 제공하며 다른 참가자의 후원자 정보는 공개하지 않는다.
  본인 말 수동 조작 허용과 시청자 참여 설정 권한은 별개다.
- 연결 전환 후 같은 채팅·후원이 재전달되어도 소스 채널 기준 영수증으로 중복 실행을 막는다.
  연결 해제는 이미 접수된 후원 예약을 취소하지 않는다.

### 영속 상태

- `marble_rooms`: owner_user_id PK, JSON 상태, revision, 읽기 전용 overlay_token.
- `marble_requests`: owner + request_id unique, 동작 fingerprint와 결과. 재시도해도
  최신 상태를 반환하되 같은 키를 다른 작업에 재사용하면 거부한다.
- `marble_invites`: 명시된 대상 계정, pending/accepted/declined/revoked, 만료 7일.
- `marble_participation`: 소스 채널 계정별 설정, 독립 revision, 유료 연결 방과
  `connected_invitation_id`, 별도의 `obs_owner_user_id`와 `obs_revision`.
  `marble_source_requests`: 연결 대상과 무관한 소스 채널별 처리 영수증.
- 방 row lock과 DB 시계로 멀티 인스턴스 경쟁을 직렬화한다.
- DB 결과가 권위 상태이며 프로세스 메모리만으로 성공 응답하지 않는다.
- 관리/참가/OBS는 1초 활성 상태 polling, 연결 실패 시 최대 10초 간격으로
  영구 재시도한다. 중복 요청, stale revision, 느린 이전 응답을 무시한다.
- 인증 만료·권한 철회·방 삭제 응답에서는 이전 스냅샷을 숨긴다. 이후 정상 조회로
  권한을 다시 확인하기 전에는 늦게 도착한 변경 응답으로 화면을 복원하지 않는다.
- 읽기 요청으로 시간 만료를 계산하지만 다음 굴리기는 명시적 완료 후 진행한다.
- OBS 응답에서 계정 ID, 초대 대상, 토큰, 후원 원본, 포인트 데이터는 제거한다.
- 별도 `marble:read/write` 관리자 스코프. 참가자 API는 실제 로그인 actor로 검사한다.

## UI와 디자인

- 관리 화면은 기존 헤더/버튼/탭/폼을 따른다. 탭은 게임, 판·카드, 참여 설정,
  OBS 배치. 상단에서 상태와 시작/일시정지/종료를 제어한다.
- 게임 탭: 실제 보드가 가장 큰 영역, 옆에 내 진행/주사위/미션 제어,
  아래 참가자별 진행 상태와 최근 기록. 좁은 화면은 보드 아래에 제어를 배치한다.
- 보드는 투명 중앙을 둘러싼 밝은 중성 흰색 타일, 민트/코랄/황금/파랑 기능 색. 장식보다
  칸 이름, 이동 순서, 현재 말의 상태가 먼저 읽혀야 한다. 글자를 굽히거나 회전하지 않는다.
- 말은 참가자 고유색과 이름을 함께 표시하고 같은 칸에서는 겹치지 않게 분산한다.
  여러 말의 이동 애니메이션을 동시에 재생할 수 있어야 한다.
- 황금 카드는 뒷면 회전 후 내용 표시, 주사위는 결과에 맞게 착지,
  말은 칸마다 작은 점프, 도착 칸은 짧은 강조. reduced-motion이면 즉시 결과로 표시.
- 미리보기와 OBS는 동일한 컴포넌트를 사용한다. 관리 조작은 OBS에 나타나지 않는다.
- 폼은 입력 레이블, 오류 위치, disabled/loading, 변경사항 저장·취소,
  덮어쓰기 충돌 안내를 제공한다. 위험한 초기화/종료는 확인을 받는다.

## OBS 배치

- `/viewer/marble/[token]`은 투명 배경, 읽기 전용.
- board, dice, timer, card, roster 5블록을 이동·크기 변경·표시 토글한다.
- 말은 보드 칸에 종속되어 별도 드래그로 게임 위치를 바꿀 수 없다.
- 가로 1920x1080, 세로 1080x1920 레이아웃 각각 저장, 화면 비율로 자동 선택.
- 좌표/폭은 백분율, height는 블록 고유 비율 기준. 보드는 화면 방향의 16:9/9:16 비율이다. 숫자 입력과 드래그,
  방향키 1px/Shift 10px, 기본 배치 복원 지원. 화면 밖으로 나가지 않게 제한한다.
- OBS 주소는 클릭으로 공개, 복사, 새 창 보기, 토큰 재발급.

## 모듈 계약

- 공통 타입: `shared/marble.d.ts`, 순수 엔진 `shared/marble.js`.
- `createMarbleState()` 기본 상태; `parseMarbleSettings(input, base)` 엄격 검증;
  `applyMarbleAction(state, input, { now, randomInt, uuid })`는 새 상태 반환.
- 엔진 액션: `add-player`, `remove-player`, `update-player`, `start`, `end`,
  `pause`, `resume`, `roll`, `complete`, `pass`, `timer-pause`, `timer-resume`,
  `timer-add`, `timer-finish`, `focus`, `reset`, `settings`, `layout`, `enqueue-donation`.
  `leave-player`는 참여 종료 API가 인증한 본인 말에만 사용하는 서버 내부 동작이다.
- `MarbleState`: version, revision, settings, players, status, phase, currentPlayerId,
  round, lastRoll, pending, timer, pausedAt, history, donationQueue, deck, playerStates.
  최상위 진행 필드는 초점 참가자의 상태를 반영한 호환용 projection이다.
- `MarbleSettings`: title, diceCount, participantControl, triggerPlayerId, points, donation, tiles,
  cards, layouts. UI만의 시험 데이터는 저장하지 않는다.
- `MarbleSnapshot`: state, serverNow, ownerUserId?, overlayToken?, access?, invitations?.
  인증 화면에는 본인 채널의 `viewerParticipation`, 참가 화면에는 본인 예약 건수
  `viewerDonationQueueCount`를 추가하며 OBS에는 공개하지 않는다.
- 관리자: GET `/api/marble`; POST `/api/marble/action` {action,requestId,revision,...};
  PUT `/api/marble/settings` {settings,requestId,revision};
  PUT `/api/marble/layout` {layouts,requestId,revision};
  POST `/api/marble/overlay/rotate` {requestId}; GET `/api/marble/users?q=...`;
  POST `/api/marble/invites` {memberUserId,requestId};
  DELETE `/api/marble/invites/:id`.
- 관리 채널의 유료 시청자 참여만 복원: POST `/api/marble/participation/disconnect`
  {requestId,participationRevision}.
- 개인: GET `/api/viewer/marble/invitations`; POST `/api/viewer/marble/invitations/:id`
  {action:'accept'|'decline',requestId}; GET `/api/viewer/marble/rooms/:ownerId`;
  POST `/api/viewer/marble/rooms/:ownerId/action`.

## 검증 기준

### 온라인 개인 OBS

- 기존 개인 OBS 토큰을 유지하고 초대 수락 시 해당 온라인 방을 자동으로 표시한다.
  여러 방을 수락하면 가장 최근에 새로 수락한 방을 표시한다. 이미 수락한 초대의
  반복 요청은 OBS 선택을 바꾸지 않는다. 기존 방으로 돌아갈 때는 참가 화면에서
  `이 방을 내 OBS에 표시`로 선택한다. 유료 시청자 참여 토글과 OBS는 독립적이다.
- 같은 보드와 모든 말의 위치·이동 경로를 공유한다. 주사위·미션·황금 카드·타이머는
  방장과 온라인 참가자 각각 본인의 `playerStates`로 표시한다. 본인이 대기 중이면
  다른 사람의 미션을 대신 표시하지 않는다. 오프라인 게임의 초점 선택은 유지한다.
- 가로·세로 OBS 배치는 주소 주인의 저장값을 사용한다. 배치 편집 미리보기도
  실제 개인 OBS 조회를 사용하며 저장은 자신의 게임 설정에만 적용한다.
- 토큰·OBS 연결·대상 방을 단일 SQL 읽기로 결정한다. 매 조회 시 수락된 초대와
  본인 말이 있는지 검사하고, 초대 철회/방 삭제/말 제거 시 본인의 원래 보드로 돌아간다.
  다른 수락된 방으로 임의 전환하지 않으며, 다른 방에서 나가도 현재 표시 방은 유지한다.
- 방장 토큰 재발급은 참가자의 주소를 무효화하지 않는다. 본인 토큰 재발급은
  본인의 이전 주소만 무효화한다. 참여 종료 시 같은 주소가 자신의 게임으로 돌아간다.
  게임 종료는 참여 종료가 아니므로 결과 화면과 참가·OBS 연결을 유지한다.
- `overlayRevision.connection`, `overlayRevision.source`, `state.revision`, `serverNow`
  순으로 최신 여부를 비교해 버전이 낮은 방으로의 전환도 허용하고 이전 방의 지연 응답은
  거부한다. 토큰·계정 ID·참여 설정·후원자 정보는 공개 OBS 응답에 포함하지 않는다.
  connection은 `obs_revision * 2 + 유효하지 않은 이전 연결의 복귀 비트`다. 초대 철회에
  source 잠금을 추가하지 않고도 낮은 revision의 개인 보드 복귀를 즉시 수용한다.
- 034 마이그레이션은 기존 수락된 방도 자동 연결한다. 기존 유료 연결 방이 유효하면
  우선 보존하고, 없으면 가장 최근 수락한 방을 사용한다. 최초 1회만 이관하며,
  재실행 시 선택/종료 상태·가격·개인 배치를 덮어쓰지 않는다.
