# Roulette Result Actions

룰렛 항목의 실행 값은 등록된 명령어 또는 특수 변수 템플릿입니다. OBS가 해당 스핀의 정지를 확인한 뒤 한 번 실행합니다. 연결이 없거나 확인이 유실되면 기존 서버 폴백을 사용합니다. 디자인 테스트(`testMode: true`)는 실행 액션을 실행하지 않습니다.

## Supported Values

| 입력 예 | 동작 |
| --- | --- |
| `${roulette::다음 룰렛}` | 이름 또는 ID로 지정한 룰렛을 기존 대기열에 추가; 같은 룰렛도 최대 5회 |
| `${action::축하}` | 게시된 블루프린트와 기존 로컬 액션 실행 경로 사용 |
| `${automation::축하}`, `${blueprint::축하}` | action의 기존 별칭 |
| `!등록된명령어 인자` | 해당 채널의 현재 명령어 응답과 로컬 명령어 이벤트 실행 |
| `${video_donation} https://youtu.be/영상ID 0:00 1:00` | 지정 구간을 영상 후원 대기열에 추가 |
| `${bgm_request} 가수 곡명` | BGM 신청 대기열에 추가 |
| `${songbook_request} 가수 곡명` | 기존 노래책 검색·접수·인당 제한으로 신청 |
| `${songbook_url}` | 해당 스트리머의 시청자 노래책 주소 |
| `${live.title_change} 새 제목`, `${live.game_change} 카테고리` | 최초 실행자의 현재 관리 권한을 확인한 후 변경 |
| `${memo::공지}` | 이름 있는 메모를 읽기만 함 |
| `${counter::user::당첨}`, `${counter::global::당첨}` | 당첨 실행 시 증가; 같은 템플릿의 중복 변수는 한 번 증가 |
| `{user.name}`, `{user.points}`, `{user.attendanceDays}` 등 | 기존 플랫폼별 시청자 조회 값 |
| `{live.title}`, `{channel.followers}`, `${dday::2026-12-31}` 등 | 기존 방송·채널·날짜 조회 값 |
| `{roulette.result.label}`, `{roulette.result.value}` | 현재 당첨 항목의 이름과 원래 실행 값 |

인자가 필요한 특수 변수를 실행 값에 직접 넣으면 해당 템플릿의 나머지 텍스트를 인자로 사용합니다. 등록된 명령어의 응답에 넣으면 명령어 인자를 사용합니다. 여러 인자 기반 작업은 같은 인자를 공유하므로 서로 다른 인자가 필요하면 각각 등록한 명령어 또는 블루프린트를 사용합니다.

룰렛 보상은 명령어 비용과 영상/BGM 신청 비용을 다시 차감하지 않습니다. 영상/BGM 기능 활성화, 차단, 최대 재생 길이와 노래책 신청 제한은 그대로 적용됩니다. 블루프린트가 명시적으로 설정한 포인트 지급·차감 액션은 별도입니다. 방송 제목·카테고리 변경은 권한을 우회하지 않으며 YouTube에서는 지원하지 않습니다.

이름 없는 `${memo}`는 직접 실행 값에서 사용할 명령어 ID가 없어 지원하지 않습니다. 등록된 명령어를 통해 실행하면 해당 명령어의 메모를 읽습니다. 후원·출석 이벤트 전용 값과 블루프린트 노드·임시 변수는 직접 실행 값의 카탈로그에 노출하지 않습니다. 출석 조회는 `{user.attendanceDays}`를 사용합니다.

## Execution Safety

- 저장된 템플릿에 원래 적힌 실행 변수만 동작합니다. 시청자 이름, 메모, 당첨 이름 등으로 삽입된 변수나 명령어는 다시 실행하지 않습니다.
- 한 템플릿의 특수 실행은 최대 16개입니다. 기존 실행 깊이·액션 수·채팅 수 제한과 채널 큐 admission을 유지합니다.
- 같은 실행 묶음의 동일 룰렛은 최초 실행을 포함하여 최대 5회 실행합니다. 다른 룰렛을 거치거나 여러 액션으로 분기해도 같은 룰렛 ID의 횟수를 합산합니다. 6번째 실행은 추첨·방송 전에 차단합니다. 명령어·블루프린트 재진입은 기존처럼 즉시 차단합니다.
- 정지 콜백은 원래 실행 컨텍스트를 유지하고, 영속 대기열은 root ID와 경로 및 기존 root당 작업 수 제한을 유지합니다. 기존 실행 예산 테이블의 `roulette_counts`가 재시작과 다중 서버에서도 같은 root의 총 실행 횟수를 원자적으로 제한합니다. 기존 스키마 준비 경로가 해당 열을 자동 추가합니다.
- 방송이 꺼져 있어도 로컬 프로그램·블루프린트 실행을 세션 키 확인으로 차단하지 않습니다. 실제 채팅 송신과 로컬 장치의 연결 가능 여부는 별도입니다.

## Overlay Metadata

`items`, `itemWeights`는 동일한 순서입니다. 일반 룰렛은 `weight`, 확률 룰렛은 `probability`를 사용합니다. 숫자 합산이 넘치는 극단적인 가중치는 같은 비율로 정규화합니다. `selectedItemIndex`는 현재 스핀의 정확한 당첨 인덱스이므로 이름이 중복되어도 구별됩니다.

실시간·즉시·테스트·큐·재전송 이벤트에 같은 필드를 포함합니다. 이전 DB 기록은 별도 인덱스가 없으므로 이름과 실행 값으로 한 항목을 특정할 수 있을 때만 복원하며, 중복되는 경우 `null`입니다. 기존 룰렛 설정과 결과 저장 스키마는 변경하지 않습니다.
