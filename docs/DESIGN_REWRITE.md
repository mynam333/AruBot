# AruBot 상용 UI 재작성 기록

## 목표

- 예시 이미지, 데모 수치, 가짜 룰렛 항목 없이 실제 서비스 데이터만 표시한다.
- 관리자, 시청자, 공개 채널, OBS 오버레이, 로컬 프로그램, 브라우저 확장이 하나의 제품처럼 보이게 한다.
- API 경로, 인증 쿠키, viewer token, WebSocket payload와 실행 액션 형식은 변경하지 않는다.
- 불러오기 실패와 실제 빈 데이터를 구분한다.

## 발견한 구조적 문제와 수정 내용

| 영역 | 기존 문제 | 적용한 해결책 |
| --- | --- | --- |
| 전역 디자인 | 파스텔 그라디언트, 블러, 떠오르는 카드가 대부분의 화면에 반복됨 | 중립 배경, 단색 표면, 얇은 경계, 민트 포인트 중심의 운영 콘솔 토큰으로 교체 |
| 정보 계층 | 페이지마다 큰 홍보형 헤더가 실제 작업 영역을 밀어냄 | 공통 `PageHeader`, 실제 상태 지표, 작업 우선순위 중심으로 재배치 |
| 내비게이션 | 15개 메뉴가 한 목록에 있고 태블릿·모바일 동선이 약함 | 업무 그룹 사이드바, 태블릿 아이콘 레일, 모바일 핵심 하단 메뉴와 전체 서랍 구성 |
| 상태 표현 | API 실패가 0개 또는 빈 목록처럼 보임 | `readJsonResult`, `ErrorState`, `EmptyState`, `StatusDot`을 추가해 실패·빈 상태·정상 상태 분리 |
| 대시보드 | 마케팅 문구와 기능 카드가 실제 운영 상태보다 큼 | 연결 채널, 봇, 영상 대기열, 명령 처리 상태와 실제 빠른 작업 중심으로 재작성 |
| 룰렛 관리 | 실제 OBS 렌더러와 다른 수동 목업 미리보기가 존재함 | 목업 미리보기를 제거하고 저장된 레이아웃·스킨이 실제 실행에 적용됨을 명시 |
| 룰렛 휠 | 항상 8칸으로 만들고 없는 항목을 가짜 항목으로 채움 | 서버가 보낸 실제 항목 수로 섹터·각도·정지 위치·라벨을 동적 계산 |
| 룰렛 오버레이 | 프레임과 장식이 결과보다 강하고 영문 상태 문구가 혼재함 | 프레임을 단순화하고 실제 룰렛명·시청자·결과·배치 진행을 우선 표시 |
| 예측 오버레이 | `preview=1`에서 실제 예측 없이 대기 샘플을 표시함 | 실제 예측이 있을 때만 렌더링하고 관리자 화면도 실제 최신 데이터만 표시 |
| 공개 채널 | 채널 정체성이 약하고 실패가 빈 목록처럼 표시됨 | 응답 데이터의 실제 채널명을 사용하고 실시간 갱신 오류 상태를 별도 표시 |
| 랜딩 | 제품 내부 화면을 흉내 낸 데모 카드와 명령어 샘플이 존재함 | 실제 지원 기능, 연결 대상, 진입 경로만 제공하는 제품 소개로 재작성 |
| 로컬 프로그램 | 임시 `A` 브랜드 마크와 웹과 다른 파스텔 UI | 패키지 아이콘 사용, 웹 콘솔과 같은 색·경계·상태 패턴 적용 |
| 브라우저 확장 | 영문/한글 혼용 및 설정 용어 불일치 | 상태·버튼·설정 용어를 한국어로 통일하고 동일한 다크 운영 UI 적용 |

## 기능 보호 계약

- 룰렛 정의 저장 형식 `theme: \`${layout}:${theme}\`` 유지
- 룰렛 viewer token 및 `/api/roulette/ws` 연결 유지
- 룰렛 메시지의 `name`, `username`, `label`, `value`, `items`, `theme`, `batchId`, `batchCount` 사용 유지
- 기존 관리자 API endpoint와 인증 credentials 유지
- 브라우저 확장의 background service 메시지 타입과 DOM id 유지
- 로컬 프로그램 renderer의 기존 DOM id와 renderer 이벤트 연결 유지

## 검증 기준

- ESLint: 오류 0건
- TypeScript: 오류 0건
- Next.js production build: 성공
- 룰렛 동적 섹터 및 기존 호환 회귀 테스트: 통과
- 브라우저 확장 CHZZK/CIME/Toonation 회귀 테스트: 통과
- 데스크톱, 태블릿, 모바일: 가로 오버플로 없음
- 프로덕션 브라우저 콘솔: hydration 포함 오류 0건

## 기존 백엔드 테스트 상태

디자인 작업 범위 밖의 `server/index.js`와 DB provider 관련 기존 소스 계약 테스트 3개는 작업 전과 동일하게 실패한다. 해당 파일은 동시에 진행 중인 변경을 보호하기 위해 이번 재작성에서 수정하지 않았다.
