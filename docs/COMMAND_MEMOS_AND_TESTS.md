# 메모 변수와 블루프린트 테스트

## 메모 명령어

명령어의 응답을 `오늘의 공지: ${memo}`로 설정합니다.

- 스트리머 또는 채팅 관리자가 `!공지 내일 저녁 8시 방송`을 입력하면 `내일 저녁 8시 방송`을 저장하고 응답에 표시합니다.
- `!공지`처럼 인자가 없으면 기존 메모를 응답에 넣습니다.
- 일반 시청자는 인자를 붙여도 내용을 바꿀 수 없고 기존 메모만 조회합니다. 명령어 자체의 역할 제한, 쿨다운, 포인트 설정은 그대로 적용됩니다.
- `${memo}`는 명령어 ID별 메모입니다. 같은 명령어의 여러 트리거는 같은 메모를 사용합니다.
- `${memo::공지}`처럼 이름을 지정하면 같은 채널의 다른 명령어에서도 공유할 수 있습니다. 이름 없는 메모와 이름 있는 메모는 별개입니다.

메모는 DB에 저장하므로 재시작 후에도 유지되고 다른 스트리머와 공유되지 않습니다. 명령어와 인자를 구분하는 앞쪽 공백을 제외한 인자 원문을 저장합니다. 내부 공백, 줄바꿈, 문장부호를 재조합하거나 변환하지 않습니다. 플랫폼의 채팅 출력 길이 제한은 그대로 적용됩니다.

내용은 최대 4,000자, 한 응답에서 서로 다른 메모는 최대 16개입니다. 같은 메모가 반복돼도 한 번 저장하며, 서로 다른 메모를 한 응답에 넣으면 모두 같은 인자로 갱신됩니다. 저장된 내용의 특수 변수는 문자 그대로 출력되고 실행되지 않습니다. 과도한 길이와 금지된 텍스트는 자르거나 바꾸지 않고 저장을 거부합니다.

블루프린트의 명령어 직접 실행과 룰렛 결과로 호출되는 명령어는 메모를 조회만 합니다. 시뮬레이션에 입력한 관리자 정보로 메모를 수정할 수 없습니다.

## 블루프린트 테스트

- **시뮬레이션:** 기기 전송 없이 조건·분기와 결과를 점검합니다.
- **연결 기기 실제 테스트:** 확인 후 현재 편집 내용을 저장하고 로컬 명령, OBS, 소리, FX 오버레이 및 외부 연결 요청을 실제 전송합니다. 방송 화면과 소리에 반영될 수 있습니다.

테스트는 현재 저장된 초안을 대상으로 하며, 다른 편집으로 버전이 바뀌면 중단합니다. 중첩 액션은 게시된 버전을 사용합니다. 두 테스트 모드 모두 실제 시청자 포인트 변경과 방송 채팅 전송을 막습니다. 실제 연결 테스트에서 지원하지 않는 승인·타이머·채팅 투표 노드는 성공으로 넘기지 않고 오류로 표시합니다.

로컬 작업은 로컬 프로그램이 실행되고 해당 계정으로 연결되어 있어야 합니다. FX 오버레이를 직접 표시하는 노드는 해당 브라우저 소스도 열려 있어야 합니다. 전송 또는 작업 접수는 기기의 실행 완료와 다릅니다. 기기 실행 결과는 로컬 프로그램의 작업 로그에서 확인합니다.

## 후원 반응

치지직, YouTube, CIME의 후원 반응에 다음 변수를 사용할 수 있습니다.

- `${blueprint::액션이름}`, `${action::액션이름}`, `${automation::액션이름}`: 게시된 블루프린트를 실행합니다.
- `${roulette::룰렛이름}`: 포인트 소모 없이 룰렛을 한 번 실행합니다.
- `${username}`, `${amount}`, `${message}` 또는 `{donation.username}`, `{donation.amount}`, `{donation.message}`: 후원자 정보입니다.

후원자가 메시지나 닉네임에 입력한 특수 변수는 실행하지 않습니다. 관리자가 저장한 응답에 있는 실행 변수만 동작합니다. 블루프린트에 설정된 실제 포인트 조정 노드는 일반 실행과 같은 정책으로 동작합니다.

## FX 랜덤 위치

블루프린트의 **FX 오버레이 → 배치와 크기 → 표시 위치**에서 **랜덤 위치**를 선택합니다. 이미지·스티커·비디오가 나타날 때마다 위치를 새로 고릅니다. 크기는 기존 `%` 또는 `px` 설정을 사용하고 화면보다 크면 화면 안으로 제한합니다.

표시 중 내용이 바뀌거나 화면 크기가 바뀌어도 위치를 다시 추첨하지 않습니다. 고정 위치로 돌아가면 이전 X·Y 설정을 사용합니다. 기존 저장 설정은 고정 위치로 유지됩니다. 사용자 정의 CSS로 추가한 이동·확대 애니메이션의 화면 이탈까지 제한하지는 않습니다.

## 배포

프런트엔드·백엔드를 함께 배포하고 `npm run db:migrate`로 `029_bot_memo_values.sql`을 적용합니다. 기존 백엔드 배포 절차에는 마이그레이션 단계가 포함되어 있습니다. `npm run db:provider-smoke`는 메모 테이블의 읽기·쓰기 권한도 확인하고 점검 데이터를 롤백합니다.
