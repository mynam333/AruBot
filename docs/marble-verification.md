# 주루마블 검증 기록

## 구현 범위

- 싱글 플레이 우선, 대표 프로필 사진과 닉네임을 사용하는 말.
- 수동, 포인트 명령어, 후원 진입점 및 별도 설정.
- 사용자 지정 칸, 술·안주 황금 이벤트 12종, 타이머, 주사위 전진·후진, 보너스 주사위.
- 방어권 수량 보상·차감·전부 회수·두 배, 실제 증감 표시와 이전 기본값의 안전한 갱신.
- 차례 없는 온라인 초대와 참가자별 진행, 방장 제어.
- 읽기 전용 OBS 주소와 재연결, 가로/세로별 개별 블록 배치 저장.
- 화면 둘레 보드와 투명한 중앙, 비활성 보조 패널 숨김.
- 온라인 참가자 본인의 시청자 참여 설정, 한 채널당 한 방 연결, 내 게임으로 연결 복원.

  진행 중 갱신 지연, 한 번만 revision 변경, DB 저장 실패 시 롤백.

  다른 방 전환 이후 이벤트 재전달, 독립 설정 버전 충돌, 참가 철회·방 삭제 시 과금 중단,
  원래 게임 연결 복원, 실제 잔액·게임·영수증 롤백, 무효화된 캐시 조회 경쟁을 검증했다.

  복구할 수 있다. 실제 HTTP 유틸의 에러 코드 전달도 검증했다.

## 로컬 브라우저 검증

실제 관리 화면과 오버레이 컴포넌트를 임시 PGlite 서버에 연결했다.
테스트 계정, 포인트 및 이미지는 운영 데이터와 분리했다.

- 시작, 굴리기, 말 이동, 미션 완료, 종료, 재시작.
- 포인트/후원 설정, 칸과 타이머 편집, 배치 저장, 초대 수락.
- 대표 프로필 표시, 참가자 모바일 스크롤, 가로 넘침 없음.
- 3D 주사위의 비어 있지 않은 픽셀과 프레임 간 변화 확인.
- 최종 둘레형 데스크톱 보드와 비활성 패널 숨김 확인.
- 최종 390px 모바일 세로 배치와 1920×1080 방송 화면 확인.
- 방송 화면의 HTML/body 및 중앙 모든 상위 요소 배경이 실제 투명임을 확인.
- 보드가 선택된 상태에서도 내부 주사위 블록 선택과 위치 변경 가능.

## 디자인 결정

### 온라인 개인 OBS 추가 검증

아래 Chrome 기록은 이전 개인 OBS 구현의 검증이다. 초대 자동 연결 변경은 다음 별도 절을 기준으로 한다.

- 각자의 기존 주소가 같은 보드·말 위치를 반환하고, 서로 다른 주사위/미션/타이머와
  개인 저장 배치를 표시함을 검증했다. 조회가 방장 초점과 저장 상태를 변경하지 않는다.
- 본인 미션이 없을 때 다른 참가자 미션을 빌려 표시하지 않음, 방 전환·연결 해제 시
  낮은 방 revision 수용, 지연 응답 거부, 초대 철회·방 삭제 차단, 개인별 토큰 재발급 검증.
- PGlite 실제 SQL에서도 개인 연결에 따른 OBS 조회와 철회 후 접근 차단을 확인했다.
- Chrome에서 방장은 주사위 1/1번 칸, 참가자는 주사위 5/5번 칸을 표시하면서
  두 사람의 말 위치가 동일함을 확인했다. 실제 OBS 배치 편집 미리보기도 연결된 방과
  본인 진행을 표시했다. 가로 1440×810, 세로 390×694에서 화면 넘침이 없었다.
  `personal-obs-guest.jpg`, `personal-obs-portrait.jpg`는 격리된 로컬 DB의 캡처다.
- 이 변경에서 주루마블 테스트, 변경 파일 ESLint, 프로덕션 빌드를 실행했다.
  실제 방송용 OBS 및 운영 서버 배포는 수행하지 않았다.

### 초대 수락 자동 OBS 연결

- 초대 수락만으로 기존 개인 OBS에 해당 보드가 표시되며, 유료 시청자 연결·설정은 변하지 않는다.
- 최신 새 수락 우선, 같은 수락의 중복/재시도 무시, 기존 방의 명시적 선택과 버전 충돌 검증.
- 실행/일시정지 중 참여 종료, 본인 말·미션·예약만 제거, 다른 참가자의 상태 보존 검증.
- 나간 방의 이전 초대 ID나 이전 요청 ID로 새 참가 상태를 제거할 수 없음을 검증.
- 현재 OBS 방에서 나가면 내 보드 복귀, 다른 방에서 나가면 선택 방 유지. 게임 종료는 결과·연결 유지.
- 초대 철회/방 삭제 시 OBS는 내 보드로 복귀하나 유료 연동은 자동 복원하지 않는다.
- 재초대 수락으로 과거 유료 설정이 자동 활성화되지 않으며 가격·명령어·토글 저장값은 보존한다.
- PGlite: 032/033 데이터에서 034 최초 이관, 기존 유효 연결 우선, 재시작 시 선택/종료 보존,
  새 사용자의 유료 기본값 OFF, 실제 SQL에서 수락·후원 예약·실행 중 나가기·동일 요청 재시도 확인.
- 참가자/관리 페이지 변경 파일 ESLint와 프로덕션 빌드 통과.
- Chrome의 격리된 로컬 DB에서 개인 OBS 주소를 열린 채로 유지하고, 관리 화면의 초대 수락만으로
  두 사람의 공유 보드가 표시되는 것을 확인했다. 참가자 화면의 참여 종료 후 같은 OBS 주소가
  새로고침 없이 개인 보드로 복귀했다. 기존 유료 연결 토글은 조작하지 않았다.

### 기존 디자인

초기 정사각형/중앙 장식 구상은 사용자의 버튜버 방송 요청으로 대체했다.
타일 재질과 색상 역할은 유지하고, 24칸을 가로 9×5 및 세로 5×9 테두리로 배치했다.
중앙 배경과 제목은 제거했으며 주사위·미션·타이머를 안쪽 가장자리에 배치했다.
저장된 사용자 좌표는 덮어쓰지 않는다. 새 기본 배치는 OBS 배치에서 명시적으로 적용한다.

별도 최종 검토에서 가로/세로 화면과 투명 중앙 배치를 승인했다.
기존 긴 미션 잘림 및 40칸에서의 다중 말 겹침 지적은 해결됨으로 판정했다.

추가 시각 검토에서 작은 상태 글자, 플레이어 식별, 일반/특수 칸 위계,
카드의 가로 압축 모션, 주사위 크기 맥동을 개선했다. 카드에 실제 앞뒷면과
원근 회전을 사용하고 주사위 카메라는 고정했다. 프로필과 현재 플레이어 헤더,
진행 방향, 효과 아이콘, 임박/완료 타이머를 보강했다.
중앙에는 효과나 배경을 추가하지 않았다.

## 배포 경계

운영 서버 배포, 운영 DB 마이그레이션 실행 및 실제 OBS 방송 합성은 수행하지 않았다.
033 참여 설정 마이그레이션은 저장소 초기화 시 실행되며 기존 게임 설정을 덮어쓰지 않는다.
034 OBS 연결 마이그레이션도 `marble-store.ensureSchema()`가 032/033 뒤에 실행한다.
배포 산출물의 `server/migrations`에 034 파일을 함께 포함해야 한다.
실제 CHZZK/CIME/YouTube 채팅과 후원 수신은 이번 로컬 검증에 포함하지 않았다.
브라우저 검증은 실제 OBS 소스의 오디오/그래픽 환경을 보증하지 않는다.
배포 후 16:9/9:16 브라우저 소스에서 투명도, 프로필 로딩, 재연결을 확인해야 한다.
