# 방송 아바타 v3 적용 기록

2026-10-11. 기존 웹사이트 화면, 기본 무료 캐릭터 팩, 방송 출력 주소의 키, 저장된 캐릭터와 반응을 유지한다. 로컬 앱과 중계 서버 변경이며 새 런타임 의존성은 없다.

## 호환성

- v1/v2 설정은 정규화 후 v3로 저장한다. 변환 전 파일은 `config.json.v3-original`에 보존한다. 더 높은 버전은 기본값으로 덮어쓰지 않고 업데이트가 필요하다고 알린다.
- 구규칙의 채팅 시간은 `legacyAllSteps`, 중단 방식은 `replace`로 유지한다. 기존 이미지의 정사각형 표시도 보존하고 원래 비율은 선택적으로 적용한다.
- 기존 사용자가 `!boost` 등 새 내장 명령 이름을 이미 반응에 사용했다면 사용자 반응을 우선한다. 새 내장 기능이 기존 별칭을 가로채거나 설정 전체를 무효화하지 않는다.
- 새 규칙은 시간을 지정한 한 단계에 연결한다. 달리기·부양은 시간 생략 시 설정된 기본 시간, 최초 기본값은 5초다.
- 입력 시간은 0.1~120초로 제한한다. 상한 조정은 진단에 기록한다. 전체 반응 시간은 별도 상한을 넘으면 실행하지 않는다.
- 실행 중인 반응은 시작 당시 단계와 시간을 사용한다. 저장한 수정은 다음 실행부터 적용한다. 비활성화/퇴장/관리자 취소는 기존과 같이 실행을 중단한다.
- 업데이트는 로컬 앱과 서버에 각각 반영한다. 명령 충돌 메타데이터와 중계 진단은 새 서버가 제공할 때만 활성화된다. 구서버의 기존 이벤트 수신은 유지된다.

## 시간과 동시 실행

이동, 포즈, 말풍선, 크기 표시를 구분한다. `withPrevious`는 직전 단계와 동시에 시작하지만 같은 영역의 동시 실행은 거부한다. 일반 채팅 반응의 새 기본값은 병렬이다. 인사 포즈와 말풍선은 이동을 유지할 수 있다. 이동 중 앉기/춤 같은 충돌 조합은 진단에 남기고 실행하지 않는다.

점프는 물리적 충격 1회다. 단계의 시간은 다음 단계까지의 대기 또는 착지 대기의 최대 시간이다. 도착 대기는 대상이 없어지거나 제한 시간을 넘으면 실패 정책에 따라 중단하거나 다음 단계로 넘어간다. 임시 크기는 개인의 저장된 크기를 바꾸지 않는다.

엔진 물리·예약·스프라이트는 같은 시뮬레이션 시간을 사용한다. 긴 시스템 정지 후 밀린 동작을 한꺼번에 실행하지 않는다. 진행 중 게임은 시스템 대기 중단 결과로 끝나며 승리를 지급하지 않는다. 브라우저가 직접 재생하는 단일 GIF/애니메이션 WebP는 일시정지와 프레임 탐색을 완전히 제어할 수 없다. 정밀한 동기화에는 스프라이트 시트를 사용한다.

## 참여·대상·게임

- 대상은 `@닉네임`, `"공백 있는 닉네임"`, `#참여번호`로 구별한다. 시간과 대상을 함께 받는 반응은 마지막 토큰을 시간으로 읽는다. 예: `!따라 "시청자 이름" 8`.
- `!상호작용 off` / `!targeting off`로 대상 상호작용을 거부하고 `on`으로 복구한다. 방송 전체 허용과 개인 허용을 모두 확인한다.
- `!퇴장`은 숨김, `!입장`은 복귀다. 운영자 시간제 제외와 차단은 입장 명령으로 우회할 수 없다. 차단은 일반 프로필의 90일 정리 대상에서 제외하며 운영자가 해제/기록 삭제한다.
- 정원 정책은 거부, 1분 이상 비활성 참여자 교체, 최대 30명 대기열 중 선택한다. 대기열은 30초 후 만료되며 오래된 명령은 재생하지 않는다.
- 게임 모집을 켜면 `!참가`로 참가한다. 모집 종료 후 추가 참가는 받지 않는다. 모집 시간이 0이면 현재 참여자로 바로 진행한다.
- 달리기는 기본 난수 기반 관전 게임이다. 부스트를 허용한 경우 `!부스트`는 사용자별 설정 횟수만큼만 적용된다. 응원은 `!응원`의 개인 3초 쿨다운을 기준으로 달성 가능한 목표를 검사한다.

## 데이터·진단

연출 팩 백업은 이미지와 설정만 포함하고 출력 키와 개인 기록을 제외한다. 개인 기록 백업/복원은 별도 동의 작업이다. 백업 검사와 압축은 worker에서 수행하고 취소 시 준비 파일만 정리한다. 복원 중 검증/저장 실패는 기존 설정과 파일을 보존한다.

백업 도중 프로세스를 강제 종료하면 준비 디렉터리가 남을 수 있다. 정상 완료·실패·취소 시에는 정리하지만 강제 종료 후 외부 저장 위치까지 자동 탐색·삭제하지는 않는다.

진단은 최근 200건을 메모리에 보관한다. 수신 지연, 설정 리비전, 실행/거절 코드를 제공한다. 내보내기는 원문 채팅·닉네임·키·경로·식별자를 제외한 허용 필드만 담는다. 출력 연결 수는 OBS 프로그램을 식별한 숫자가 아니라 일반 출력 WebSocket 연결 수다.

중계는 방송별 제한된 큐, 퇴장/후원/명령/일반 채팅 우선순위와 방송 간 순환 분배를 사용한다. 일반 채팅만 같은 사용자 단위로 병합한다. 5초 이상 지연된 이벤트를 재생하지 않으며 폐기 수와 대기 시간을 표시한다. 전건 전달을 보장하는 영속 큐가 아니고 포인트 지급·후원 정산의 근거로 사용하지 않는다.

## 검증 범위

- `npm run test:avatars`: 기존 동작과 v3 엔진·저장소·오버레이·중계 집중 회귀 검사 127개 통과.
- `npm run test:avatars:ui`: Playwright 편집기 흐름 검사 11개 통과. 로컬 릴리스 CI에서 Chromium을 설치한 뒤 실행하며 백엔드 배포 검사에는 브라우저를 요구하지 않는다.
- 로컬 프로그램 네트워크/외부 열기/요청 보호 Jest 3개 스위트, 22개 검사 통과.
- 임시 저장소의 실제 편집 화면과 실제 오버레이로 화면·입력 흐름 확인. 운영 DB나 실제 채팅 봇은 실행하지 않는다.
- Windows 배포 패키지 생성은 설치·자동 업데이트·코드 서명·실제 OBS 방송 검증을 대신하지 않는다.

로컬 확인용 설치 파일: `dist/local-program-avatar-v3/AruBot-Local-Program-0.1.0-x64.exe`. NSIS x64 패키징이 성공했고 패키지 내 주요 소스 13개가 작업 파일과 일치한다. 디지털 서명은 없는 상태다. 공개 릴리스·운영 서버 배포·실제 설치는 수행하지 않았다. 정식 릴리스 버전은 기존 CI에서 부여한다.

개발 PC의 Node 22.15.0 격리 엔진 측정: 기본 팩 150명, 600 tick에서 tick p95 약 0.83ms, 최대 약 6.72ms, 전체 스냅샷 71,192바이트였다. OBS/브라우저 렌더링과 인터넷 중계 지연은 포함하지 않으며 방송 PC 성능 보장이 아니다. 이 범위에서는 전체 렌더러 교체나 델타 프로토콜을 추가하지 않았다.

아래 항목은 별도 실제 환경 확인이 필요하다: Windows 설치 업데이트, OBS 출력 2개 재연결, 실제 치지직 이벤트 지연, 방송 PC의 150명 렌더링 비용, 8시간 메모리 관찰. 원 기획의 p95 및 장시간 기준은 측정 전까지 달성했다고 표시하지 않는다. 새 게임, 유료 경제, 에셋 시장, GIF 프레임 변환, Canvas/WebGL 교체는 이번 범위에 포함하지 않는다.
