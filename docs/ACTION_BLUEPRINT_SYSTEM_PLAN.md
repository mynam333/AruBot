# 실행 액션 블루프린트 시스템 기획

## 목표

실행 액션 블루프린트는 명령어, 룰렛, 후원 반응, 예측 베팅, 자동 알림, 수동 버튼에서 호출할 수 있는 노드 기반 방송 자동화 편집기다. 스트리머는 코드 없이 캔버스에서 노드를 배치하고 포트끼리 연결해 채팅 응답, 대기, 조건 분기, OBS/로컬 프로그램/HTTP 실행, 다른 특수 변수 호출까지 한 흐름으로 구성할 수 있어야 한다.

구현 전제:

- 지금 단계에서는 코드 작성보다 기획 완성도를 우선한다.
- 기본 시작 노드는 모든 블루프린트에 반드시 1개 존재한다.
- 시작 노드는 입력 포트가 없고, 종료 노드는 출력 포트가 없다.
- 캔버스는 배경 드래그로 이동하고 마우스 휠 또는 트랙패드 제스처로 확대/축소한다.
- 노드는 드래그로 위치를 옮길 수 있다.
- 출력 포트에서 입력 포트로 드래그해 연결선을 만든다.
- 노드 안의 설정값에는 기존 치환 변수와 실행 액션 특수 변수를 사용할 수 있다.

## 호출 특수 변수

실행 액션은 문구 안에서 다음 형태로 호출한다.

- `${action::액션ID}`: 게시된 실행 액션을 호출한다.
- `${automation::액션ID}`: 자동화 문맥에서 같은 액션을 호출한다.
- `${blueprint::블루프린트ID}`: 블루프린트 단위로 호출한다.
- `${node::노드ID}`: 블루프린트 내부 테스트나 고급 실행에서 특정 노드부터 호출한다. 기본 UI에는 노출하지 않고 디버그/고급 모드에서만 사용한다.

호출 가능 위치:

- 채팅 명령어 응답
- 룰렛 항목 값
- 후원 반응 메시지/액션
- 예측 베팅 정산 후 실행 액션
- 자동 알림
- 관리자 수동 실행 버튼
- 향후 로컬 프로그램 리모컨 버튼

실행 결과 정책:

- 특수 변수 실행은 원래 채팅 응답 텍스트와 분리한다.
- 액션 실패가 명령어, 룰렛, 후원 처리 자체를 중단하면 안 된다.
- 실패는 실행 로그와 관리자 토스트/알림으로 남긴다.
- 채팅에 실패 메시지를 공개할지 여부는 블루프린트별 옵션으로 둔다.

## 캔버스 UX

### 기본 레이아웃

- 좌측: 노드 팔레트, 템플릿, 검색
- 중앙: 블루프린트 캔버스
- 우측: 선택 노드 설정 패널
- 상단 툴바: 저장, 게시, 실행 테스트, 실행 기록, 확대/축소, 캔버스 맞춤
- 하단 상태줄: 저장 상태, 선택 노드 ID, 확대율, 검증 오류 수

### 캔버스 조작

- 배경 드래그: 캔버스 이동
- 마우스 휠: 확대/축소
- `Ctrl` 또는 `Cmd` + 휠: 더 세밀한 확대/축소
- 더블 클릭 배경: 노드 검색 팔레트 열기
- 빈 영역 드래그: 노드 다중 선택 영역 만들기
- `Ctrl` 또는 `Cmd` + 노드 클릭: 개별 노드 선택/해제
- `Shift` + 노드 클릭: 선택 범위 확장
- 선택 노드 드래그: 여러 노드 동시 이동
- `Space` 누른 상태 드래그: 툴 모드와 무관하게 캔버스 이동
- `0`: 100% 보기
- `1`: 전체 노드 맞춤
- `Delete`: 선택 노드/엣지 삭제
- `Ctrl/Cmd + Z`: 실행 취소
- `Ctrl/Cmd + Shift + Z`: 다시 실행

### 노드 드래그

- 노드는 캔버스 좌표 `x`, `y`를 가진다.
- 드래그 중에는 격자 스냅을 선택 옵션으로 제공한다.
- 노드가 겹치면 자동 정렬 제안을 보여준다.
- 시작/종료 노드는 삭제 가능 여부를 제한한다.
  - 시작 노드: 삭제 불가, 1개 고정
  - 종료 노드: 삭제 가능하지만 최소 1개 권장, 없으면 검증 경고

### 포트 연결

- 출력 포트에서 입력 포트로 드래그하면 임시 연결선이 표시된다.
- 호환되지 않는 포트 위에 올리면 빨간 상태와 사유 툴팁을 표시한다.
- 입력 포트에는 여러 입력 연결이 들어올 수 있다.
- 여러 입력이 한 포트에 들어오면 도착 순서대로 실행하거나, 노드 설정에 따라 모두 도착할 때까지 기다린다.
- 출력 포트는 하나의 연결만 나갈 수 있다.
- 같은 출력 포트에서 다른 노드로 다시 연결하면 기존 연결을 교체할지 확인한다.
- 순환 연결은 기본 금지한다.
- 고급 모드에서 반복 노드를 통해 명시적으로만 반복을 허용한다.

### 연결선 표현

- 일반 흐름: 단색 라인
- 조건 성공: 민트 라인
- 조건 실패: 코랄 라인
- 오류 처리: 앰버 라인
- 데이터 전달선: 점선
- 비활성 노드와 연결선: 흐린 색

## 노드/포트 모델

### 노드 공통 필드

- `id`: 내부 고정 ID
- `type`: 노드 타입
- `name`: 사용자 표시 이름
- `position`: `{ x, y }`
- `enabled`: 사용 여부
- `config`: 타입별 설정
- `ports`: 입력/출력 포트 정의
- `timeoutMs`: 노드별 제한 시간
- `retry`: 재시도 정책
- `notes`: 관리자 메모

### 변수와 표현식 공통 규칙

- 모든 노드의 텍스트, 숫자, 조건, JSON, URL, 헤더, 파일명, 오버레이 문구 설정값에는 변수를 사용할 수 있다.
- 지원 변수: 기존 치환 변수, 이벤트 컨텍스트, 앞 노드 출력, 임시 변수, 특수 변수 실행 결과
- 예: `{user.name}`, `{user.points}`, `{roulette.result}`, `{flow.bonusPoint}`, `{node.pick.result}`
- 숫자 입력란도 `1000`, `{user.points}`, `{flow.basePoint} * 2`처럼 계산식을 받을 수 있다.
- 계산식은 안전한 표현식 엔진으로 제한 평가한다.
- 임의 JavaScript 실행은 허용하지 않는다.
- 표현식 미리보기 버튼으로 현재 테스트 컨텍스트 기준 결과를 확인할 수 있어야 한다.

### 포트 타입

- `flow`: 실행 흐름
- `text`: 문자열
- `number`: 숫자
- `boolean`: 참/거짓
- `object`: 구조화 데이터
- `event`: 트리거 이벤트
- `media`: 사운드/이미지/영상 참조

포트 호환 규칙:

- `flow`는 `flow`끼리만 연결한다.
- `text`, `number`, `boolean`은 변환 노드를 통해 다른 타입으로 바꿀 수 있다.
- `object`는 경로 선택 노드로 필요한 값만 꺼낼 수 있다.
- 실행 흐름선과 데이터선은 시각적으로 구분한다.

## 필수 노드

### 시작 노드

역할:

- 블루프린트 실행의 진입점이다.
- 입력 포트가 없다.
- 기본적으로 새 블루프린트 생성 시 자동으로 존재한다.

출력:

- `flow.out`
- `event.context`
- `user`
- `channel`
- `trigger`

설정:

- 호출 허용 위치: 명령어, 룰렛, 후원, 예측, 자동 알림, 수동 실행
- 동시 실행 정책: 병렬 실행, 기존 실행 무시, 새 실행 무시, 큐에 넣기
- 쿨다운: 블루프린트별 실행 간격

### 종료 노드

역할:

- 흐름을 명시적으로 종료한다.
- 출력 포트가 없다.

입력:

- `flow.in`
- `result`

설정:

- 종료 상태: 성공, 실패, 취소
- 로그 메시지
- 실행 결과를 호출자에게 반환할지 여부

## 기본 실행 노드

### 채팅 전송 노드

- CHZZK/CIME 채팅으로 메시지를 보낸다.
- 메시지 입력값에는 치환 변수, 앞 노드 출력값, 임시 변수, 계산식을 사용할 수 있다.
- 기본 전송 대상은 이벤트를 발생시킨 플랫폼이다.
- 이벤트 발생 플랫폼을 알 수 없으면 현재 해당 스트리머가 방송 중인 플랫폼으로만 전송한다.
- 양쪽 플랫폼에서 모두 방송 중인 경우 기본은 트리거 플랫폼 우선, 고급 옵션으로 전체 전송을 선택할 수 있다.
- 오프라인 플랫폼이나 현재 방송 중이 아닌 플랫폼에는 기본 전송하지 않는다.
- 메시지 길이 제한과 플랫폼별 제한을 미리 검증한다.
- 옵션: 관리자 전용 채팅, 실패 시 조용히 무시, 실패 시 오류 분기

### 대기 노드

- 지정한 시간만큼 다음 노드 실행을 늦춘다.
- 초/분 단위를 지원한다.
- 최대 대기 시간은 서버 비용을 고려해 제한한다.
- 긴 대기는 로컬 프로그램 또는 큐 기반 예약으로 전환한다.

### 조건문 노드

- 값 비교로 흐름을 성공/실패 포트로 나눈다.
- 고정된 비교 대상 목록을 제공하지 않는다.
- 좌변과 우변 모두 변수, 문자열, 숫자, 불리언, 계산식을 입력할 수 있다.
- 예: `{user.points}` `>=` `1000`
- 예: `{roulette.result}` `contains` `"꽝"`
- 예: `{flow.rewardCount} * 2` `>` `{donation.amount} / 1000`
- 연산자: 같음, 다름, 포함, 정규식, 초과, 이상, 미만, 이하, 비어 있음, 존재함
- 좌변/우변의 평가 결과 타입을 표시하고, 비교 불가능한 타입은 게시 전 오류로 막는다.

### 임시 변수 생성/수정 노드

- 흐름 안에서 임시 변수를 만들거나 기존 임시 변수를 수정한다.
- 예: `rewardName`, `bonusPoint`, `soundName`
- 뒤 노드에서 `{flow.rewardName}` 같은 형태로 사용할 수 있다.
- 문자열 결합, 숫자 계산, 반올림, 최소/최대, 랜덤 숫자, 배열 길이, JSON 경로 읽기 같은 안전한 계산을 지원한다.
- 연산 모드:
  - 값 대입
  - 숫자 더하기/빼기/곱하기/나누기
  - 문자열 이어붙이기
  - 배열에 추가
  - 객체 필드 설정
  - JSON 경로에서 값 추출
- 출력 포트로 변경된 변수 값을 내보낸다.

### 변수 읽기 노드

- 기존 치환 변수나 이벤트 컨텍스트 값을 읽는다.
- 예: `{user.name}`, `{user.points}`, `{attendance.streak}`, `{roulette.result}`, `{donation.amount}`
- 출력 포트 타입은 변수 정의에 따라 자동 결정한다.

### 특수 변수 실행 노드

- 다른 특수 변수 또는 게시된 액션을 실행한다.
- 예: `${action::...}`, `${blueprint::...}`, `${automation::...}`
- 자기 자신 또는 현재 블루프린트로 이어지는 재귀 호출은 기본 금지한다.
- 최대 호출 깊이를 둔다.
- 실행 결과를 다음 노드로 전달할 수 있다.

### N회 반복 노드

- 지정한 횟수만큼 연결된 흐름을 반복 실행한다.
- 반복 중에는 `true` 출력 포트로 흐름이 이어진다.
- 반복이 모두 끝나면 `false` 출력 포트로 이어진다.
- 현재 반복 번호는 `{loop.index}`로 제공한다.
- 전체 반복 횟수는 `{loop.total}`로 제공한다.
- 반복 횟수 입력값에는 숫자, 변수, 계산식을 사용할 수 있다.
- 최대 반복 수를 제한해 서버 부하와 실수로 인한 과도 실행을 막는다.
- 각 반복 사이 대기 시간을 선택할 수 있다.

### 랜덤 분기 노드

- 여러 출력 후보 중 하나를 무작위로 선택한다.
- 후보별 가중치 또는 확률을 지정할 수 있다.
- 확률 입력값에도 변수와 계산식을 사용할 수 있다.
- 선택된 후보 이름, 인덱스, 확률을 출력값으로 제공한다.
- 방송 이벤트 추첨, 랜덤 사운드, 랜덤 OBS 연출에 사용한다.

### 로그 노드

- 실행 로그에 사용자 지정 메시지를 남긴다.
- 디버깅 중에만 활성화할 수 있다.
- 공개 채팅에는 노출하지 않는다.

## 방송 자동화 노드

### OBS 노드

- 장면 전환
- 소스 표시/숨김
- 필터 켜기/끄기
- 브라우저 소스 URL 변경
- 텍스트 소스 내용 변경
- 리플레이/녹화 시작/중지

### HTTP 요청 노드

- GET/POST/PUT/PATCH/DELETE
- 헤더와 바디 템플릿 지원
- 민감 헤더는 로컬 저장 또는 서버 비밀 저장소를 사용한다.
- 응답 JSON을 다음 노드로 전달할 수 있다.

### WebSocket 노드

- 지정 연결로 메시지를 보낸다.
- JSON 템플릿을 지원한다.
- 응답 대기 여부를 선택한다.

### UDP 노드

- 로컬 프로그램 모드에서만 기본 제공한다.
- 조명, 사운드보드, 일부 로컬 툴 연동에 사용한다.

### 사운드 재생 노드

- 서버 호스팅 사운드 또는 로컬 프로그램 사운드를 재생한다.
- 서버 호스팅은 사용자별 10MB 제한을 따른다.
- 더 큰 파일은 로컬 프로그램 사용을 안내한다.

### TTS 노드

- 후원 전용이 아니라 자동화용 방송 연출 노드로 제공한다.
- 브라우저 TTS, 로컬 프로그램 TTS, 향후 외부 TTS provider를 구분한다.
- 말할 내용을 직접 입력할 수 있다.
- 말할 내용에는 변수, 앞 노드 출력, 계산식을 사용할 수 있다.
- 속도, 음높이, 음성, 볼륨 설정을 가진다.
- 이벤트 플랫폼과 무관하게 설정된 출력 장치 또는 로컬 프로그램에서 재생한다.

### 오버레이 표시 노드

- OBS 브라우저 오버레이에 텍스트, 이미지, 진행바, 카운트다운, 뱃지, 룰렛 결과를 표시한다.
- 표시 내용에는 모든 변수를 사용할 수 있다.
- 표시 방식:
  - 즉시 표시 후 자동 숨김
  - 지정 시간 동안 유지
  - 다음 오버레이 노드가 숨길 때까지 유지
  - 진행바/카운트다운처럼 시간에 따라 갱신
- 위치 프리셋: 상단, 중앙, 하단, 좌측, 우측, 사용자 지정
- 애니메이션 프리셋: 페이드, 슬라이드, 팝, 스케일, 흔들림
- 출력값으로 표시 ID를 제공해 뒤 노드에서 숨김/수정할 수 있다.

### T.I.T.S 노드

- 로컬 프로그램을 통해 T.I.T.S API와 통신한다.
- 모델/트리거 목록을 자동으로 불러와 드롭다운으로 선택한다.
- 트리거 실행, 강도, 지속시간, 대상 설정을 지원한다.

### VTube Studio 노드

- 로컬 프로그램을 통해 VTube Studio API와 통신한다.
- 모델, 핫키, 파라미터 목록을 자동으로 불러온다.
- 핫키 실행, 파라미터 변경, 아이템 표시/숨김을 지원한다.

## 외부 이벤트 트리거

### 투네이션 이벤트

- 투네이션은 알림 실행을 사용자가 임의로 보낼 수 없으므로 실행 노드를 제공하지 않는다.
- 투네이션에서 들어온 후원/알림 이벤트를 블루프린트 시작 트리거로 받는 범위까지만 기획한다.
- 투네이션 이벤트 데이터는 `{donation.amount}`, `{donation.message}`, `{donation.nickname}` 같은 변수로 노드에서 사용할 수 있다.

## 참여형 방송 노드

실사용 매력이 높고 기존 아루봇 기능과 바로 연결되는 노드:

- 포인트 조회 노드: 특정 시청자의 현재 포인트를 읽어 다음 노드로 넘긴다.
- 포인트 지급/차감 노드: 특정 시청자에게 포인트를 지급하거나 차감한다. 금액에는 변수와 계산식을 사용할 수 있다.
- 포인트 충분 여부 노드: 필요한 포인트와 현재 포인트를 비교해 성공/실패로 분기한다.
- 포인트 랭킹 조회 노드: 상위 N명 또는 특정 범위의 포인트 순위를 읽는다.
- 포인트 적립 제외 확인 노드: 특정 UUID가 포인트 적립 제외 대상인지 확인한다.
- 룰렛 목록 조회 노드: 실행 가능한 룰렛 목록을 읽어 선택 UI나 다음 노드에 넘긴다.
- 룰렛 실행 노드: 기존 룰렛을 실행하고 결과를 다음 노드로 넘긴다.
- 룰렛 결과 비교 노드: 룰렛 결과 라벨/값/액션 값을 비교해 분기한다.
- 룰렛 결과 표시 노드: 룰렛 결과를 채팅 또는 오버레이에 표시한다.
- 룰렛 항목 추가/수정 노드: 방송 중 임시 이벤트용 룰렛 항목을 추가하거나 가중치를 조정한다. 위험도가 있어 고급 권한으로 둔다.
- 예측 베팅 열기 노드: 질문과 선택지를 받아 예측 베팅을 연다.
- 예측 베팅 정산 노드: 선택 결과를 받아 포인트를 정산한다.
- 출석 체크 조회 노드: 시청자의 연속/누적 출석일을 읽는다.
- 쿨다운 확인 노드: 유저별/블루프린트별 쿨다운을 검사한다.
- 랜덤 분기 노드: 확률 기반으로 여러 출력 중 하나를 선택한다.
- N회 반복 노드: 반복 중 `true` 포트로 계속 흐르고, 반복 완료 후 `false` 포트로 흐른다.
- 합류 노드: 여러 흐름을 하나로 모은다.
- 오류 처리 노드: 앞 노드 실패 시 대체 흐름을 실행한다.
- 관리자 확인 노드: 실행 전 관리자 승인 대기 상태를 만든다.
- 채팅 투표 대기 노드: 일정 시간 동안 채팅 투표를 받고 결과를 출력한다.
- 타이머 노드: 방송 중 일정 시간 뒤 실행하거나 반복 실행한다.
- 오버레이 표시 노드: OBS 브라우저 오버레이에 텍스트/이미지/진행바를 띄운다.
- 오버레이 숨김/수정 노드: 표시 중인 오버레이를 숨기거나 문구/진행률을 수정한다.
- 클립/하이라이트 마커 노드: 방송 중 기억할 순간을 로그로 남긴다.

1차 구현 우선순위:

1. 시작, 종료, 채팅, 대기, 조건문
2. 변수 읽기, 임시 변수 생성/수정, 특수 변수 실행
3. 포인트 지급/차감, 룰렛 실행
4. 랜덤 분기, N회 반복, 오버레이 표시
5. OBS, 사운드, TTS
6. HTTP, WebSocket, UDP
7. T.I.T.S, VTube Studio
8. 오류 처리, 합류, 관리자 확인

## 블루프린트 검증 규칙

저장 전 경고:

- 종료 노드가 없다.
- 연결되지 않은 노드가 있다.
- 필수 설정값이 비어 있다.
- 메시지가 플랫폼 제한 길이를 넘는다.
- 대기 시간이 제한보다 길다.

게시 전 오류:

- 시작 노드가 없다.
- 시작 노드가 2개 이상이다.
- 시작 노드에 입력 포트가 있다.
- 종료 노드에 출력 포트가 있다.
- 순환 연결이 있다.
- 존재하지 않는 노드를 참조하는 엣지가 있다.
- 포트 타입이 맞지 않는다.
- 하나의 출력 포트에서 여러 연결이 나간다.
- 삭제된 특수 변수를 호출한다.
- 권한이 없는 자동화 연결을 참조한다.

## 실행 정책

### 큐

- 서버 부담을 줄이기 위해 기존 자동화 큐를 재사용한다.
- 짧은 노드는 서버에서 즉시 실행한다.
- 로컬 프로그램, OBS, VTube Studio, T.I.T.S, 로컬 파일이 필요한 노드는 로컬 에이전트 큐로 위임한다.
- 긴 대기와 반복 실행은 큐 작업으로 분리한다.

### 제한

- 사용자별 분당 실행 수 제한
- 블루프린트별 동시 실행 수 제한
- 노드별 타임아웃
- 특수 변수 호출 깊이 제한
- 반복 노드 최대 반복 수 제한
- HTTP/WebSocket 외부 요청 도메인 제한 옵션

### 실패 처리

- 노드 실패 시 기본은 블루프린트 실패 종료다.
- 각 노드는 `실패 시 계속`, `실패 포트로 이동`, `즉시 종료` 중 하나를 고를 수 있다.
- 실패 포트를 둔 노드는 오류 처리 흐름을 만들 수 있다.
- 실패 내용은 실행 로그에 남기고 공개 채팅에는 기본 노출하지 않는다.

## 저장/게시 UX

- 편집 중에는 자동 저장 초안으로 저장한다.
- 게시 버튼을 누르면 검증을 통과한 스냅샷을 버전으로 고정한다.
- 특수 변수는 게시된 버전만 실행한다.
- 초안 변경은 현재 방송 중 실행 중인 버전에 영향을 주지 않는다.
- 이전 버전으로 되돌리기 기능을 제공한다.
- 게시 전 테스트 실행은 초안 버전으로 실행할 수 있다.

## 테스트 UX

- 수동 실행 버튼으로 샘플 컨텍스트를 넣어 테스트한다.
- 테스트 컨텍스트 프리셋:
  - 채팅 명령어 호출
  - 룰렛 당첨
  - 후원 반응
  - 예측 베팅 종료
  - 출석 체크
- 테스트 중 실행된 노드는 순서대로 강조한다.
- 각 노드의 입력/출력/실행 시간을 우측 로그 패널에 표시한다.
- 로컬 프로그램이 필요한 노드는 연결 상태가 없으면 테스트를 건너뛰고 안내한다.

## 권한과 보안

- 민감한 API 키는 노드 설정값에 평문 저장하지 않는다.
- 서버 저장이 필요한 키와 로컬 저장이 나은 키를 연결 타입별로 구분한다.
- 로컬 프로그램 전용 연결은 서버에서 실행하지 않는다.
- HTTP 노드는 내부망/로컬 주소 호출을 기본 차단하고 로컬 프로그램 모드에서만 허용한다.
- 공개 특수 변수 ID는 추측하기 어렵게 생성한다.
- 블루프린트 실행 URL은 별도 토큰 없이 공개하지 않는다.

## 추천 템플릿

초기 제공하면 좋은 템플릿:

- 룰렛 당첨 시 채팅 안내 + OBS 오버레이 표시 + 사운드 재생
- 후원 금액별 TTS + 포인트 지급 + OBS 연출
- 예측 베팅 종료 후 결과 채팅 + 우승 선택지 오버레이
- 출석 첫 채팅 시 환영 메시지 + 포인트 지급
- 특정 명령어로 VTube Studio 핫키 실행
- 관리자 버튼으로 방송 시작 준비 시퀀스 실행
- 채팅 투표 결과에 따라 장면 전환

## 아직 결정할 사항

- 캔버스 라이브러리는 React Flow 계열을 사용할지, 커스텀 구현할지 결정해야 한다.
- 모바일에서는 전체 편집을 지원할지, 보기/테스트/간단 수정만 지원할지 정해야 한다.
- 긴 대기 노드의 최대 허용 시간을 정해야 한다.
- HTTP 노드의 외부 도메인 허용 정책을 정해야 한다.
- 특수 변수 실행 노드에서 다른 블루프린트 호출 결과를 어디까지 반환할지 정해야 한다.
- N회 반복 노드의 기본 최대 반복 수와 관리자 상한을 정해야 한다.
