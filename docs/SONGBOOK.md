# 노래책

- 관리 화면: `/songbook`
- 시청자 화면: `/c/<공개 채널 UID>/songbook`
- 기존 영상 후원/BGM과 독립적인 **스트리머 가창 신청 목록**입니다. 자동 영상 재생이나 포인트 차감은 없습니다.

## 곡 관리

제목과 가수는 필수입니다. YouTube 영상 주소, 키 조절(-12~+12 반음), 난이도 5단계, 태그 12개, 공개 메모와 비공개 연습 메모를 저장합니다. 키는 가창 정보이며 음원을 변조하지 않습니다. 썸네일은 영상 ID로 표시하며 YouTube 검색 API를 호출하지 않습니다.

제목/가수/태그 검색, 태그/난이도 필터, 제목/가수/최근 등록순 정렬과 페이지 이동을 지원합니다. 곡은 채널당 최대 5,000개입니다. 곡별로 공개 여부와 신청 가능 여부를 따로 지정할 수 있습니다.

## 신청

노래책 열람은 로그인 없이 가능합니다. 신청과 내 신청 취소는 로그인이 필요합니다. 초기에는 신청 접수가 꺼져 있으며 관리 화면에서 `노래 신청 받기`를 켭니다. 인당 대기/진행 한도는 1~10곡, 채널 대기/진행 목록은 최대 500개입니다. 같은 시청자의 같은 곡 중복 신청과 10초 이내 연속 신규 신청을 제한합니다.

상태는 대기 → 부르는 중 → 완료입니다. 관리자는 거절할 수 있고 시청자는 자기 대기 신청만 취소할 수 있습니다. 관리자는 한 번에 한 곡만 부르는 중으로 설정할 수 있습니다. 삭제한 곡의 대기 신청은 취소되며 이미 진행한 신청의 곡 정보는 스냅샷으로 보존됩니다. 신청 목록은 화면이 보일 때 10초마다, 곡 목록/접수 설정은 30초마다 갱신됩니다.

## 보안과 배포

- `songbook:read` / `songbook:write` 권한을 기존 봇 관리자 시스템과 연결했습니다. 사이트 관리자와 소유자는 기존 권한 정책을 따릅니다.
- 공개 API는 비공개 메모, 소유자/시청자 계정 ID를 포함하지 않습니다. 내 신청 API는 실제 로그인 사용자만 조회합니다.
- 동일 채널 쓰기는 DB 설정 행을 잠가 직렬화합니다. 신청 키로 재시도를 멱등 처리하며 곡 수정/삭제는 revision 충돌을 검사합니다.
- `server/migrations/027_songbook.sql`은 첫 노래책 접근 시 기존 DB 연결을 사용해 자동 적용됩니다. DB 계정에 테이블 생성 권한이 필요합니다. 수동 마이그레이션으로 먼저 적용해도 됩니다.
- 새 패키지나 API 키는 필요 없습니다. 프런트엔드와 백엔드를 함께 배포해야 합니다.

## 검증

`npx jest tests/songbook.test.js --runInBand`에서 입력 검증, 공개 정보 제한, 요청 상태 전이, 소유권, 쓰기 잠금과 재시도 동작을 점검합니다. DB 쿼리 목을 사용하므로 운영 DB 마이그레이션 실행 자체를 증명하지는 않습니다.
