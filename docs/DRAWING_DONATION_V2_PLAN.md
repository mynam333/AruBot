# 그림 후원 V2: 원본 보존, 벡터 브러시, 자연스러운 재생

작성일: 2026-09-29

상태: V2 구현 및 로컬 집중 검증 완료. 배포와 운영 OBS/실제 포인트 차감 연동 확인은 아직 수행하지 않았다. 아래는 설계와 개편 전 진단 기록이며, 실제 구현 파일·검증·배포 조건은 [구현 기록](D:/AruBot/docs/DRAWING_DONATION_V2_IMPLEMENTATION.md)을 기준으로 한다.

최종 사용자 결정: **획 사이 대기는 재생 시간에서 전부 제외한다. 최근 색상은 컬러피커의 선택 이력이 아니라 실제 획·도형·채우기에 사용한 색을 최근 사용 순서로 기록한다.**

추가 구현: Shift 직선·1:1 도형, 픽셀 선택 영역의 8개 크기 핸들·회전·Alt 복제·Ctrl 다중 꼭짓점 왜곡, 변형 제스처 전체의 시간 기록/재생, 선/채움의 독립 색상·불투명도, 상하/좌우 동시 대칭. 아래 초기 설계와 달리 선택 변형도 최종 상태뿐 아니라 입력 시각별 프레임을 보존한다.

## 1. 결론

**시청자가 보면서 그린 그림을 원본으로 삼고, 같은 원본을 편집기·검수 화면·OBS에서 재생한다. 선은 벡터 윤곽으로 만들고, 재질이 필요한 붓만 그 윤곽 안에 고정된 질감을 입힌다.**

브러시 개수를 늘리는 일보다 먼저 해결해야 하는 것은 다음 다섯 가지다.

1. 그리는 중, 펜을 뗀 직후, 리플레이 종료 후의 선 모양과 농도가 달라지지 않는다.
2. 제출 시 서버가 점을 삭제하거나 붓을 대체해 시청자가 본 그림을 바꾸지 않는다.
3. 입력 시간을 원본에 보존하되 획 사이 대기는 재생에서 제외한다. 획 내부의 빠르고 느린 구간 비율은 배속하더라도 유지한다.
4. 완성본은 무손실 이미지로도 보존한다. 작은 목록 썸네일을 원본 대신 사용하지 않는다.
5. 새 그림의 기본 불투명도는 100%다. 커서는 그림 위에 표시되고 그릴 위치를 가리지 않는다.

구현 범위는 **공통 엔진 + 원본 보존 + 정확한 재생 + 브러시 8종과 지우개 + 기본 편의 기능 + 레이어·도형·채우기·선택 변형·대칭·도장**이다.

## 3. '그린 그대로'의 보존 계약

### 반드시 보존하는 것

위치, 화면 비율, 선의 곡선과 두께, 색, 불투명도, 압력 변화, 질감 배치, 획 순서, 지우개 결과, 입력 시간, 적용한 브러시 설정을 보존한다. 나중에 기본 브러시 설정이 바뀌어도 이미 보낸 그림은 바뀌지 않아야 한다.

여기서 원본은 사용자가 실제 편집 화면에서 확인한 **동일한 문서 상태**다. 보정된 선을 보여 주고 보정 전 데이터를 다른 방식으로 재해석하거나, 제출할 때만 더 예쁘게 다듬는 처리는 하지 않는다.

### 원본 패키지

| 구성 | 역할 | 보존 방식 |
| --- | --- | --- |
| 입력과 시간 데이터 | 수정, 원본 속도 재생, 검증 | 좌표·압력·시간을 손실 없이 직렬화 |
| 확정 벡터 경로와 브러시 설정 | 그려진 윤곽을 재현 | 경로 생성 버전, 재질 버전, seed 포함 |
| 완성본 PNG | 시청자가 승인한 완성 결과의 기준 | 투명 배경, 기준 해상도, 무손실 |
| 작은 WebP 썸네일 | 대기열 목록을 빠르게 표시 | 파생 캐시로만 사용 |
| manifest | 어떤 문서·이미지·렌더러가 한 묶음인지 확인 | schemaVersion, revision, 각 파일 hash |

PNG에는 방송 영상, 커서, 선택 테두리, 안내선, 체커보드가 들어가지 않는다. 투명한 그림 레이어만 저장한다. 벡터 원본을 PNG로 대체하지도 않는다.

### 기준 해상도와 표시

- 기본 16:9 문서는 논리 해상도 1920×1080을 기준으로 한다. 다른 비율은 같은 원칙으로 별도 규격을 지정한다.
- 편집과 저장은 같은 문서 좌표·색상 기준(sRGB)을 사용한다. DPR과 화면 확대율은 표시 변환일 뿐 붓 계산에 들어가지 않는다.
- 작은 화면에서는 기준 그림을 축소해서 보여 준다. OBS의 화면 비율이 다르면 종횡비를 유지하여 맞추고, 임의로 가로·세로를 따로 늘리지 않는다.
- 픽셀 단위로 보존하는 대상은 기준 해상도의 완성 PNG다. 서로 다른 모니터, OS 색 관리, 확대 배율까지 화면상 모든 픽셀이 같다는 뜻은 아니다.
- Canvas의 기기별 안티앨리어싱까지 벡터 데이터만으로 완전히 같다고 보장할 수는 없다. 완성본은 원본 PNG를 표시하고, 재생 중 선의 윤곽·질감·농도는 동일 엔진의 검증 대상으로 삼는다.
- 모든 기기의 재생 프레임까지 픽셀 단위 동일성이 필요하다면, 무손실 타일 기반 렌더링 기록이 추가로 필요하다. 저장량이 커지는 별도 기능이며 벡터 전환만으로 해결됐다고 주장하지 않는다.

### 저장·전송 절차

1. 제출을 누르면 문서 revision을 고정한다. 아직 진행 중인 획은 공통 엔진으로 끝내고, 이 확정 상태를 제출 미리보기로 보여 준다.
2. 원본 문서와 기준 PNG를 같은 확정 상태에서 만든다. 바이너리 이미지는 JSON의 base64 대신 별도 업로드한다.
3. 서버는 형식, 권한, 크기, 복잡도, 버전, 저장 자산을 검증한다. 범위를 벗어난 좌표나 알 수 없는 붓을 다른 값으로 고쳐 수락하지 않는다.
4. 서버가 재계산한 비용과 수락한 문서 revision을 묶는다. 견적 이후 가격이 달라지면 자동 차감하지 않고 다시 확인받는다.
5. 모든 원본 자산이 안전하게 저장된 뒤 후원 레코드와 차감을 확정한다. 기존 durable job/환불 경로를 활용하되 재시도·부분 실패를 점검한다.
6. 응답에는 수락한 revision과 hash를 포함한다. 성공 응답과 일치해야만 로컬 초안을 지운다.
7. 검수, OBS, 이벤트 로그 재생은 같은 immutable 원본 패키지를 읽는다. 나중에 새 브러시로 자동 변환하지 않는다.

hash는 저장·전송 손상 확인 수단이지, 클라이언트가 보낸 PNG와 벡터가 같은 그림이라는 증거 자체는 아니다. 서버가 허용된 렌더러로 검증용 결과를 생성하거나 별도 렌더 작업에서 일치성을 확인해야 한다. 이 작업은 격리된 큐에서 처리하고 일반 API 프로세스를 막지 않는다. 유의미한 불일치는 차감·자동 승인을 보류하고 원본을 유지한다. 작은 안티앨리어싱 차이와 윤곽·색·내용의 차이는 구분한다.

원본 이미지/문서가 누락되거나 지원하지 않는 버전이면 썸네일 또는 기본 펜으로 조용히 대체하지 않는다. 재시도 또는 명시적인 오류 상태로 둔다.

## 4. 벡터 형태로 그리는 방법

### 권장: 벡터 윤곽 + 재질 레이어 + Canvas 2D 출력

입력은 위치 샘플로 받지만, 화면에 샘플마다 동그라미를 찍을 필요는 없다. 입력을 매끈한 중심 곡선으로 만들고, 그 주위에 두께를 가진 연속 윤곽을 생성하여 채운다.

```text
입력 좌표·압력·시간
    -> 문서 좌표 변환
    -> 제한적인 선 보정과 곡선 생성
    -> 두께를 가진 벡터 윤곽
    -> 붓별 색·재질·합성
    -> 편집 / 검수 / OBS 공통 출력
```

펜, 마커, 붓펜의 윤곽은 벡터로 유지한다. 크레용, 연필의 입자나 에어브러시의 부드러운 분포까지 모두 작은 SVG 도형으로 만들지는 않는다. 그런 도구는 벡터 영역과 결정적 재질 마스크를 조합한다. 사용자가 원하는 것은 정밀하고 매끈한 그림이지, 반드시 DOM 전체를 SVG로 만드는 것은 아니다.

Canvas의 `Path2D`는 경로를 보관하여 재사용할 수 있고 곡선 경로도 지원한다. 따라서 기존 Canvas 기반 화면을 유지하면서 벡터 경로를 적용할 수 있다. [MDN Path2D](https://developer.mozilla.org/en-US/docs/Web/API/Path2D)

압력 기반 획 윤곽 생성에는 `perfect-freehand`를 우선 검토한다. 이 라이브러리는 입력에서 획 외곽선을 생성하고 Canvas/SVG로 출력할 수 있으며 MIT 라이선스다. 다만 기본 옵션만 적용해서 일치 문제가 해결된다고 보지는 않는다. 미완료/완료 옵션, 끝 가늘어짐, 입력 보정이 이미 표시한 선을 바꾸는지 작은 시제품에서 확인한 후 버전을 고정한다. [공식 저장소](https://github.com/steveruizok/perfect-freehand)

### 선 보정의 원칙

- 기본 보정 강도는 낮게 둔다. 사용자가 그린 모서리, 글씨, 작은 원을 둥글게 뭉개지 않는다.
- 강한 안정화는 선택 기능으로 제공한다. 결과를 펜을 뗀 다음에만 보정하지 않는다.
- 완성된 과거 구간은 고정한다. 입력을 받는 짧은 끝부분만 갱신하며 그 한계를 명시한다.
- 끝 가늘어짐을 '현재 배열 길이의 몇 %'로 계산하지 않는다. 실제 압력과 고정된 문서 거리 기준으로 계산한다.
- 손을 떼는 순간 전체 획을 다시 피팅하지 않는다. 시작·중간·종료가 같은 경로 생성 규칙을 따른다.
- 동일 위치 탭, 짧은 획, 급회전, 교차, 자기 겹침을 정상적인 입력으로 처리한다.
- 마우스의 가상 압력을 사용한다면 문서 거리/입력 시간으로 계산한다. 디스플레이 픽셀 수나 재생 배속으로 두께를 계산하지 않는다.

### 점무늬가 보이지 않게 하는 방법

매끈한 도구는 원형 stamp를 이어 붙이지 않고 연결된 윤곽을 한 획으로 합성한다. 크레용의 작은 입자는 '선이 끊기는 결함'이 아니라 재질 내부의 의도된 빈틈이어야 한다.

에어브러시는 특성상 연속 농도 누적이 필요하다. 내부 계산에 작은 구간을 사용하더라도 간격과 누적량을 문서 거리·원본 시간에 고정하여 프레임률에 따른 구슬 모양이나 농도 차이가 보이지 않게 한다.

## 5. 그리는 중과 완성 후를 같게 만드는 공통 엔진

화면마다 브러시 함수를 복사하지 않고 다음 책임을 공유한다.

| 책임 | 설명 |
| --- | --- |
| Document | 문서 비율, 획, 브러시 설정, 버전, 레이어 |
| Input | 실제 입력을 정규 문서 이벤트로 변환 |
| Geometry | 보정된 중심선과 고정된 획 윤곽 생성 |
| Material | 색, 종이 결, 붓결, 농도, 지우개 합성 |
| Timeline | 원본 시간과 방송 시간을 변환 |
| Renderer | 임의 시점·완성본·미리보기를 동일 규칙으로 출력 |
| Pricing | 문서 내용에서 비용을 계산하는 순수 함수 |

### 가장 중요한 구현 규칙

1. `render(document, time)`과 완성본 렌더링이 동일한 문서·기하·재질을 사용한다.
2. 부분 배열을 새로운 획처럼 넘겨 seed, taper, 압력을 다시 시작하지 않는다.
3. 질감은 `strokeId + seed + 재질 버전 + 문서 위치/누적 거리`로 결정한다. 프레임 번호와 부분 배열 인덱스는 쓰지 않는다.
4. 완성된 획은 캐시하고 현재 획만 별도 작업 표면에 그린다. 불투명도는 한 획을 합성할 때 적용하여 부분 갱신 때문에 진해지지 않게 한다.
5. 의도적으로 겹칠수록 진해지는 재질은 별도의 누적 규칙을 쓴다. 한 프레임에서 같은 구간을 두 번 계산해서 생기는 진해짐과 구분한다.
6. 펜을 뗄 때 작업 표면을 확정 상태로 옮기며 다른 브러시 함수로 다시 그리지 않는다.
7. 재생 마지막 프레임과 유지 화면의 기준 상태가 같다. 마지막에 손실 썸네일이나 다른 모양의 렌더링 결과로 교체하지 않는다.
8. 리사이즈, 중간 시점 탐색, 새로고침 후 재생에도 같은 결과가 나와야 한다.

Canvas의 합성 기능을 활용해 획 마스크와 재질을 조합하고 지우개를 적용한다. 구체적인 합성 순서는 공통 엔진 내부에서만 관리한다. [MDN 합성 연산](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/globalCompositeOperation)

### 실제 난도가 높은 부분

기성 윤곽 생성기를 매 프레임 전체 입력에 적용하면 과거 선까지 달라질 수 있다. 끝부분 처리와 압력 곡선을 안정화하는 시제품을 첫 번째 작업으로 둔다. 시제품 통과 전에는 여러 브러시를 동시에 구현하지 않는다.

최종 그림 위에 넓은 마스크를 움직이는 재생도 기본 해법으로 쓰지 않는다. 선이 교차하면 아직 그리지 않은 미래 구간까지 먼저 드러날 수 있다. **시간 순서가 있는 경로 구간**을 기준으로 공개해야 한다.

## 6. 실제 그리기 속도를 재현하는 방식

### 위치 데이터와 시간 데이터를 분리하지 않는다

각 입력에 `x, y, pressure, time`을 기록하고, 획의 시작과 종료도 기록한다. `performance.now()` 계열의 단조 시간과 이벤트 시간을 같은 기준으로 맞춘다. 여러 입력을 한 프레임에서 처리하더라도 모든 입력에 같은 프레임 시각을 부여하지 않는다.

지원 브라우저에서는 `getCoalescedEvents()`로 합쳐진 입력을 가져오고, 미지원 환경은 일반 pointer 이벤트로 동작하게 한다. 이 API는 지원 범위와 HTTPS 조건을 확인해야 한다. [MDN 입력 샘플 수집](https://developer.mozilla.org/en-US/docs/Web/API/PointerEvent/getCoalescedEvents)

### 시간에서 곡선 위치로 변환

곡선의 단순 진행률을 일정 속도로 증가시키지 않는다. 입력 순서를 따라 `원본 시간 -> 곡선의 누적 길이` 대응표를 만들고 현재 시각 사이를 보간한다.

예를 들어 같은 길이의 두 선을 각각 1초와 3초에 그렸다면, 2배속 재생에서는 각각 0.5초와 1.5초가 걸려야 한다. 두 선을 모두 1초씩 보여 주는 재생은 요구사항을 만족하지 않는다.

```text
T = 첫 입력부터 마지막 펜 떼기까지의 원본 시간
L = 스트리머가 설정한 최대 재생 시간
k = max(1, T / L)
재생 시간 = (원본 시간 - 시작 시간) / k
```

- 모든 구간에 같은 배속 `k`를 적용한다. ease-in/ease-out을 추가하지 않는다.
- 점 개수 비율이나 경로 길이 비율로 시간을 대신하지 않는다.
- 베지어 곡선의 파라미터는 거리와 같지 않으므로 구간별 길이 표를 사용한다.
- 같은 위치에서 멈춘 시간도 유지한다. 에어브러시의 누적은 원본 시간으로 계산하며 배속해도 완성 농도가 바뀌지 않는다.
- 화면 갱신은 `requestAnimationFrame`의 실제 경과 시간에 맞춘다. 30/60/144Hz마다 재생 속도가 달라지지 않게 한다. [MDN 애니메이션 시간](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)

### 재생 옵션

| 모드 | 동작 | 권장 |
| --- | --- | --- |
| 그린 구간 재생 | 획 사이 대기를 전부 제거하고 획 내부 속도 비율만 유지하여 균일 배속 | 기본·고정 |
| 원속도 미리보기 | 획 사이 대기를 제외한 실제 그리는 구간을 1배속으로 확인 | 편집기 보조 기능 |

기존 120ms 점 간 시간 제한은 V2 기본 모드에서 제거한다. 배속이 매우 높아져 알아보기 어려우면 제출 미리보기에서 실제 방송 배속과 길이를 보여 준다. 동의 없이 일부 획을 생략하거나 마지막에 전체 그림을 갑자기 완성하지 않는다.

실수로 그렸다가 실행 취소한 획은 제출 문서와 리플레이에서 제외한다. 남아 있는 획의 입력 시간은 보존하고, 삭제된 작업 때문에 생긴 공백도 재생에서는 제외한다.

## 7. 브러시 구성과 질감 사양

모든 신규 브러시는 사용자 불투명도 100%로 시작한다. 이미 저장된 그림의 alpha는 수정하지 않는다. 다른 붓을 선택해도 현재 사용자가 조절한 전역 불투명도는 유지하고, 새 문서 및 설정 초기화 시 100%로 돌아간다.

불투명도와 재질은 별개다. 연필의 종이 빈틈이나 에어브러시 가장자리까지 불투명한 덩어리로 만들지는 않는다. 형광펜·수채화의 재질 농도는 해당 도구의 별도 속성으로 명확하게 다룬다.

| 도구 | 목표 질감 | 구현 방향 | 추가 조절 | 단계 |
| --- | --- | --- | --- | --- |
| 정밀 펜 | 균일하고 선명한 윤곽, 깔끔한 글씨 | 연결된 곡선과 매끈한 cap/join, 기본 일정 두께 | 선 보정 | 1차 |
| 연필 | 가느다란 흑연·색연필 결, 압력에 따른 밀도 | 벡터 윤곽 안에 문서 고정 미세 입자, 뭉친 원형 점 제거 | 단단함/질감 | 1차 신규 |
| 크레용 | 왁스가 종이 돌기에 걸리는 넓고 거친 결 | 일정한 종이 결 마스크와 압력 기반 피복, 무작위 점무늬 의존 제거 | 거칠기 | 1차 개선 |
| 먹붓 | 유려한 굵기 변화, 날렵한 끝, 길이 방향 붓결 | 압력 기반 윤곽 + 진행 방향 결, 불필요한 번짐·그림자 제거 | 마른 붓 정도 | 1차 개선 |
| 평붓 마커 | 사선 펜촉의 납작하고 또렷한 면 | 일정 각도 펜촉의 연속 윤곽, 점선 방식 제거 | 펜촉 각도 | 1차 신규 |
| 에어브러시 | 이음매 없는 부드러운 분사 | 거리·시간 적분 기반 농도, 정지 중 분사, 프레임 독립 | 경도/분사량 | 1차 개선 |
| 형광펜 | 넓고 일정한 띠, 일정한 재질 농도 | 단일 획 내부 중복 진해짐 방지, 획 사이 겹침 규칙 고정 | 폭/재질 농도 | 2차 |
| 수채화 | 옅은 안료와 자연스러운 가장자리 | 벡터 경계 안의 고정 안료 마스크, 시간 경과에 따른 무작위 재변형 금지 | 번짐/안료량 | 2차 |
| 지우개 | 지울 범위를 예측 가능한 정확한 윤곽 | 같은 경로 엔진의 마스크 제거, 기본 단단한 가장자리 | 크기, 이후 부드러움 | 1차 개선 |

형광펜을 방송 영상과 실제 multiply 합성하는 것은 별도 문제다. 투명한 OBS 브라우저 내부 합성은 다른 OBS 소스의 픽셀을 읽을 수 있다는 뜻이 아니다. 1차 설계는 투명 오버레이 내부에서 재현 가능한 색과 alpha를 기준으로 한다.

물감이 계속 퍼지거나 마르는 물리 시뮬레이션은 초기 범위에서 제외한다. 그리는 순간과 전송 후의 결과가 달라지지 않는 것이 우선이다.

### 브러시별 완료 기준

- 펜: 짧은 글씨와 급회전에서도 모서리가 뭉개지거나 구슬 모양이 보이지 않는다.
- 연필/크레용: 같은 위치의 입자가 재생·확대·완성 전환에서 이동하지 않는다.
- 먹붓: 느림/빠름과 압력 변화가 자연스럽고 종료 순간 전체 선이 가늘어지지 않는다.
- 마커: 일정한 펜촉 각도와 균일한 내부 농도가 유지된다.
- 에어브러시: 낮은 프레임률, 높은 배속에서도 원본과 완성 농도가 같다.
- 지우개: 편집, 실행 취소, OBS에서 지워진 위치가 일치한다.

## 8. 추가 기능과 우선순위

현재 이미 있는 실행 취소/다시 실행, 색 선택, 스포이드, 미리보기, 큐 승인·환불, 이벤트 로그 재생은 유지·개선 대상으로 분류한다.

| 기능 | 사용자 가치 | 구현 방법 | 우선순위 |
| --- | --- | --- | --- |
| 확대/이동/화면 맞춤 | 모바일에서도 작은 글씨를 정확히 그림 | 문서 좌표와 view transform 분리, 역변환으로 입력 좌표 계산 | 높음 |
| 필압 및 선 안정화 | 펜 태블릿과 마우스 모두 자연스러움 | pointerType 구분, 압력 곡선, 제한적 보정 | 높음 |
| 최근 색/즐겨찾는 색 | 매번 같은 색을 다시 고르지 않음 | 작은 색상 팔레트와 기기 내 설정 | 높음 |
| 그림 내부 스포이드 | 브라우저 기본 스포이드 미지원 시에도 사용 | 합성된 그림 레이어에서 색 추출. 외부 방송 영상 추출은 별도 | 높음 |
| 자동 임시 저장/복구 | 새로고침·실수로 나가도 그림 보존 | IndexedDB, 문서 버전, 사용자·스트리머별 구분, 유효기간 | 높음 |
| 실제 방송 미리보기 | 결과, 속도, 비용을 보내기 전에 확인 | OBS와 같은 엔진·시간 정책, 완료본과 재생 전환 | 필수 |
| 잉크/복잡도 한도 표시 | 완성 후 제출 거절을 예방 | 서버 한도와 같은 계산, 입력 중 남은 한도 표시 | 필수 |
| 전체 지우기 보호 | 완성 그림의 우발적 삭제 방지 | 확인 및 한 번의 실행 취소로 복원 | 높음 |
| 밝은/어두운 배경 점검 | 방송 배경에 묻히는 선 확인 | 미리보기 배경만 전환, 원본에는 저장하지 않음 | 높음 |
| PNG 저장 | 자신이 보낸 그림을 보관 | 승인한 무손실 원본에서 다운로드 | 중간 |
| 선/사각형/원 도구 | 자막·강조·말풍선 표현 | 경로 객체로 저장, 자유선과 같은 합성·비용 규칙 | 2차 |
| 제한된 레이어 | 밑그림과 선을 나눠 수정 | 초기 최대 3개, 순서·잠금·숨김, 공통 문서 합성 | 2차 |
| 선택/이동/크기 조절 | 다시 그리지 않고 배치 수정 | 객체 transform과 hit test, 최종 배치에 재생 경로도 적용 | 2차 |
| 영역 채우기 | 넓은 영역 채색 | 기준 해상도의 마스크 연산 결과 저장, 면적 기반 한도·비용 | 3차 |
| 대칭 그리기/제한된 도장 | 적은 조작으로 장식 제작 | 대칭 transform과 허용된 내장 자산만 저장 | 3차 |

레이어의 숨김 상태가 제출에 영향을 주는지 명확하게 한다. 초기 정책은 숨긴 레이어를 방송과 비용 계산에서 제외하고, 시청자가 최종 합성 미리보기로 확인하는 방식이다. 레이어 추가 시 지우개는 기본적으로 현재 레이어에만 적용한다.

도형이나 변형은 편집 조작 전체를 방송에 재현하지 않고, 최종 배치된 객체를 그리는 순서로 재생하는 것을 기본으로 한다. 완성본에 없는 선택 상자나 변형 중간 상태는 송출하지 않는다.

임의 이미지/SVG 업로드, 외부 폰트·URL, 공동 편집, AI 이미지 생성, 무제한 레이어는 초기 범위에 넣지 않는다. 검수·저작권·자원 사용·원본 재현 문제를 크게 늘린다.

## 9. 편집 화면 구성

기존 서비스 스타일을 유지한다. 큰 소개 화면 대신 캔버스가 첫 화면의 중심이 된다.

- 상단: 스트리머, 잔여 포인트, 예상 비용, 초안 저장 상태, 제출.
- 도구 막대: 브러시 종류, 지우개, 색상, 실행 취소/다시 실행, 확대/화면 맞춤.
- 브러시 설정: 크기, 불투명도 100%, 해당 붓에 의미 있는 고급 설정 1~2개만 표시.
- 브러시 선택: 이름과 실제 공통 렌더러로 생성한 짧은 획 샘플. 모든 도구에 같은 아이콘만 반복하지 않는다.
- 모바일: 캔버스를 우선하고 도구 막대는 고정 높이, 세부 설정은 열고 닫는 패널.
- 아이콘 버튼에는 이름과 툴팁·접근성 라벨을 제공한다. 색 선택은 swatch, 모드는 segmented control, 숫자는 입력/슬라이더를 사용한다.

커서는 최상단 별도 UI 레이어이며 원본에 포함하지 않는다. 현재 고친 중심점과 흑백 테두리를 유지하고, 이후 문서 확대율에 맞춰 붓 범위를 정확히 계산한다. 펜촉을 입력 위치에서 임의로 위나 아래로 이동시키지 않는다.

터치는 한 손가락 그리기/두 손가락 확대·이동 정책을 명확히 한다. 펜 입력 중 손바닥 입력을 별도로 처리하고, `pointercancel`과 capture 해제 시 획이 계속 이어지지 않게 한다.

## 10. 데이터와 프로젝트 변경 위치

### V2에 필요한 필드

```text
DrawingDocument
  schemaVersion
  rendererVersion
  documentId / revision
  canvas: logicalWidth, logicalHeight, aspect, colorSpace
  strokes[]
    id, layerId, seed
    brush: id, version, color, opacity, size, materialSettings
    samples[]: x, y, pressure, time, optionalTilt
    startedAt, endedAt, pointerType
    compiledGeometry: versioned vector segments + time mapping
  replayPolicy: original-ratio | trim-pen-up-gaps

DrawingManifest
  documentHash
  finalImageKey / finalImageHash
  previewImageKey
  rendererVersion / materialAssetHashes
  pricingVersion / acceptedCost
  acceptedRevision
```

임의 SVG 문서나 실행 가능한 코드를 저장하는 형식은 사용하지 않는다. 허용된 명령과 숫자로 표현한 경로, 검증 가능한 설정만 받는다.

벡터 경로와 입력 데이터를 함께 보관할 때는 두 내용의 일치도 검증한다. 입력과 무관한 거대 경로나 다른 이미지를 보내서 검증과 과금을 우회할 수 없게 한다.

### 제안 파일 구성

기존 루트 `shared/`의 ESM 공유 패턴을 따른다. 서버에서 불필요한 React/브라우저 코드를 가져오지 않는다.

| 위치 | 예정 역할 |
| --- | --- |
| `shared/drawing/document.js` | 스키마, 제한, canonical 직렬화, 버전 판별 |
| `shared/drawing/brushes.js` | 버전별 브러시 사양과 허용 설정 |
| `shared/drawing/geometry.js` | DOM 없는 경로·시간 대응 계산 |
| `shared/drawing/timeline.js` | 동일한 재생 시간 정책 |
| `shared/drawing/pricing.js` | 서버·클라이언트 공통 비용 계산 |
| `src/shared/drawing/renderer.ts` | Canvas 2D 경로·재질 출력 |
| `src/shared/drawing/input.ts` | pointer/좌표/압력 입력 처리 |
| `src/shared/drawing/draft-store.ts` | 임시 저장과 복구 |

파일명은 제안이다. 실제 구현 때 기능 크기에 따라 합칠 수 있으며 처음부터 거대한 플러그인 프레임워크를 만들지 않는다.

편집기·관리자·OBS는 위 공통 함수를 사용하게 바꾼다. 서버의 제출, 스토리지 로드, DB 매핑, 이벤트 로그 재생도 manifest와 버전을 잃지 않도록 수정한다. 기존 `strokes`, `canvas`, `replay` JSON 필드를 활용하되 이미지 키·hash·버전 저장이 부족하면 additive migration으로 확장한다.

## 11. 비용, 한도, 보안

- 고정 비용 방식은 기존 정책을 유지한다.
- 잉크 비용은 서버에서 확정한다. 렌더링 stamp 수, 화면 해상도, 프레임 수로 과금하지 않는다.
- 비용 계산 버전을 기록하고, 같은 규격 문서에 같은 비용이 나오도록 한다. 고품질 질감을 위해 내부 샘플이 늘어났다는 이유로 가격이 올라가면 안 된다.
- 신규 도구의 계수는 공개된 브러시 사양에 둔다. 도형·채우기는 실제 면적 기준의 별도 상한을 먼저 정한다.
- 기본 120획/6,000점/문서 JSON 1MiB를 출발점으로 삼되, 고빈도 입력에서 지나치게 빨리 한도에 도달하는지 측정한다. 한도 초과를 숨겨서 점을 버리지 않는다.
- 입력 정리나 정밀도 양자화가 필요하면 표시 전에 같은 규칙으로 적용한다. 서버 전송 때만 손실 축약하지 않는다. 전송 압축은 원본을 되돌릴 수 있는 방식만 사용한다.
- PNG 원본은 현재 384KiB 미리보기 제한과 분리한다. 초기 제안은 1920×1080급과 파일당 8MiB 상한이며 실제 샘플로 조정한다. 초과 시 품질을 자동 낮추지 않고 제출을 중단한다.
- 압축 해제 후 크기, 이미지 디코딩 픽셀 수, 경로 복잡도, 재질 계산량, 처리 시간을 제한한다. 입력 점이 적다고 계산 비용도 낮은 것은 아니다.
- 계정·채널 권한, 차단, 잔액, 큐 한도, 제출 쿨다운, 환불 경로를 유지한다.
- 제출 idempotency key를 사용하여 재전송이 중복 차감·중복 큐 등록을 만들지 않게 한다. 이를 보장하는 DB 제약과 기존 결제 작업 흐름을 함께 확인한다.
- 렌더 자산과 원본 파일은 immutable 키로 저장한다. 외부 SVG, 임의 URL, 임의 CSS/합성 함수는 허용하지 않는다.
- 초안은 사용자·채널별로 분리하고, 7일 보관을 초기 제안으로 둔다. 삭제 기능과 로그아웃 시 접근 차단을 제공하며 인증 토큰을 초안에 넣지 않는다.
- 원본 업로드 중 실패한 임시 객체는 수명 주기로 정리하되, 확정 후원의 원본은 임의로 삭제하지 않는다.

## 12. 기존 그림과 배포 호환

기존 V1 그림은 과거 입력이 이미 축약되어 있을 수 있다. 없어진 점이나 질감을 복원했다고 주장하지 않는다. 원본으로 남아 있는 데이터를 보존하고 V1용 호환 렌더링으로 처리한다.

1. 서버와 스토리지 로더가 V1/V2를 함께 읽도록 먼저 확장한다. 이때 V2 제출은 꺼 둔다.
2. 검수 화면과 OBS에 V2 렌더러·무손실 원본 표시를 배포한다.
3. 오래 열려 있는 OBS가 구버전일 수 있으므로 renderer capability/version을 연결 시 보고한다.
4. 지원하지 않는 OBS에는 갱신 필요를 알리고 V2 재생을 대기시킨다. 지원되지 않는 붓을 기본 펜으로 바꾸지 않는다.
5. 소수 채널에서 V2 제출을 켜고 원본 일치·속도·저장 실패 지표를 확인한 뒤 확대한다.
6. 문제 발생 시 신규 V2 제출만 끄고 이미 받은 V2 문서를 읽는 경로는 유지한다.

새 배포가 과거 그림의 브러시 버전을 덮어쓰지 않게 한다. 이벤트 로그의 무료 재생도 당시 원본·버전·가격 정보를 복사하고 포인트를 다시 차감하지 않는다.

## 13. 성능 설계와 최소 검증

아래 수치는 아직 측정한 결과가 아니라 구현 목표다.

- 일반 데스크톱/OBS 1080p에서는 60fps, 대표 모바일에서는 최소 30fps를 목표로 한다.
- 입력 때 전체 그림을 매번 다시 그리지 않는다. 확정 획 캐시와 활성 획 작업 표면을 분리한다.
- 지우개·레이어 이동처럼 과거 합성에 영향을 주는 작업은 관련 영역 또는 체크포인트부터 다시 합성한다.
- 커서 이동은 React 전체 리렌더를 발생시키지 않는다.
- 캔버스 DPR, 작업 표면 크기, 캐시 수를 제한한다. 전체 4K 화면을 레이어마다 무제한 보관하지 않는다.
- Worker/OffscreenCanvas는 측정 결과 필요할 때 도입한다. 미지원 시에도 같은 원본·같은 질감을 출력하는 fallback을 유지하며, 저사양 모드에서 질감을 제거하지 않는다. [MDN OffscreenCanvas](https://developer.mozilla.org/en-US/docs/Web/API/OffscreenCanvas)

### 변경 범위에 집중한 검증

| 검증 | 통과 기준 |
| --- | --- |
| 원본 왕복 | 저장 후 복원한 문서의 canonical hash와 원본 자산 hash가 일치 |
| 부분/완성 렌더링 | 같은 환경·같은 해상도에서 최종 픽셀 일치, 전환 시 윤곽·농도 변화 없음 |
| 입력/재생 | 짧은 획, 단일 탭, 곡선, 교차선, 필압, 지우개, 정지 분사 사례 일치 |
| 속도 | 1초/3초 입력이 2배속에서 0.5초/1.5초로 재생 |
| 프레임 독립 | 30/60/144Hz 진행에서 같은 시점의 상태와 완성 농도가 동일 |
| 시간 탐색 | 처음부터 재생한 결과와 중간 시점으로 이동한 결과가 일치 |
| 화면 변환 | 크기·DPR·OBS 비율이 달라도 도형 비율과 질감 위치가 유지 |
| 전송 실패 | 업로드·검증 실패, 이중 클릭, 응답 유실에서 원본 유실·중복 차감 없음 |
| 호환 | 과거 V1 그림과 이벤트 로그 재생이 계속 동작 |
| 커서 | 검정/흰색/같은 색 그림 위, 지우개, 작은 화면에서도 위치 확인 가능 |

모든 조합을 수작업으로 반복하지 않는다. 공통 엔진 고정 fixture, 원본/차감 회귀 테스트, 대표 데스크톱·모바일·OBS 확인에 집중한다. 브러시 샘플 비교가 승인되기 전에는 전체 UI를 다시 디자인하지 않는다.

## 14. 구현 순서와 완료 기준

### 0단계: 커서 가림

이번 작업에서 수정했다. 실제 브라우저 시각 확인과 서비스 배포는 별도다.

### 1단계: 선과 재생의 일치 시제품

정밀 펜과 먹붓 한 종류씩으로 공통 경로 엔진, 안정적인 끝 처리, 시간 기반 재생을 만든다. 도형 교차와 투명 획을 포함해 편집·재생·완성 전환을 비교한다.

완료 기준: 펜을 떼거나 재생이 끝날 때 선 모양과 농도가 바뀌지 않는다. 속도 비율 테스트를 통과한다. 이 단계에서는 실제 차감과 운영 DB를 연결하지 않는다.

### 2단계: 원본 보존과 기존 화면 연결

V2 문서, 무손실 원본, manifest, 서버 검증, idempotency, 가격 확인, V1 호환을 구현한다. 편집기·검수·OBS를 공통 엔진에 연결하고 기본 불투명도를 100%로 바꾼다.

완료 기준: 제출 전 문서와 저장·다운로드·검수·OBS의 원본이 일치한다. 원본 누락·지원 불가·비용 변경을 조용히 통과시키지 않는다.

### 3단계: 1차 브러시와 기본 편의 기능

정밀 펜, 연필, 크레용, 먹붓, 평붓 마커, 에어브러시, 지우개를 완성한다. 확대/이동, 팔레트, 초안 복구, 실제 방송 미리보기, 한도 표시를 추가한다.

완료 기준: 도구마다 재질이 명확히 다르고 100% 불투명도 기본값, 같은 그림 보존, 모바일 입력 기준을 충족한다.

### 4단계: 고급 편집

레이어 3개, 선택/이동/크기 조절, 도형, 형광펜·수채화를 추가한다. 채우기와 대칭은 비용·재생·성능 설계가 준비된 기능부터 별도 배포한다.

완료 기준: 새 기능이 최종 합성과 재생·과금의 의미를 바꾸지 않는다. 최종 미리보기와 송출 결과가 여전히 일치한다.

## 15. 이번 기획의 기본 결정

- 원본 보존과 같은 모습의 재생은 선택 옵션이 아닌 필수 조건이다.
- 기본 불투명도는 100%, 새 그림에만 적용한다.
- 순수 SVG로 모든 질감을 억지로 표현하지 않고 벡터 윤곽과 재질을 분리한다.
- 자연스러운 재생은 점을 더 찍는 문제가 아니라 시간과 경로의 대응을 보존하는 문제다.
- 서버의 숨은 보정·점 삭제·붓 대체를 V2 제출에서 제거한다.
- 완성본 원본은 무손실 PNG, 목록용 썸네일은 별도다.
- 획 사이 대기는 재생 시간에서 모두 제외하고 획 내부 속도 비율은 유지한다.
- 브러시 종류 확대보다 선 일치 시제품과 저장 무결성을 먼저 끝낸다.

실제 구현 결과와 배포 시 확인할 사항은 [구현 기록](D:/AruBot/docs/DRAWING_DONATION_V2_IMPLEMENTATION.md)에 정리했다.
