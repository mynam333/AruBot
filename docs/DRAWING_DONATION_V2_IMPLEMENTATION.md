# 그림 후원 V2 구현 기록

2026-09-29. 코드 구현과 로컬 검증 완료. 운영 배포와 실제 방송/포인트 연동 검증은 별도다.

## 사용자 동작

- 정밀 펜, 연필, 크레용, 먹붓, 평붓 마커, 형광펜, 에어브러시, 수채화, 지우개. 기본 불투명도 100%.
- 펜은 연결된 벡터 윤곽, 연필은 미세 종이 결, 크레용은 굵은 종이 입자, 먹붓은 필압/속도 기반 굵기와 진행 방향의 마른 붓결을 사용한다.
- 마커/형광펜은 사선 펜촉의 연속 면, 에어브러시는 거리·시간 기반 분사, 수채화는 옅은 내부 안료와 상대적으로 짙은 테두리를 사용한다. 질감 seed와 문서 좌표를 고정해 재생 때 입자가 이동하지 않는다.
- 자유선, 선/사각형/타원/별/하트, 영역 채우기, 좌우·상하 대칭(동시 사용 시 4방향), 최대 3개 레이어.
- Shift 자유선은 직선 축에 구속하며 모든 입력 시각·압력·진행 속도를 보존한다. Shift 도형은 캔버스 픽셀 기준 1:1 비율이다. 사각형은 자유곡선 보정을 거치지 않는 닫힌 경로로 모서리를 유지한다.
- 도형의 선 색·불투명도·두께와 채움 색·불투명도를 독립적으로 설정한다. 선과 채움은 각각 끌 수 있다.
- 자유선·직선·도형에 별도 외곽선을 켤 수 있다. 외곽선의 두께(1~100), 색상, 불투명도(0~100%)는 본체의 선·채움과 독립적이다. 본체의 기하학적 영역을 외곽선에서 제외하여 반투명 선이나 채움의 내부 색을 덮지 않는다. 도형은 외부 경계만 감싼다. 지우개·영역 채우기·선택 도구에는 추가 외곽선을 적용하지 않는다.
- 외곽선은 획별 설정으로 저장하고 같은 입력 시각·필압을 따라 그리기와 재생에 적용한다. 대칭·선택 변형·WebP 저장에도 포함한다. 실제로 사용한 외곽선 색만 최근 색에 기록하며, 잉크량 과금에서는 외곽선 면적과 불투명도도 반영한다.
- 현재 레이어의 사각 선택 영역은 획 일부를 포함한 픽셀 단위로 선택한다. 꼭짓점·모서리 8개 핸들로 크기를 조절하고 별도 핸들로 회전한다. Alt로 내부를 드래그하면 복제한다.
- Ctrl로 여러 꼭짓점을 선택한 뒤 드래그하면 선택한 점만 움직인다. Ctrl로 모서리 핸들을 드래그하면 해당 모서리의 두 점을 함께 변형한다. 나머지 꼭짓점은 고정되며, 교차하거나 완전히 접히는 사각형은 제한한다. Shift 회전은 15도 단위다.
- 확대/이동/화면 맞춤, 필압·선 보정, 실행 취소/다시 실행, 흑백 이중 테두리 커서, 내부 스포이드, 배경 전환, 투명 WebP 저장(품질 60%). 브라우저가 WebP를 지원하지 않으면 PNG로 대체하지 않고 오류를 알린다.
- 최근 색상은 실제로 완료한 획·도형·채우기에서만 기록한다. 최신 사용 색이 먼저이며 최대 8개다. 색 선택만 하거나 지우개/선택 이동을 사용해도 기록은 바뀌지 않는다. 즐겨찾기는 명시적으로 지정한 색 10개다.
- 초안은 사용자·스트리머별 IndexedDB에 보존하며 만료는 7일이다. 완료한 편집은 500ms 뒤, 진행 중인 획은 2초 간격으로 저장한다. 새 빈 문서는 기존 초안을 덮어쓰지 않는다.

## 재생 정책

획 사이 대기는 전부 제거한다. 4초 그리기 + 6초 대기 + 1초 그리기는 5초가 기준이다. 남은 획의 압력·좌표·입력 시간은 그대로 보존한다. 숨긴 레이어, 지운 작업의 대기는 재생과 비용에서 제외한다.

획 내부 속도는 일정 비율로 배속하고 점 사이에서 시간 보간한다. 에어브러시를 누른 채 정지하여 실제로 분사하는 시간은 그리는 시간이다. 1초 미만의 짧은 획을 임의로 1초까지 늘리지 않는다. 완성본 유지 시간은 스트리머의 별도 설정이다.

선택 영역의 이동·확대/축소·회전·왜곡은 제스처마다 별도 작업으로 저장한다. 각 입력 시각과 중심·배율·각도·네 꼭짓점 위치를 보존하고 재생 시 시간 보간한다. 제스처 사이의 대기는 제외한다. 선택 조각은 원본 픽셀을 유지하므로 여러 번 변형해도 이전 프레임을 반복 확대하지 않는다. 선택 테두리만 만드는 시간은 재생에 포함하지 않는다.

원근 계산은 [perspective-transform](https://github.com/jlouthan/perspective-transform) 1.1.3을 고정 사용한다. 평행사변형은 Canvas affine 변환, 일반 사각형은 역투영과 premultiplied-alpha 보간을 사용해 삼각형 경계 틈을 피한다. 대형 전체 캔버스 왜곡의 프레임률은 장치 성능에 영향을 받지만 입력 샘플은 별도로 모두 보존한다.

## 원본 계약

`shared/drawing/document.js`는 버전, 브러시 설정, 모든 좌표/압력/시간, 레이어, 변형, seed, 채우기 마스크를 검증한다. V2에서는 서버가 점을 축약하거나 브러시를 바꿔 수락하지 않는다.

`shared/drawing/renderer.js`를 편집기, 관리자, OBS, 서버 검증에서 공유한다. `perfect-freehand@1.2.3`의 윤곽과 Canvas 재질 합성을 사용한다. 초기 기획의 별도 compiledGeometry 저장은 하지 않으며, 손실 없는 입력/설정과 고정 렌더러 버전으로 윤곽을 재구성한다. 향후 윤곽/재질 알고리즘 변경 시 기존 버전을 덮어쓰지 말고 버전별 렌더러를 유지해야 한다.

외곽선 필드는 렌더러 `2.1.0`에서 지원한다. 외곽선이 없는 기존 `2.0.0` 문서는 기존 경로로 읽고 재생하며, 이전 문서에 외곽선을 포함한 새 획을 기록하면 `2.1.0`으로 올린다. 구버전 OBS가 외곽선을 누락한 채 재생하지 않도록 API의 렌더러 버전 확인을 유지한다.

확정한 문서와 같은 상태의 투명 PNG를 각각 SHA-256으로 묶어 제출한다. 커서, 방송 배경, 선택 테두리는 PNG에 포함되지 않는다. 서버는 별도 제한된 worker에서 같은 문서를 그려 제출 이미지와 비교한다. 브라우저/네이티브 안티앨리어싱 차이는 허용하되 다른 그림은 거절한다. 검증한 제출 이미지를 WebP로 압축하며, 서버 재렌더링 결과로 교체하지 않는다.

최종 이미지는 항상 WebP다. `quality: 60`, `effort: 6`, `preset: 'drawing'`, `smartSubsample: true`로 색상에 손실 압축을 적용하고, `alphaQuality: 100`으로 투명도를 보존한다. 저장 전에 변환 전후 이미지의 크기와 모든 alpha 값을 직접 비교한다. 색상 프로파일은 유지하고 해상도는 줄이지 않는다. 크기와 alpha가 달라지거나 압축이 실패하면 포인트를 차감하지 않고 실패 처리하며 PNG로 대체 저장하지 않는다. 원본 입력에 해당하는 8비트 PNG만 허용한다.

문서의 좌표·시간·필압·변형 기록은 손실 없이 유지한다. 검수와 OBS는 문서 해시와 저장된 이미지 파일의 해시를 확인하고 재생 완료 후 보관된 WebP를 사용한다. 색상 손실 압축을 허용한 정책이므로 최종 이미지의 RGB 픽셀이 제출 PNG와 완전히 동일하다고 보장하지 않는다. OS·브라우저 간 재생 프레임의 미세한 안티앨리어싱 차이도 있을 수 있다.

## 저장과 전송

- `POST /api/drawing-donation/originals`: 로그인한 사용자의 임시 PNG 업로드, 최대 16MiB. 최대 1920×1920 RGBA 캔버스의 원본 보존을 위한 여유를 포함한다. API·편집기·로컬 저장소는 같은 상수를 사용한다.
- `POST /api/drawing-donation/submit`: 문서 최대 4MiB, 소유권/차단/한도/가격/해시/렌더링 검증. 전체 JSON 요청 제한 5MiB 안에서 메타데이터 여유를 둔다. 모든 원본 저장 후 기존 atomic paid durable job으로 차감·등록한다.
- 편집기는 점 수·획 수뿐 아니라 UTF-8 기록 용량을 실시간 표시한다. 새 입력의 바이트 증가량을 계산해 제한을 넘기기 전에 멈추고, 이미 수락한 획·변형 프레임은 확정한다. 마지막 획 전체를 취소하거나 좌표·압력·시간을 줄이지 않는다. revision 등 메타데이터 증가를 위해 1KiB를 예약한다.
- 문서 해시 기반 요청 키로 응답 유실 후 재시도해도 동일 요청의 차감을 반복하지 않는다. 성공 응답의 `originalHash`는 제출 PNG의 해시다. 저장 메타데이터의 `original.sourceHash`는 제출 PNG, `original.hash`는 저장된 WebP의 해시로 구분한다. 성공 응답의 두 해시가 일치한 뒤 초안을 정리한다.
- `GET /api/drawing-donation/originals/:id`: 스트리머 세션 또는 OBS 토큰으로 해당 스트리머의 이미지만 읽는다. WebP는 `image/webp`, 기존 PNG는 `image/png`으로 반환하고 각각 파일 해시를 검증한다. 파일은 공개 정적 경로에 노출하지 않는다.
- 기존 `canvas`, `metrics`, `replay` JSON과 `stroke_object_key`, `preview_object_key`를 사용한다. 추가 DB migration은 없다. `previewImage`는 목록용 WebP이며, 신규 V2 `previewObjectKey`는 전체 해상도 WebP 키다. 최종 저장 성공 후 임시 PNG를 삭제하며, 기존에 저장된 PNG를 일괄 변환하지는 않는다.
- WebP 압축은 최종 이미지의 저장·다운로드 용량을 줄인다. PNG 임시 업로드의 16MiB 제한이나 별도 문서/재생 기록의 4MiB 제한을 늘리지는 않는다.
- 원본이 없거나 지원하지 않는 버전이면 임의의 기본 펜으로 대체하지 않는다. OBS는 렌더러 버전을 보고하고, 완료 응답에 현재 item ID를 포함하여 다음 그림을 잘못 종료하지 않는다.
- 이벤트 로그 무료 재생은 문서와 WebP를 새 후원 ID의 별도 경로로 복사한다. 기존 PNG의 재생 복사본도 WebP로 변환하되 기존 PNG 자체는 변경하지 않는다. 이미 WebP인 파일은 재압축하지 않아 반복 재생으로 화질이 추가 저하되지 않는다. 원본 후원 삭제 때문에 재생 복사본이 함께 사라지지 않는다.

### 저장소

기존 Supabase Storage 설정이 있으면 그대로 사용한다. 설정이 없는 PostgreSQL 환경은 `server/drawing-local-storage.js`의 비공개 디스크 저장소를 사용한다. 키에 `local:`을 붙여 나중에 저장소 설정을 바꿔도 읽는 위치를 혼동하지 않는다.

`DRAWING_DONATION_STORAGE_DIR`로 영구 경로를 지정할 수 있다. 기본 경로는 **실제 `.env` 파일 옆의 `.drawing-donations`**다. 프로젝트 배포가 공유 `.env` 심볼릭 링크를 사용하므로 기본 경로도 release 디렉터리 밖에 유지된다. 이 디렉터리는 Git에서 제외된다. 원본 파일은 임시 파일 쓰기와 fsync 후 rename으로 확정한다.

다중 API 호스트에서는 반드시 같은 영구 볼륨을 마운트하거나 공통 Supabase Storage를 설정한다. 컨테이너의 임시 파일시스템만 사용하지 않는다. 디스크 백업에는 이 경로를 포함한다. 저장 실패 시 차감하지 않는다. 미제출 업로드는 기존 retention 작업에서 24시간 후 정리한다.

### 기록 압축과 로컬 보관

- 신규 V2 기록과 이벤트 로그 재생 복사본은 canonical JSON을 gzip level 9로 압축하여 `.json.gz`로 저장한다. 좌표·필압·시간·선택 변형 프레임을 반올림하거나 제거하지 않는다. 기존 비압축 JSON도 읽으며, 과거 기록의 일괄 재압축은 하지 않는다. 압축 해제 후 문서 해시와 기존 렌더러를 그대로 사용한다.
- 압축은 영구 저장 용량을 줄이며, 입력·압축 해제 후 JSON의 4MiB 안전 제한과 점 수 제한은 그대로다. 압축 해제 크기를 제한하여 비정상 파일의 메모리 사용을 차단한다.
- 작성 화면의 저장 아이콘 및 관리자 검수 화면의 `.aruart 저장` 버튼으로 기록과 최종 이미지를 함께 보관한다. 관리자 내보내기는 서버에 보관된 이미지 바이트를 다시 인코딩하지 않는다. 작성 화면의 이미지는 기존 WebP 품질 0.6 설정을 따른다.
- `.aruart` v1: ASCII `ARUART01`(8바이트), manifest/압축 기록/이미지 길이(uint32 little-endian 각 4바이트), UTF-8 JSON manifest, gzip canonical JSON, WebP 이미지 순서다. 기존 PNG 원본을 보관할 때만 PNG 바이트를 허용한다. manifest에 문서·이미지 SHA-256, 렌더러 버전, 크기, 재생 시간 설정을 넣고 계정 ID·인증 토큰은 넣지 않는다.
- 별도 재생 페이지 없이 기존 작성/관리 화면의 `로컬 파일 재생` 모달에서 연다. 파일 읽기·해시 검증·재생·탐색·배속·이미지 추출 모두 브라우저 안에서 수행한다. 서버 업로드나 포인트 차감이 없고 기존 작성 중인 문서는 변경하지 않는다. 모달을 닫으면 재생과 렌더러 자원을 정리한다. 최초 포맷은 V2 문서 대상이며, 이전 V1 획 데이터의 내보내기는 지원하지 않는다.

### 30일 자동 정리

- 접수 시각으로부터 30일이 지난 그림 기록·원본·미리보기를 정리한다. `ARUBOT_DRAWING_DONATION_RETENTION_DAYS`는 1~30일만 허용하고 누락·0·잘못된 값은 30일로 처리한다. 기존 365일 설정도 30일로 제한한다. 전역 정리 작업이 활성화되어 있어야 하며 기본 실행 간격은 1시간이다.
- 대기/승인 항목은 DB 행 잠금 안에서 포인트 반환과 거절 상태 변경을 함께 커밋한다. 수동 거절·삭제 환불·차단·로컬 리모컨도 같은 함수를 사용해 중복 환불을 방지한다. 포인트 반환 실패를 무시하거나 환불 완료로 처리하지 않는다.
- 현재 재생 중인 항목은 실행을 중단하지 않고 완료 후 다음 정리에서 삭제한다. 재생 상태가 1시간 이상 고정된 만료 항목은 중단된 후원으로 간주해 취소·환불한다. 만료된 승인 항목은 새로 재생하거나 다시 승인하지 않는다.
- 외부 저장소 삭제가 성공한 뒤 DB 행과 durable job의 그림 payload를 정리한다. 실패하면 취소·환불 상태와 객체 키를 남겨 다음 작업에서 재시도한다. 백업 파일은 운영자의 백업 보관 주기에 따라 별도로 정리해야 한다.
- 서버 삭제는 사용자가 내려받은 `.aruart`에 영향을 주지 않는다. 장기 보관이 필요한 그림은 자동 정리 전에 내려받아야 한다. 운영 배포 시 기존 30일 초과 데이터도 정리 대상이 되므로 사전 안내·필요한 백업을 확인한다.

## 검증

- 기록 압축/보관 변경: native drawing 테스트 49개와 제출·백엔드 아티팩트·재생 Jest 22개, TypeScript, 변경 모듈 ESLint 및 서버 구문 검사 통과. 압축 전후 문서·재생 픽셀·이미지 바이트 보존, 손상/과대 압축 파일 거절, 중복 환불 차단, 환불 실패 rollback, 삭제 실패 재시도를 확인했다. 기존 그림 화면의 보관 버튼과 로컬 파일 모달에서 열기·재생·일시정지·처음/끝 탐색·닫기 후 초안 보존을 확인했으며, 390px 화면에서 모달 가로 넘침이 없다. 운영 정리/환불은 실행하지 않았다.
- 외곽선 변경: `npm run test:drawing` 36개, 제출/백엔드 아티팩트 Jest 19개, TypeScript·변경 모듈 ESLint 통과. 독립적인 색상·두께·alpha, 반투명 내부 불변, 모든 브러시와 도형의 중간/최종 재생, 대칭·변형·문서 왕복, 구버전 호환, 잉크 과금, 격리된 서버 검증과 WebP alpha 보존을 확인했다. 로컬 브라우저에서 외곽선 켜기·색상·두께·불투명도 조작과 도형 그리기를 확인했고 시험 도형은 실행 취소했다. 390px 모바일에서 설정 영역의 가로 넘침이 없음을 확인했다. 운영 API/OBS 전송은 실행하지 않았다.
- WebP 저장 변경: `npm run test:drawing` 30개, 제출/백엔드 아티팩트 Jest 19개 통과. 실제 손실 압축, 투명도 값 일치, 색상 프로파일, PNG 대체 저장 차단, 오류 시 미차감, 재시도 해시, 기존 PNG 조회·재생 변환을 확인했다. TypeScript와 변경된 그림 모듈 ESLint도 통과했다. 이 변경에서 브라우저 수동 검증이나 운영 서비스 실행은 하지 않았다.
- `npm run test:drawing`: 22개 통과. 재질별 최종 픽셀, 시간 보간/대기 제외, 실제 사용 색상, 4방향 미러, 독립 도형 색상·불투명도, 선택 이동/복제/회전/왜곡의 중간 프레임과 최종 픽셀, 잘못된 선택 데이터 거절, 서버 원본 검증, 로컬 저장을 확인한다. 배포 CI에도 포함했다.
- 그림 관련 집중 Jest 6개 suite, 36개 통과. 제출 함수는 실제 운영 서버를 부팅하지 않는 mock harness로 저장 전 차감 금지, 재시도 중복 차감 방지, 요청 충돌, 다른 사용자 원본 거절, 로그인 검증을 확인했다.
- TypeScript 검사, 변경된 그림 모듈 ESLint 검사, production dependency audit 통과. 기존 승인된 CHZZK 예외 6개 이외 새 production 취약점은 없다.
- 브라우저의 1920x1080 PNG와 같은 문서를 네이티브 검증 worker에 넣어 수락을 확인했다. 크레용/먹붓/수채화 3획, 비교 대상 77,006픽셀 중 허용 임계치를 넘는 차이 3픽셀, 평균 alpha 오차 4.92/255.
- 데스크톱/390px 모바일 실제 그리기, 커서, 초안 복구, 미리보기 모달을 확인했다. `/drawing-lab`은 개발 전용이며 운영에서는 404, 실제 API 전송/포인트 차감은 하지 않는다.
- 추가 데스크톱 확인: 서로 다른 선/채움 색상으로 사각형을 그린 후, 영역 선택 → 크기 조절 → 상단 두 점 왜곡(하단 고정) → 한 꼭짓점 원근 변형 → Alt 복제 → 회전 입력이 기록되는 것을 확인했다.

## 배포 확인

1. API와 프런트엔드를 같은 변경으로 배포하고 `npm ci`로 새 의존성 `perfect-freehand`, `@napi-rs/canvas`, `perspective-transform`을 설치한다. 네이티브 Canvas의 운영 플랫폼용 optional dependency를 제외하지 않는다.
2. 원본 영구 저장 경로의 쓰기 권한·디스크 용량·백업을 확인한다. 앞단 프록시와 외부 Storage 버킷을 사용하는 경우 PNG 업로드 제한도 16MiB 이상인지 확인한다. 이번 작업에서는 운영 DB/봇을 실행하지 않았다.
3. 프런트엔드와 API를 함께 배포한 뒤 기존 OBS 브라우저 소스를 새로고침해 렌더러 `2.1.0`을 로드한다. 구버전 OBS에는 새 문서를 전송하지 않는다.
4. 실제 로그인한 시청자의 제출 → 승인 → OBS 재생 → 원본 유지 → 이벤트 로그 무료 재생을 소액/테스트 채널에서 최종 확인한다. 실제 운영 OBS, 실기 펜의 필압·손바닥 입력, 다중 서버 장애 상황은 아직 실환경 검증하지 않았다.
