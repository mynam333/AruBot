# 봇 관리자

## 사용

1. 채널 소유자가 관리 화면의 **봇 관리자**(`/bot-managers`)를 엽니다.
2. 아루봇에 로그인한 이력이 있는 계정을 닉네임 또는 계정 ID로 검색합니다.
3. 플랫폼과 계정 ID를 확인하고 관리자로 추가합니다. 기본값은 **전체 운영 권한**입니다.
4. 일부 기능만 맡기려면 전체 운영 권한을 끄고 기능별 **조회 / 수정**을 선택합니다. 수정에는 조회가 포함됩니다.
5. 관리자는 화면 상단 채널 선택기에서 **내 채널 / 관리하는 채널**을 전환합니다.

동명이인 오등록을 줄이기 위해 계정 확인 단계를 두었습니다. 같은 계정을 다시 추가해도 기존 권한을 초기화하지 않습니다.

## 권한 범위

| 스코프 | 기능 |
| --- | --- |
| `dashboard` | 대시보드 |
| `connection` | 연결 상태, 정보 새로고침, 봇 재연결 |
| `commands` | 채팅 명령어, 출석 설정 |
| `macros` | 자동 알림 |
| `points` | 포인트 조회, 적립 설정, 잔액 관리, 가져오기/내보내기 |
| `predictions` | 예측 개설, 종료, 정산 |
| `roulette` | 룰렛 설정 및 결과 테스트 |
| `wheel` | 돌림판 참여 설정, 항목, 추첨 |
| `video` | 영상 후원/BGM 설정 및 대기열 |
| `drawing` | 그림 후원 설정, 검수, 대기열 |
| `donations` | 후원 조건과 반응 |
| `automations` | 연결된 방송 도구의 설정과 실행 |
| `actions` | 블루프린트 및 연결된 효과 실행 |
| `logs` | 이벤트 조회, 권한이 있는 효과 재생 |
| `settings` | 봇 활성화 등 기본 설정 |

저장 형식은 `['*']` 또는 `['points:read', 'points:write']`입니다. 알 수 없는 스코프와 빈 권한은 거부합니다.

전체 운영 권한에도 **다른 관리자 추가/권한 변경, 계정 삭제, 개인 OAuth 연결, API 키 및 영구 오버레이·로컬 프로그램 제어 링크 발급**은 포함되지 않습니다. 이러한 작업은 채널 소유자와 허용된 사이트 관리자 작업으로 분리됩니다. 사이트 관리자도 다른 사용자의 개인 로그인 세션으로 가장하지 않습니다.

`app_users.is_admin` 사이트 관리자는 별도 등록 없이 모든 채널을 검색·관리할 수 있습니다. 일반 관리자 명단과 추가 대상 검색에는 사이트 관리자가 나타나지 않습니다.

### 연동 실행

- 명령어·출석 메시지·후원 반응 등에 실행 변수를 연결하려면 대상 기능의 수정 권한도 필요합니다.
- `${action::...}`, `${automation::...}`, `${blueprint::...}`는 `actions:write`가 필요합니다.
- 영상/BGM 신청 실행 변수는 `video:write`, 방송 제목·카테고리 변경 변수는 `connection:write`가 필요합니다.
- 룰렛 실행 변수는 `roulette:write`와 `actions:write`가 필요합니다. 룰렛의 결과 값이 기존 명령어나 다른 액션을 실행할 수 있기 때문입니다. 실행 값이 없는 일반 룰렛 항목은 룰렛 권한만으로 관리할 수 있습니다.
- 로그 재생은 `logs:write`와 해당 그림/영상/액션의 수정 권한이 모두 필요합니다.
- 관리자용 룰렛 결과 테스트는 같은 추첨 가중치를 사용하지만 포인트 차감, 결과 액션 실행, 비밀 오버레이 링크 발급은 하지 않습니다.
- 자동화·액션 수정은 연결된 방송 PC에서 실행을 일으킬 수 있는 강한 권한입니다. 신뢰하는 계정에만 부여해야 합니다.

## 채널 격리

- 로그인 사용자(actor)와 관리 대상(owner)을 별도로 보관합니다. 사이트 관리자 여부는 항상 actor 기준으로 확인합니다.
- 관리 요청의 `botOwner`는 권한이 아니라 대상 선택 값입니다. 서버가 매 요청마다 DB의 실제 권한과 엔드포인트별 스코프를 검증합니다.
- 대상 선택은 탭별 `sessionStorage`에 저장합니다. 다른 탭의 채널 선택에 영향을 주지 않습니다.
- 전환 시 미저장 변경 경고 후 전체 페이지를 이동합니다. 이전 채널의 폼, 임시 초안, 진행 중 요청을 새 채널에 섞지 않습니다.
- 권한 확인 실패 시 자신의 채널로 자동 대체하지 않고 화면을 차단합니다. 지연된 요청도 이전 대상에 고정됩니다.
- HTTP 요청은 회수된 권한으로 새 작업을 할 수 없습니다. 큐 WebSocket은 같은 서버에서 즉시 닫고, 다른 서버에서도 5초 간격으로 재검증합니다. 활성 화면은 30초 간격 및 탭 복귀 시 재검증합니다.
- 이미 접수된 작업과 저장된 명령어·설정은 관리자 해제만으로 취소·삭제되지 않습니다.
- 명시적으로 검토하지 않은 API는 위임 요청을 차단합니다. 개인 인증·공개 시청자 페이지는 관리 채널 선택을 상속하지 않습니다.

관리자 추가·변경·해제와 감사 기록은 같은 DB 트랜잭션으로 저장합니다. 성공한 위임 운영 요청도 실제 actor와 대상 owner, 라우트 템플릿으로 기록합니다. 일반 운영 요청 감사 기록 실패는 서버 로그에 남기며 이미 완료한 운영 작업을 되돌리지 않습니다. 로그 응답에서 영구 토큰·인증 정보는 제거합니다.

## 배포

- 마이그레이션: `server/migrations/026_bot_managers.sql`
- 테이블: `bot_managers`, `bot_management_audit`
- 기존 데이터와 설정은 삭제하지 않습니다. RLS 및 권한 제한으로 브라우저의 DB 직접 접근을 허용하지 않습니다.
- 기존 백엔드 배포 절차의 `npm run db:migrate`가 새 마이그레이션을 적용합니다. 런타임에도 최초 사용 시 멱등적으로 스키마를 준비합니다.
- 프런트엔드와 백엔드를 함께 배포해야 합니다. 새 프런트엔드에는 `/api/bot-management/context`가 필요합니다.
- DB 연결 장애는 권한 없음으로 우회하지 않고 실패 처리합니다.

## 검증

권한 정책, actor/owner 분리, 미허용 API 차단, 실행 변수의 추가 권한, 설정 보존, 관리자 변경 및 감사 저장, WebSocket 권한 회수, 탭별 API 주소, 기존 UI의 읽기 전용 상태를 집중 테스트합니다.

Chrome 모의 API 환경에서 관리자 추가·고급 권한 선택·수정·해제, 채널 전환·취소·복귀, 권한 회수, 읽기 전용 명령어, 사이트 관리자 검색을 확인했습니다. 1440×1000 및 390×844 화면을 확인했습니다. Browser 플러그인 스킬이 제공되지 않아 설치된 Playwright와 Chrome을 사용했습니다.

| 확인 항목 | 결과 |
| --- | --- |
| 전체 Jest 회귀 테스트 | 1,299개 통과, 환경 의존 테스트 5개 건너뜀 |
| 타입 검사 | 통과 |
| 프로덕션 빌드 | `npm run build` 통과 |
| 실제 화면·모달·버튼 흐름 | Chrome 모의 API에서 통과 |
| 데스크톱·모바일 레이아웃 | 수평 넘침·빈 화면·프레임워크 오류 화면 없음 |
| 브라우저 콘솔 | 페이지 예외 없음. 광고 관련 Permissions-Policy 미지원 및 React DevTools shim/Fast Refresh 경고는 개발 실행에서 관찰됨 |

콘솔 경고까지 포함해 무경고 환경이라고 판단한 것은 아닙니다. 기존 개발 실행 경고의 원인은 이번 기능 변경 범위에서 수정하지 않았습니다.

로컬 확인 URL: `http://127.0.0.1:3118/bot-managers`. 정상 사용에는 백엔드·DB·로그인이 필요하며 브라우저 검증의 모의 API는 운영 데이터에 저장하지 않았습니다. 실제 PostgreSQL 통합 검사는 `ARUBOT_TEST_POSTGRES_URL`이 설정된 격리 DB에서 수행합니다. 운영 계정 간 권한 부여와 실제 OBS 재생까지 검증했다는 의미는 아닙니다.
