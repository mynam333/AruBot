# 로컬 FX 파일 사용

1. 업데이트된 로컬 프로그램을 방송 PC에서 실행하고 계정을 연결합니다.
2. **FX 에셋**에서 이미지·영상·음성이 있는 폴더를 선택합니다.
3. **로컬 FX 오버레이 주소 복사**를 누르고 같은 PC의 OBS 브라우저 소스에 붙여 넣습니다.
4. 기존 웹 FX 브라우저 소스는 비활성화합니다. 두 소스를 동시에 열면 효과와 소리가 중복될 수 있습니다.
5. 웹 블루프린트에서 기존 에셋을 선택해 실행합니다. FX 설정과 랜덤 위치는 그대로 사용합니다.

로컬 오버레이는 웹과 동일한 렌더러를 사용합니다. 서버의 FX 이벤트에 연결하므로 이미지·영상·사운드뿐 아니라 텍스트 표시·갱신·숨김, TTS도 같은 경로로 받습니다. 로컬 파일 원본은 서버에 업로드하지 않습니다. 다른 PC나 휴대폰에서는 방송 PC의 파일을 볼 수 없습니다.

오버레이 주소와 포트는 프로그램을 다시 실행해도 유지됩니다. 최초 사용 후부터 저장된 포트로 자동 시작하며, 봇 연결은 끊겨도 계속 재시도합니다. 다른 프로그램이 해당 포트를 점유한 경우 실행 기록에 시작 실패가 표시됩니다. 브라우저 소스를 처음 열 때는 로컬 프로그램이 먼저 실행되어 있어야 합니다.

기존 웹 FX 주소도 계속 사용할 수 있습니다. 단, HTTPS 웹사이트의 로컬 네트워크 접근을 브라우저가 차단하면 권한 허용이 필요합니다. 로컬 FX 주소는 오버레이와 파일이 같은 출처이므로 이 교차 출처 접근에 의존하지 않습니다. 브라우저 보안 기능을 끄거나 PC 폴더 전체를 공유할 필요는 없습니다.

파일이 없거나 이동된 경우, 또는 연결된 FX 오버레이가 없는 경우 작업 실패 이유가 로컬 실행 기록에 표시됩니다. 영상 형식은 브라우저가 지원하는 코덱이어야 합니다. 파일 확장자만 바꿔도 코덱이 변환되지는 않습니다.

## 배포

- 백엔드, 프런트엔드, 로컬 프로그램을 함께 업데이트합니다. DB 마이그레이션은 필요 없습니다.
- `npm run local:release`는 공용 FX 컴포넌트를 로컬 번들로 빌드한 뒤 설치 프로그램에 포함합니다.
- 개발 실행은 `npm run local:app`으로 시작합니다. FX 코드 수정 후에는 `npm run build:local-fx`로 로컬 번들을 갱신합니다.
- 로컬 파일 서버는 `127.0.0.1`에만 열리고, 등록한 미디어 파일마다 별도의 서명으로 접근을 제한합니다. 오버레이 URL의 키는 비공개로 관리합니다.
