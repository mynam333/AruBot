# 시청자 참여 돌림판

관리 메뉴의 **돌림판**(`/wheels`)에서 항목 모집, 수동 추가, 추첨, 결과 확인을 처리한다. 기존 `/roulette`의 상품 룰렛과 설정·결과를 공유하지 않는다.

## 참여

| 방식 | 설정 | 입력 |
| --- | --- | --- |
| 무료 채팅 | 사용 여부, 명령어, 한 판당 인당 한도 | `!돌림판 노래 한 곡` |
| 포인트 | 사용 여부, 명령어, 1칸당 포인트 | `!돌림판추가 3 노래 한 곡` 또는 `!돌림판추가 노래 한 곡` |
| 후원 | 사용 여부, 1칸당 원화 금액 | 후원 메시지가 항목 이름이 된다. 메시지가 없으면 후원자 이름을 사용한다. |
| 수동 | 항목 이름, 칸 수 | 관리 화면의 추가 버튼 |

포인트 명령어는 이 페이지에서 설정하는 전용 명령어다. 일반 채팅 명령어에 같은 이름을 별도로 만들 필요가 없다. 저장하거나 모집을 시작할 때 기존 명령어와의 이름 충돌을 검사한다.

무료 참여는 입력 한 번에 1칸이다. 한도는 한 판 동안 누적되며 당첨이나 항목 삭제로 복구되지 않는다. 새 판을 만들면 초기화한다. 포인트 명령의 칸 수는 생략하면 1칸이며 한 번에 최대 100칸이다. 이름은 60자 이내다.

후원은 봇이 수신하는 CHZZK·CIME·YouTube 원화 후원 이벤트를 사용한다. 외부 결제 수단을 새로 연결하거나 결제를 취소하지 않는다. 예를 들어 1,000원당 1칸 설정에서 2,500원은 2칸이며 남은 500원은 다음 후원에 합산하지 않는다. 원화가 아닌 YouTube 후원은 환산하지 않는다.

## 추첨

- 한 판은 최대 1,000칸, 200개 추가 항목이다. 같은 이름으로 여러 번 추가한 항목은 출처와 구매 단가를 보존하기 위해 별도 기록한다.
- 한 칸의 확률은 모두 같다. 3칸을 가진 항목의 확률은 1칸 항목의 세 배다. 넓은 색 구간은 같은 추가 항목의 칸을 묶어 표시한 것이다.
- 서버가 추첨 당시 목록을 고정하고 난수로 당첨 칸을 결정한 뒤 저장한다. 브라우저는 해당 칸 중앙에 맞춰 회전한다.
- 회전 중 들어오는 참여는 다음 추첨 목록에 추가된다. 현재 추첨의 확률과 결과는 바뀌지 않는다.
- 새로고침하거나 다른 관리 화면을 열어도 같은 서버 시각을 기준으로 회전·결과를 복구한다. 다음 추첨은 현재 회전 종료 후 가능하다.
- 당첨 칸은 기본적으로 유지한다. 다음 추첨에도 같은 칸 수로 참여하며 다시 당첨될 수 있다. 다른 항목 구성이 바뀌지 않으면 당첨 확률도 같다. 설정에서 1칸 제외 또는 같은 항목 전체 제외로 변경할 수 있다. 이미 저장한 처리 방식은 덮어쓰지 않는다.
- 회전 시간을 4~15초로 설정할 수 있다. 동작 줄이기를 사용하는 브라우저는 회전 연출을 줄여도 결과 발표 시각은 유지한다.

## 데이터와 포인트

설정, 칸 목록, 최근 추첨 결과와 요청 처리 기록은 서버 DB에 저장한다. 포인트 차감과 칸 추가는 같은 트랜잭션으로 처리한다. 정원·잔액·권한 조건을 만족하지 못하면 차감하지 않는다. 같은 메시지나 요청을 다시 받아도 동일 요청 식별자로 추가 차감을 방지한다.

수동 삭제와 새 판 만들기는 남은 칸의 환불 가능한 포인트를 돌려준다. 당첨으로 소비한 포인트는 돌려주지 않는다. **후원금은 이 기능에서 환불하지 않는다.** 회전 중 새 판 만들기는 막는다. 결과 기록은 최근 50개를 유지한다.

이벤트에 제공자 고유 ID가 있으면 이를 중복 방지 기준으로 사용한다. ID가 없으면 원래 이벤트 시각과 내용으로 식별한다. 둘 다 없는 구형 후원 이벤트는 5초 단위의 짧은 중복 창을 사용하므로 이 경우 완전한 중복 판별을 보장하지 않는다.

## 적용과 검증

웹 프런트엔드와 백엔드를 함께 배포하고 `server/migrations/024_participation_wheel.sql`을 적용한다. 기존 배포의 `npm run db:migrate` 경로를 사용한다. 브라우저에는 수정 권한이나 개인 포인트 식별자를 포함하지 않는 공개 상태만 반환하며 관리 API는 로그인한 소유자 범위로 제한한다.

DB 이관 시 `participation_wheels`와 `participation_wheel_requests`를 반드시 함께 옮긴다. 중복 처리 기록을 잃으면 과거 이벤트가 다시 반영될 수 있다. 두 테이블은 이관 건수·체크섬·필수 테이블 검사에 포함되어 있다.

런타임 DB 계정을 분리해서 사용한다면 `docs/DATABASE_ROLES.md`에 따라 두 테이블의 CRUD 권한과 해당 서버 역할 전용 RLS 정책을 함께 설정한다. `db:provider-smoke`가 실제 접근 가능 여부를 롤백되는 트랜잭션으로 검사한다.

`npm run test:wheel`은 입력 검증, 트랜잭션·중복 방지·환불, 명령어/API 연결, 회전 좌표·시간 계산을 검사한다. 백엔드 배포 CI에서도 실행한다.

검증은 격리된 저장소·포인트 모형과 로컬 웹 화면에서 수행한다. 실제 운영 DB 마이그레이션이나 실방송 후원 수신을 자동 검사 결과만으로 검증했다고 간주하지 않는다.
